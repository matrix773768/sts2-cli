# M1-NOSL3C-II-A 动作覆盖与原生资格

基线为 `fceb4c6`，游戏为 0.113.1，隔离宿主加载冻结 Solver 0.51.5。此交付完成了公开弃牌堆绑定和原生构造入口的扩展，覆盖资格仅适用于已复放的轨迹与已测机制。

## 动作与公开信息

v2 保留逐步菜单索引。新动作 `play_with_draw_top` 使用 `choice_zone=discard` 和当前可见的弃牌堆索引。弃牌堆保持本步原生候选顺序。执行端以状态键和出现序数绑定实际实例，向策略只发布区域和公开索引。生存者继续使用 `choice_zone=hand`，索引以打牌前的手牌为准。空候选使用普通出牌，唯一候选由原生自动完成时用完整续体比对结果。

读取 Solver 的选择规格需要先证明候选已经公开。当前只在已确认的手牌弃牌与弃牌堆置顶路径使用此逻辑。Solver 的执行期规格可以依赖抽牌堆顺序、随机生成结果或同一次打牌中先前的选择。扩大范围需要把执行暂停点、公开候选和私有恢复句柄分开，并对原生与 Solver 的同一层选择逐次对账。

使用两份公开状态相同但隐藏抽牌顺序不同的原生起点，v2 序列化观察和 Actor 概率逐项相同。当前探针覆盖初始决策点，尚需覆盖带既往公开历史和打牌后显露候选的决策点。

## 费用与目标

v2 从 Solver 的可打性检查取得当前能量和星星费用，按实例发布 X 标志与即时星星数。旋风斩实际消耗当前能量的复放通过。储君的崇拜及随后消耗固定星星的陨星经过相同原生初态逐步复放。两项对照均比较了完整续体摘要。星星 X 和其他特殊费用的资格仍待验证。

## 模型与数据

`contract.py` 提供 v2 投影和 Decision。Actor 对每个菜单行评分，以候选牌区实例构造引用；动作特征包含费用、X 标志和弃牌堆选择标志，打出的卡和被选实例同时可见。资格脚本使用固定复放动作，另逐步保存参考模型的分布并重建历史核对 logp。它产生的轨迹只供资格审计。

可用 `Policy.from_v1` 初始化 v2 模型。该入口复用旧权重，给动作输入追加四个零初始化列，并将旧状态向量的末位零改为当前星星数。v2 权重可通过 `save_policy` 和 `restore_policy` 往返，训练恢复必须使用相应观察版本及运行标识，现有 3A/3B/3C/Ib 继续由原入口复现。正式 v2 采样账本、训练程序接入及包含优化器状态的恢复仍待完成。

## 建根与资格

独立宿主的 schema 3 查询原生角色池和遭遇目录，支持由原生接受的前三幕普通遭遇及五个角色。保留无药水、无遗物、HP 范围和原生升级约束，允许超过 40 张卡的牌组。探针在第三幕 GLORY 的 AXEBOTS_NORMAL 成功构造五个原生根，每个根有 41 张重复且混合升级的角色牌。第三幕和新增角色的逐动作与战斗终局资格均待验证。

头槌夹具在第一幕复放 9 步，包含两个候选的选择和两次唯一候选；每步的独立原生续体 SHA-256 一致。多候选的顺序和实际目的实例经原生回调核验。末步锁定 73/80 HP，药水槽一致。完整复放另外核对锁定金币。资格仅适用于该夹具的两条受测路线。保留现有 E3 敌方侧终局风险分类，尚无新证据可解除它。

## 复现

从仓库根运行，使用 [3C-I 环境说明](m1-nosl3c-training-infrastructure.md) 的游戏 DLL、Solver 与 CoreCLR。

```powershell
python -X utf8 experiments/m1-nosl3c-iia/build.py
python -X utf8 experiments/m1-nosl3c-iia/qualify.py logs/nosl3c-iia-qualification
python -X utf8 experiments/m1-nosl3c-iia/probe_roots.py logs/nosl3c-iia-roots
python -X utf8 experiments/m1-nosl3c-iia/probe_costs.py logs/nosl3c-iia-costs
```

覆盖状态和下一步依赖见 [机器可读矩阵](../experiments/m1-nosl3c-iia/coverage.json)。仓库保存 [验证摘要](../experiments/m1-nosl3c-iia/evidence.json)。完整复放结果和可构造根由上述命令输出到本地日志目录。


## 回归结果

隔离宿主构建为 0 错误、7 个既有警告。分别运行 NOSL3A、3B、3C 和 Ib 定向套件，依次通过 6、4、5、4 项。全量 `tests` 单次运行 160 通过、1 跳过、2 失败。两项失败的 EngineProbe 直接调用系统 dotnet，而系统缺少 .NET 9。保留系统 SDK 构建并单独使用本地 9.0.7 host 执行探针后，两项均通过。跳过项是 S1 少于两条合法 A/B/A 续体。五角色各 5/5 场结束，无崩溃或卡死。
