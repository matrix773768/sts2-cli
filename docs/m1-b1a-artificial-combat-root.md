# M1-B1A 人工战斗初态与高速建根

铁甲战士的两个标准首回合人工根已通过两轮冷／常驻 A→B→A。常驻方案仍用原生规则从头构造每场战斗。后续根从输入请求到预测完成的中位数为 **79 ms**，逐根冷执行的同区间为 **3.37 秒**。按三个根的完整批次计入首次启动、原生退役和进程退出，常驻吞吐为 **0.64–0.66 根/秒**，逐根冷启动为 **0.27 根/秒**。

基线 `9fb088321f1606ea397dfd8052480d93cfbe4698`，`port/v0.113.1`，起始工作区干净。实验使用 Windows、SDK 10.0.404、CoreCLR 9.0.7、游戏 v0.113.1／Build 26660232、CombatSolver 0.51.5。构建及运行核对冻结 Solver 和原生 DLL。实验仅使用两个手工样本，未读取封存测试或验证数据。

## 已有预战接口

- `PreCombatForecastApi.SimulateAsync` 在游戏主线程取当前活跃单人跑局，并要求无进行中的战斗、使用注册遭遇及可解析的地图目标。可以使用已合法挂载的人工跑局作为活跃跑局，前提是满足同样的角色、原生存档及地图约束。普通未挂载的人工 `RunState` 没有直接入口。立即模拟从活跃跑局取角色、幕、种子和地图。可选 `SampleSeed` 是独立模拟的 RNG 样本覆盖，活跃跑局的原始种子仍保留。
- `SimulatePlanningAsync` 接受同一跑局的规划快照。当前幕、跑局种子、单人角色 ID、NetId 及目标地图点必须与活跃跑局兼容。提供跨越中间行的路线时，坐标、行及点类型还需通过验证。主线程捕获会核对活跃对象引用，结果回交时还核对引用及状态 token。合法构造人工规划状态理论上可用，接口本身未在本实验运行。
- `PreCombatForecastWorker` 按游戏及账号数据路径、Solver 配置哈希、模组列表复用隔离进程及文件环境。进程复用保留游戏运行时、程序集、模组和热模型初始化；种子及角色由每条请求的跑局快照提供。超时、取消或异常会使 worker 失效。场景构造仍恢复原生跑局、加载或准备资源及地图并进入原生遭遇，之后从活跃战斗捕获预测根。内部无人测试场景构造器也支持原生新局及注入合法负载，但入口和计费与本次冻结 F3B 对照有别。
- `CombatRootSnapshot.Capture` 和 `SimulatedCombatState` 仍读活跃对象、hook、原生战斗历史、规则及 RNG，创建进程内可复制的预测对象图。启动成本可以摊销，已有构造器仍需要原生战斗初始化。

## 人工输入与两条路径

[版本化人工输入草案](../experiments/m1-b1a/cases.json) 外层 `contract_version=1`，消费现有 `SyntheticCombatSpec` schema 1。当前限 Ironclad、Standard、默认第一幕、首个玩家行动窗口、普通遭遇和无已访问节点。跑局字符串种子交给原生 RNG 初始化；卡组按顺序声明模型 ID 与 0/1 升级，入场 HP 与最大 HP 由原生命令设置。难度用 `ascension`，本轮固定 A0。遗物和药水用模型 ID 与槽数组，本轮清空。金币采用原生初值。以后扩展金币、星星、规则变体或显式幕时应增加受验证的字段及版本，避免把未消费的字段误当成受支持资源。

两根共享普通遭遇 `SHRINKER_BEETLE_WEAK`、基础铁甲战士卡组及 80 最大 HP。A 的种子为 `S1TEST01`、入场 HP 80，B 为 `S1TEST02`、入场 HP 74 且升级 `BASH`。同一遭遇便于隔离卡组与随机初态的变化，实验未覆盖跨遭遇复用。

**路径 A 已实测通过。** 隔离宿主保留 `synthetic_start` 的 fresh-process 门禁。每根重新挂载原生单人局、新建牌实例和遭遇，等待行动执行器到玩家窗口。预测完成后借胜路合法打完，跳过卡牌奖励，抵达地图，释放预测探针的战斗绑定。复用 P1 的空闲检查、解除事件订阅、释放 selector、原生清理及 profile 恢复，再创建适配器。每批最后一个根也执行退役。没有活跃战斗重置。注入的活跃重置异常、下一请求发出前的取消均关闭进程，退出码 1；任何过程中抛出的比较失败、异常或外部时限同样经过失败关闭路径。本轮未注入请求执行中的取消或 RPC 超时。

**路径 B 仍缺少构造契约。** 即使限首回合，独立输入仍需重建版本化模型、Player 与 Creature 身份、原生卡牌实例标识和所有者、确定的手牌及牌堆、敌人意图状态、钩子序列、回合阶段、RNG 完整流及起始历史。种子和卡表描述了如何向原生建根，缺少经验证的独立对象图构造。P2 已实证现成 continuation 只有对账能力、快照保留原生引用。本轮未新增独立预测构造器。近期采用 A 可获得可测收益。后续混合路线可先把原生生成的首回合状态与稳定模型身份做成显式数据，再用 A 的逐步证据验证独立构造。

## 等价性与性能

同一隔离构建、相同输入和预算，F3B C、禁主动药水、512 次计费上限；每组 A→B→A，两轮。比较完整公开／原生根身份哈希（含 run 与 player RNG）、全预测返回值、所有路线动作及逐步摘要。只排除性能计时字段。两个独立冷原生对照均执行对应原生路线，并与六次常驻退役的完整原生逐步帧哈希一致。逐步预测 continuation 与原生对照也一致。A 用 13 次转移、损失 10 HP、终局 70 HP；B 用 12 次转移、损失 5 HP、终局 69 HP。两根终局金币 99，药水槽均空。实机对照用于验证本原型，未运行完整 L3 流水线或改动历史标签。[逐根结果](../experiments/m1-b1a/results.json)

模型、输入及原生建根子区间嵌套在建根 RPC 中，中位数不相加。模型及原生建根受首次 JIT 影响，热搜索差异也包含同进程预热。逐根冷批为 11.19／11.30 秒，常驻批为 4.56／4.66 秒，按对应轮次为 **2.45×／2.43×**。冷基线完成预测后直接退出。常驻为取得安全复用边界，额外支付首根 734–770 ms、后续根 104–156 ms 的原生退役成本。两组均排除完整 L3 数据生产，因此倍率内没有计入取消逐条严格验收的收益。预测进程高水位在冷批最高 114.3 MiB，常驻批最高 121.6 MiB。只有两根、每批三个位置，长期内存及多机制覆盖仍待验证。

## 猎杀者最小修复设计

依 E3，镜像仍应先结算攻击及相关死亡钩子。仅在准备施加猎杀者的后置延迟抽牌 Power 时，查询等价于原生 `PowerCmd.Apply` 的结束条件，包括剩余主要敌人和阻止战斗结束的 hook。命中时跳过该效果，其他卡牌及活动战斗的比较维持原有行为。避免用目标死亡、单看敌人 HP 或全局忽略终局 Power 替代结束条件。

回归保留 E3 的非致死、跨回合消费及最后主要敌人致死对照。另需加入击杀一名主要敌人但另一名存活，确认仍施加 2 且下一玩家回合消费。具备 fixture 时加入阻止结束的 hook，比较胜负、HP、RNG、药水和永久成长。此处只提出修复设计，未修改冻结 DLL。

## 复现

从仓库根运行，复用本地 CS1 基线 Solver、原生 DLL 和 RitsuLib。运行输出目录须为新路径。

```powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
python -X utf8 experiments/m1-b1a/build_probe.py
python -X utf8 experiments/m1-b1a/run_probe.py logs/m1-b1a/reproduce
python -X utf8 -m pytest experiments/m1-b1a/test_evidence.py experiments/m1-s1/test_synthetic.py -q
```

隔离构建、实机对照和 5 项定向测试通过。生产入口、搜索策略、冻结 DLL 和历史 L3 标签保持原有行为。未运行全量 pytest 或五角色批次。
