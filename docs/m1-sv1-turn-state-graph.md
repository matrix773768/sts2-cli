# M1-SV1 回合状态图搜索与规模实测

实验采用 Ironclad 单人 NOSL 和 `prediction_only`。STS2 为 `v0.113.1/26660232`，CoreCLR 为 `9.0.7`。实验宿主沿用 PRE0B 的合成开局和交互协议，预测引擎从 `0.51.5-iik.3b` 源码单独构建，加入搜索范围内的随机性探针和复制计时。历史前缀恢复沿用普通预测模式。基线提交为 `1714be91c8d2471e729dbc80560abeb0e19a4abf`。

## 工程调查

- PRE0B 通过 `pre0_start` 构造真实游戏模型上的合成根，再由 `i1_n2_step` 按决策索引回放。PRE1 三份训练轨迹库都有 `private_tasks.recipe`，包含完整根配方和私有种子。轨迹的 `steps` 有所选动作和每步公开观察。LS2A 的轨迹导出和动作表示可供审计，直接复用 PRE0B 的交互宿主省去了第二套状态恢复路径。
- `CombatPredictionSimulator.Fork` 复制预测状态、状态仓和 RNG，并利用写时复制容器与不可变历史前缀。常规分叉只能在稳定动作边界。待选状态由现有 `InteractiveCombat` 检查点或确定性重放恢复。SV1 对每个合法选择组合从稳定祖先恢复交互，再提交选择，并将恢复调用单独计数。分叉可能共享只读对象或写时复制的后端，所有权由会话释放。
- 搜索和结果组装在 C# 宿主内完成。Python 每个模式发送一次图搜索请求，历史根重建仍逐步通过既有协议。图保存原始合法边、合并节点的所有入边、首动作可达集合和见证路径。首动作可达关系在扩展完成后用工作队列传播，晚到的入边也参与传播。路径预算、时间预算和抽样检查的托管堆预算均可配置。
- 玩家提交结束回合时，在结算入口记录 A，随后搜索可确定的敌方与回合开始结算。B 要求求解器已经回到新的公开决策。A 使用提交边与提交前稳定快照表示，当前宿主没有独立的已提交原生阶段对象。胜利、死亡、A、B、随机边界、预算、unsupported 和错误都有独立记录。

## 状态键和公开信息

| 模式 | 实际比较内容 | 边界 |
| --- | --- | --- |
| 原始穷举 | 每条行动来源分别扩展 | 有资源预算 |
| K0 | Solver 的 `ContinuationStamp`，补充阶段、回合、预测风险与终局标记、累计损失及恢复、死亡处理集合、药水用量、历史长度和完整动作来源 | 对所有不透明预测字段保留固定根下的完整行动、槽位、目标和选择顺序作为保守身份，通常保留所有行动排列 |

`ContinuationStamp` 覆盖 HP、最大 HP、格挡、能量、星星、金币、敌人状态与意图、四个有序牌堆、按机制记录的回合历史计数、药水、遗物计数、Power、模型镜像、规则及模拟 RNG。完整动作来源进一步保护文本未覆盖的实例和历史差异。缓存以规范字符串执行相等性比较，哈希表碰撞无法合并不同活动状态。账本中的终点摘要使用 SHA-256 分组，所有产生终点的原始边仍保留。

内部键会包含未知牌序和 RNG 状态，按固定根限定在宿主的查重用途。公开输出提供当前资源、公开牌区、抽牌堆张数、敌人和可执行动作索引，以及触发边界时可公开的条件。公开观察只用于校验恢复和解释结果。图搜索未使用评分、Beam、价值网络或转移后的隐藏抽牌来挑选动作。

抽牌探针在真正读取第一张未知牌前停车。洗牌、随机卡牌或目标、随机费用、隐蔽牌顶自动出牌和未验证的揭示分别标记。已有公开待选分支可继续。当前实现把一般牌顶保守视为未知，包括通过先前动作已能推导但尚未追踪的已知牌顶。边界保存稳定动作前状态和触发边，在普通抽牌处额外保存剩余抽牌数及公开牌区张数。动作内部未保存任意指令位置的可恢复快照。

直接与条件化敌方行动继续执行。实验未枚举独立敌方随机分支。Solver 实现确实包含带多个可达后继的敌方状态机、随机召唤等路径。它们单独记为 `monster_multi_outcome_rng`、`random_enemy_effect` 或相应未验证原因。此数据只证明 Solver 的实现达到了相关代码路径，不能独立确定原生游戏中对应行动的随机性。

## 验证

小规模对照先于正式冻结。每个控制用例比较穷举、K0 与 K1 的终点，以及每个终点关联的首动作。见证路径通过独立穷举实跑过的边核对。逐分支比较父快照文本，搜索后再次校对同一个交互会话的公开根。重复基础牌、不同升级、顺序敏感遗物计数 0 和 9、早期击杀、死亡、待选、未知抽牌、随机弃取、额外能量、药水和预算截断均包括在对照中。K1 的一般局面保留动作来源，循环机制尚未建立可安全忽略历史的等价键。真实图的探索由硬计数和深度限制兜底。

13 个手工对照全部通过，另有一条 PRE1 轨迹的 6 步历史恢复通过。预期的提前胜利和死亡均出现。`INFLAME` 的窄牌组覆盖可在无新抽牌的分支到达 B。Frog Knight 对照覆盖改变血量的分支和结算入口，NPC 下一意图的逐字段阈值归因仍未单独验证。

另取公开观察完全相同、内部抽牌顺序不同的两个手工根。公平模式得到相同的公开终点、边界原因和首动作关系。单独开启 Oracle 时，可以进入未知区，两根的公开终点随内部牌序而改变。这组 Oracle 只用于隐藏信息隔离测试。

## 随机边界与复杂回合

K1 的 157,452 个随机类边界中，普通未知抽牌 92,697，洗牌 7,702，牌顶自动出牌 2,406，随机选牌 15,048，生成牌 2,826，随机目标 2,413，其他 RNG 3,303。普通未知抽牌涉及 1,519 个根，其中 667 个根在 A 前就出现普通未知抽牌。Solver 的多后继敌方状态机出现 30,184 次、涉及 305 个根，随机敌方效果出现 873 次、涉及 10 个根，两类都发生在 A 后。边界次数也反映行动来源的重复。未知抽牌是覆盖范围的首要障碍，探针会在未知区域前截断，数据无法推出未探索部分的状态规模。

- `#2 KNIGHTS_ELITE` 的五张牌产生 14 个首动作，含多目标攻击及不同合法顺序，触及 1,400 次调用。
- `#110 MYTES_NORMAL` 有七张手牌，出现 27 个待选节点和 102 次恢复调用，且有生成牌及抽牌边界。选择组合与恢复共同推高转移数。
- `#340 KAISER_CRAB_BOSS` 中 Bloodletting 把深度推到 5。重复 Strike 出现在复杂牌组里，超出了当前 K1 规则，仍耗尽预算。
- 手工将双截棍和音叉计数从 0 改为 9，其他根配方一致。触发组合让活动状态从 86 增至 206，且深度从 3 到 4。加入一瓶可用药水的手工根达到 397 个活动状态。正式历史来源没有药水或遗物，不能估计这些机制的自然出现比例。

## 结论与下一阶段

正式样本的中位数是 17 个活动状态。既定预算下，绝大部分根可穷尽当前可观测的确定性区域，约 3% 的根因转移预算停止。保留完整搜索作为默认，优先研究多目标、加能量和待选造成的长尾，现阶段数据没有支持立即在所有局面加入 Beam Search。

从 A 前的随机边界和 B 的稀缺程度看，后续首先需要追踪已知牌顶、定义可恢复的随机事件检查点，并校对 Solver 多后继敌方路径的语义。并行值得优化状态文本及端点序列化，随后对明确的历史语义做更广的 K1 约简。现有常规分叉耗时弱于这两项。进入大规模分布价值学习前还需校准公开条件下的随机结果分布、可重放地定位动作内部的事件点、补齐待选根与缺失的生命周期支持，并对自然爬塔分布与遗物药水覆盖再采样。流程止于 SV1。

## 复现与恢复

从仓库根目录运行。构建、用例和冻结命令使用新输出目录，正式 `run` 支持断点续跑。构建依赖本地已保留的 II-K.3B 源码、DLL、STS2 数据和 RitsuLib。路径可通过 `build.py --game-data` 和 `--ritsu` 指定。

```powershell
python -X utf8 experiments/m1-sv1/build.py logs/m1-sv1-repro-build
python -X utf8 experiments/m1-sv1/checks.py logs/m1-sv1-repro-checks --build logs/m1-sv1-repro-build
python -X utf8 experiments/m1-sv1/campaign.py freeze logs/m1-sv1-repro-input/frozen.json
python -X utf8 experiments/m1-sv1/campaign.py run logs/m1-sv1-repro-input/frozen.json logs/m1-sv1-repro --build logs/m1-sv1-repro-build --workers 4 --max-new 64
python -X utf8 experiments/m1-sv1/campaign.py run logs/m1-sv1-repro-input/frozen.json logs/m1-sv1-repro --build logs/m1-sv1-repro-build --workers 4
python -X utf8 experiments/m1-sv1/summarize.py logs/m1-sv1-repro/results.sqlite --output logs/m1-sv1-repro/summary.json
```

账本逐根提交，`results` 保存压缩 JSON 和 SHA-256，`sessions` 保存每次运行进度。完全相同的运行身份会跳过已完成结果。用同一批只读数据和种子重新冻结，2,048 根清单逐字节一致。更换配置、Worker 数、构建或数据文件后使用新的输出目录。运行结束后用 `summarize.py` 读取全账本，避免默认 SQLite 日志模式下的读写争用。正式运行中的一次全账本并发读取导致写入锁超时。保留已提交 811 条，将该账本切换到 WAL 后继续。首批正常停止和中途故障两种恢复路径均保留。

预算和 Worker 对照使用 `--max-new 128`，再分别设置 `--workers 1`、`--workers 4` 及 `--transitions 350`。实际文件路径、版本、配置、数据和结果摘要哈希见 [证据索引](../experiments/m1-sv1/evidence.json)。
