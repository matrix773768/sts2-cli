# M1-L2 有监督信号的战斗搜索基准筛选

2026-11-18。9 根中有 5 根在预算扫描中出现完整模拟胜利，来自 5 个独立种子组。1,200 节点补搜档中，5 根均产生严格排序，合计 **19 对、8 对共享 Beam 保留边界、1 对原始评分反转**。这组基准可用于回归和继续采集，当前暂不训练。唯一反转已在原生 Headless 复核，但困难根普遍依赖高预算，低预算下缺少可比较标签。

## 筛选规则与预算

沿用 M1-CS2 和 M1-L1 的 Windows x64、STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7、CombatSolver 0.51.5 冻结 DLL（`78e4545e825e58c3d999354b1ffcd54241b1d2cf`）。原版单树 Evaluate、Beam 24、DOP 1、Smart 药水，6 秒软期限。每档单独进程，扫描 240/800 展开额度。至少一个档位返回无预测风险的完整胜路才进入固定首步补搜。扫描不要求正常耗尽搜索，Silent 的 800 档在时间边界前已经找到胜路。

根清单固定为一个小战基线、两个取自前序跑局遇敌类型的普通战、两个现有 A10 普通夹具、两个 A10 精英夹具及两个 Boss（含 Queen 压力对照）。`nibbits` 与 `crawlers` 分别从 `run_1`、`run_2` 直接构造隔离战斗，使用起始牌组，战斗状态来自 Harness 建根。每个生成夹具使用原有种子和配装。详细 Encounter、种子与配置见 [根配置](../experiments/m1-l2/roots.json) 和 [派生结果](../experiments/m1-l2/results.json)。

运行全程串行。扫描总限 270 秒、单进程 30 秒。补搜总限 660 秒、每个根每档进程 110 秒，每个 Solve 仍用 6 秒软期限。原生复核两路共用 85 秒截止。托管堆硬限 256 MiB 适用于扫描和补搜。实际扫描子进程用时合计 195.3 秒，补搜档合计 226.4 秒，最高峰值工作集 241.1 MiB（两阶段）。软期限按求解器检查点生效，表中的墙钟可能超过 6 秒。耗时为单个冷进程样本，其中 Solve 包括根捕获和启动效应。

## 同父节点候选质量与稳定性

复用 M1-L1 的 24 节点首步观察、固定首步搜索和路线质量元组。先验证返回路线的首步、预测状态键、风险及胜利结束回合，主口径另要求搜索边界为 `None`。只比较同父节点、路线质量严格不同的两个完整胜利。平局单记，截断、未知及未生成候选没有劣质标签。按首步完整动作与预测状态标识对齐预算档，结合保留池边界 ID 统计直接竞争。候选发现经过原版准入和等价折叠，覆盖范围仅限观测到的首步。

| 根 | 候选数 | 400→1,200 完整胜利见证 | 400→1,200 主口径胜利 | 400→1,200 严格对 | 高档同池 / 反转 | 高档补搜秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 小战 | 3 | 3→3 | 3→3 | 2→2 | 0 / 0 | 1.94 |
| Nibbits 普通 | 4 | 4→4 | 0→4 | 0→5 | 2 / 0 | 9.81 |
| Crawlers 普通 | 4 | 0→4 | 0→4 | 0→6 | 3 / 1 | 11.05 |
| A10 Ironclad 普通 | 9 | 9→9 | 4→4 | 3→3 | 0 / 0 | 29.97 |
| A10 Silent 普通 | 11 | 0→11 | 0→3 | 0→3 | 3 / 0 | 23.72 |
| **合计** | **31** | **16→31** | **7→18** | **5→19** | **8 / 1** | **76.49** |

- 主口径 5 对跨档方向一致，0 对翻转，另外 14 对只在高档可比。跨档覆盖仅来自小战和 A10 Ironclad，Crawlers 的反转无法在低档复核。
- 敏感性口径允许触及预算边界但已实际返回完整、低风险胜路的见证，可跨档比较 33 对方向一致的严格对及 10 对稳定平局。Nibbits 有 2 对在严格差异与平局之间变动。0 对在两档均严格时发生方向翻转。高档额外找到 61 对严格差异，低档缺少其中至少一条符合条件的胜利见证。
- 同预算、同首步的无约束对照有 6 次可比较，质量均相同，其中 3 次路线不同。另 4 次至少一侧没有主口径下可比较的胜路。固定首步影响搜索路径，且候选补搜的相同额度不等价于无约束树里相同的展开顺序或配额。
- 高档累计 24,724 展开、125,422 转移。仅补搜约 **4.03 秒、1,301 展开、6,601 转移 / 严格对**。加首步发现约 4.46 秒 / 对，计入整个高档进程（含建根和无约束复测）约 6.29 秒 / 对。31 个候选组成的 19 对共享根及路线信息，这些比率描述采集成本。

## 反转与原生证据

`run_2` Crawlers 的首步打击以战斗 ID 1 为目标，生成分数 1,379,999，同池原始名次 2；首步防御的分数 1,439,999，原始名次 0（零基）。两者均被保留。固定打击的胜路累计损 34 HP，第 9 回合结束；固定防御损 55 HP，第 7 回合结束。两路零用药，战后 HP 差为 21。这里至少有一对值得保留的排序纠错案例，并且原版 Beam 已留下该分支。

所有成功档位的精确根戳与原生 live 根戳按根跨进程一致，补搜前后 live 戳一致，两档共 62 条首步观测的预测状态键核对均通过。单独用两个原生 Headless 进程复核反转见证。进入相同遭遇后核对起始手牌、敌人、HP、格挡和能量；两条路线首步四项数值一致，分别执行 29、23 个计划动作并原生到达卡牌奖励，战后 HP 分别为 52、31（含燃烧之血治疗）。该复核检查首步、每步行动前的回合与终局，不比较每一步的完整内部状态。其他候选的终局证据来自 Teacher 模拟。详见 [原生复核结果](../experiments/m1-l2/native-results.json)。

## 信息边界与下一阶段

当前手牌、已揭示敌人信息、HP、能量和格挡属于公开观察。候选执行后的状态量属于当前房间试探可揭示的信息，实验中由 Teacher 预测，在线使用需要独立的合法观测来源与查询成本。RNG 种子、精确指纹、未揭示牌堆和未来轨迹只作离线分组、复现与标签。求解器原始分数和保留细节可能依赖隐藏预测，只作离线基线。现有数据没有控制隐藏 RNG 的干预实验。

暂缓训练。主障碍是同池且有可重复差异的监督标签稀少，尤其缺少可解精英或 Boss。高档唯一一次评分反转、低档 5 个稳定对与 14 个缺失对不足以评价泛化或测量节省。建议继续用 Crawlers 反转作回归，用普通小战作吞吐基线，优先补可解的精英/Boss 和具有稳定非平局同池胜路的独立根。之后再考虑以同父节点的胜路质量顺序为学习目标，按种子组划分，对照实际 Beam 排名、即时原始分数与 M1-L1 手工打分。

## 复现与验收

从同时包含本仓库与 `CombatSolver-m1-cs1` 的工作区执行。扫描使用 M1-CS1 已编译 Harness。补搜重新复制并编译隔离 Harness；正式求解器 DLL 与代码保持原样。输出目录选择新的路径。

```powershell
& sts2-cli/experiments/m1-l2/build.ps1
python -B sts2-cli/experiments/m1-l2/run.py CombatSolver-m1-l2/repro scan
python -B sts2-cli/experiments/m1-l2/run.py CombatSolver-m1-l2/repro prefix --harness CombatSolver-m1-l2/.local/tool-build/OfflineSearchHarness/bin/Release/net9.0/OfflineSearchHarness.dll
python -B sts2-cli/experiments/m1-l2/analyze.py CombatSolver-m1-l2/repro
python -B sts2-cli/experiments/m1-l2/verify_crawlers.py CombatSolver-m1-l2/repro
```

逐进程输出保存完整胜路动作与失败原因，版本库保留派生数据及见证摘要。验证包括隔离编译、18 次扫描、10 次补搜批次、跨预算精确根戳检查、两条原生路线及 `git diff --check`。未越过隔离实验范围，未运行全量 pytest 或五角色批次。
