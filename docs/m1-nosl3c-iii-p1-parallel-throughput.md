# M1-NOSL3C-III-P1 严格训练并发吞吐

**建议 III-A1 使用 4 worker。** 在 P0 的固定 24 个全卡池 999 HP 根上，训练主墙钟从 **76.874 s 降到 39.327 s**，合格吞吐为原来的 **1.95 倍**。这是同机一次对照，适用于本次根、动作预算和宿主配置。

## 对照条件

从 `port/v0.113.1@9391290fde739bec9d268e4fb3e9009cfc14fed2` 运行。2 worker 取 P0 已存训练结果，4 worker 从 P0 根清单、初始模型和行为种子重采，独立完成一次 v4 训练更新。沿用 P0 的冻结身份校验和 II-K.4B 实际 worker 绑定，Solver 为 `0.51.5-iik.3b`，STS2 Build 26660232，CoreCLR 9.0.7。复用 P0 的 200 ms CPU/工作集采样。对照仅调整 worker 数，并在执行器提交外层记录任务时间。v4 仍按组等待。

## 训练等价性

- 24/24 条训练记录语义字段完全相同，含完整动作、公开观察、行为 logp、预测终局和严格资格。两边都是 719 个决策，20 条准入及 673 个优化转移。
- 两边均为 16 个严格胜局、4 个严格败局、1 个原生续体差分、2 个终局规则风险和 1 个 unsupported。逐根核对原生审计内容及终局戳。
- 首次审计对照发现，已知差分根 `000006` 的 `native_frame.peak_working_set_bytes` 从 131874816 变为 117972992。复核逐字段确认该帧的续体状态一致。排除这项资源遥测及审计复用、退役遥测后，24/24 审计一致。
- 两份 SQLite 均通过只读完整性及逐条哈希检查。更新 0 和 1 的模型参数、Adam、Torch RNG 以及序列化快照 payload 均逐字节一致。耗时字段以外的训练统计一致。更新前模型为 `cb2130276dd73a62703a8a0b955b92809fdd7db3b23f8e10719f73d40a4006a9`，更新后均为 `2dfdc711b5f794c65122a10133f54b7c7c45a32af12fd0a9a456e835d9d6ab6e`。

## 分组长尾

4 worker 的四条执行线程分别工作 31.30、28.95、32.91 和 31.49 秒。六组内先结束的任务累计等待最慢任务 **21.31 worker·s**，占组内工作加等待约 14.6%。最长任务 7.73 秒，单次提交到启动最多 3.62 ms。P0 按各两根工时估算同口径空闲为 22.84 worker·s。分组屏障仍留下可测空闲，本轮无需改调度即可获得主要收益。III-A1 优先采用 4 worker，并以约 1.23 GiB 的本次峰值工作集和单批样本限制解读容量。

本地证据位于 `logs/nosl3c-iii-p1-01`，包括单批调用脚本、任务时间、首轮对照与逐字段复核结果。基线为 `logs/nosl3c-iii-p0-01`。本轮仅运行四 worker 的一次真实更新。
