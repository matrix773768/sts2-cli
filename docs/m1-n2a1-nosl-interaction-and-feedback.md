## 待决选牌诊断与修复

从 N2A 冻结账本按失败轨迹的最后一张牌、边界和根逐条归因。敏捷根 `69df6f17…` 的 32 次与刀刃根 `15f2becb…` 的 11 次均打出生存者后停止为 `PendingChoice`。候选是同手牌中除本次打出实例外的余牌。原生选择为单张手牌弃牌。多个候选会进入选择回调，唯一候选可由原生直接处理。本批其余根没有待决选择。

策略接收展开后的 `PlayCard(card, target, choice)`。每个可选项仅包含本步候选索引、卡 ID 和升级等级。候选取自现有 `CardChoiceSupport` 的生存者单选手牌合同，剔除已打出实例后，分别计算来源及候选中的内部状态键出现次序，提交一个 `PlanCardChoice`。这些私有绑定和轨迹摘要只进受信任执行器与离线账本。选择规则由策略明确给出，资格批次优先弃最低升级、同级取最后索引。一次复合动作只调用一次 Replay。

重复实例专项选用刀刃根两张状态键相同的打击，分别弃掉第一个、第二个，再回到第一个。A→B→A 的两次 A 完全一致，A 和 B 的内部出现序数为 0 与 1。独立原生回放分别在候选 2 和 5 命中精确实例，原生回调的候选 ID／升级列表与预测一致，目的牌区验证通过，两个动作后的完整 continuation 摘要各自匹配。此专项还逐次拒绝过期步号和负索引，合法选择仍是第 1 次转移，原始根审计未变。

八条冻结路线中另有六次多候选选择的索引、候选序列、精确目的实例及延续摘要匹配。一例单候选在原生中自动解决，独立执行常规原生动作后完整摘要相符。头槌、执行后才揭示的候选及嵌套选择仍留在现有支持边界，本阶段未给它们提供自动选择。新环境用于单轨迹回调；所有冻结策略、N2A 原账本和历史证据等级保留。[选择专项](../experiments/m1-n2a1/duplicate.json) · [原生抽查](../experiments/m1-n2a1/native-audit.json)

## 反馈与奖励

`feedback` 把状态与两个时间点的信息分开。正常预测胜利或死亡才提供 `combat_terminal`，包含锁定 HP、最大 HP、累计战损、药水槽、金币及证据级别。实验禁用主动药水，奖励未计药水。五条原生胜利的锁定 HP、金币和完整终点摘要匹配。两条死亡的状态、HP 与累计战损匹配，原生胜利锁定回调在死亡上没有提供资源帧。原生退出战斗时已发放的金币和药水单列为 `native_after_combat`。未实际执行选择奖励动作，训练记录的 `post_reward.executed=false`，资源为 null。保留 E3F 已有敌方终局计数差分规则，本轮证据未新增 L3 标签。

`survival_only` 对正常胜利返 1，对死亡返 0。`win_then_hp` 按词典序比较 `(1, hp/max_hp)` 和死亡 `(0, 0)`。预算截断、unsupported、非法动作及执行错误无奖励，原因单列。非法动作拒绝只影响该请求，仍可对当前有效菜单继续操作。引擎传输与意外异常单列为运行失败，资格程序会抛出并保留引擎日志。未把失败归入普通死亡。

## 准入结论与复现
