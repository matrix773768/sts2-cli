# PROJECT-VISION v2.0

## STS2 AI · 项目总体研究规划

**版本 2.0 | 2026-11-28 | 用户已确认总体方向，实施设计稿**

项目仓库：`matrix773768/sts2-cli`。历史冻结游戏版本为 v0.113.1，现有战斗研究以单人 Ironclad 为主。本规划基于截至 CORE-5H、INFRA-2A 的已审阅报告；CORE-6A 尚未交付 Codex，外部模拟器尚无正式选型结论。

> 核心决定：以 NOSL 完整跑局的超人能力为首要研究目标；SL 视 NOSL 研究进展而定。以自主学习与搜索为中心，尽早建立真实跑局闭环。在主引擎选型与架构设计阶段验证长期性能潜力，而不是等规模化训练受阻后再次重写整个系统。

**文档体系。** 本文件规定研究目标、共同约束、性能合同和跨线里程碑。[M1-CORE v2.0](m1-core-v2.0.md)、[M1-INFRA v1.0](m1-infra-v1.0.md)、[M1-RUN v0.1](m1-run-v0.1.md) 分别定义战斗学习、环境/生产和完整跑局专项。旧 CORE v1.4、INFRA v0.1、M1-N、M1-SV 及每项实验原报告继续作为历史设计和证据，不改写历史结论。

## 1. 目标与研究边界

首要目标是在公平 NOSL 信息条件下，从新游戏到最终通关，通过自主学习和搜索达到、最终超越顶尖人类玩家。最初以 Ironclad 单角色和较低进阶建立闭环，逐步提高进阶及覆盖其他角色。合成战斗、真实战斗、固定局外策略的完整跑局和联合优化跑局均是研究工具，不能把任一中间指标等同于最终目标。

- NOSL：真实跑局只执行一次实际决策轨迹，不以死亡重开、存档回退或查看隐藏信息来决定正式行动。搜索可以在隔离模拟副本中分叉，在合法公开信念下采样未来；这些计算并非实际存档重试。搜索预算不能由真实隐藏未来决定。
- SL：暂不另开正式能力主线。只有 NOSL 的实际研究表明有明确价值（如搜索潜力、构筑救援或新的监督来源）时再制定规则和预算。合法重试历史与未曾观察的未来严格区分。
- Oracle / Ideal：允许独立探索理论上限、潜在循环、胜路存在性。不得将其结果计入公平 NOSL 胜率或无条件作为公平策略标签。

坚持自主策略学习。不使用外部 AI 的训练权重或策略标签作为捷径；允许复用开源规则引擎、模拟接口、通用算法和符合许可的人类经验。第三方成绩只作为背景和潜在对照，正式超人结论须在相同游戏版本、角色、进阶、信息与重试规则、种子协议和合理计算口径下比较。

## 3. 总体架构与信息合同

```text
公开跑局状态 ── 局外策略 / 搜索 ── 跑局价值 W
       │             │                    ▲
       ▼             ▼                    │
战斗公开状态 ── 战术 / 多回合搜索 ── 战斗价值 Z
       │             │                    ▲
       └──── 合法环境执行、快照与分叉 ──────┘
                      │
          版本化经验库 + 训练/评测
                      │
             新策略与价值检查点
```

| 模块 | 职责与接口 |
|---|---|
| 环境 | `open / observe / legal / step / checkpoint / fork / restore` 等概念接口，完整跑局及战斗共用私有状态；返回公开观察与真实资源结果。 |
| 表示 | 从公开原始状态编码；分离静态规则和动态状态、缺失字段及版本。学习器不接触私有状态。 |
| 搜索 | 产生合法候选条件程序、合法采样或显式概率分布，记录证据、预算及未解决原因。允许单动作、完整回合和多回合研究并存。 |
| 学习 | 价值分布、行动/候选引导、辅助目标、搜索蒸馏及主动经验；按实际续策身份训练。 |
| 运行 | 同一正式决策器在实际新观察后行动；失败、回退、真实死亡与通关独立记录。 |

C 是当前已验证战斗战略边界（敌方结算完、下回合初始抽牌前），仍作为基线，不是所有未来算法必须使用的唯一边界。L0–L5 的历史接口和 C/R 语义见 CORE 专项。局外使用稳定的公开决策边界，不把隐藏地图种子、未来奖励或真实牌序送入模型。

战斗资源结果分布将成为局外价值的输入。若 s 是战斗前公开跑局状态、Y 是战斗后资源结果、W 是续局价值，则联合优化可研究 `E[W(Y) | s, μ]`（Y 包含恢复后的完整公开跑局状态）。早期仍使用冻结战斗终局效用，后续才根据真实跑局证据研究资源价值和终局通关目标。不能以局部无伤替代通关率。

## 4. 性能合同：在选型时证明长期潜力

以下目标面向个人电脑上的持续迭代，并非已测指标或要求所有高预算教师同时达到的硬门槛。将高吞吐行为策略与昂贵搜索教师分开设计，分别评测质量—成本曲线。

| 层级 | 设计目标（待实测校准） | 验收口径 |
|---|---|---|
| 底层 L0 | 单核 10万–100万规则动作/秒；热复制/恢复微秒量级 | 包含代表性规则、合法菜单与状态大小；报告冷/热、P50/P95、实际触发与内存 |
| 分支 L1 | 同根大量低成本分叉，不依赖从开局复放 | 战斗、选牌、路线等检查点；分叉后的正确独立演化及吞吐 |
| AI 负载 L2 | 四 worker 每小时10万场有效自然战斗 | 固定生产策略、真实推理及结算，报告准入、战斗长度、失败、CPU与wall |
| 学习负载 L3 | 四 worker 四小时1万局有效完整跑局 | 从新游戏到真实胜/负，含全部局内外决策、经验写出、章节到达率与实际动作数 |

L2 目标相当于平均约0.144 worker秒/有效战斗（四 worker 满负载）；L3 相当于约5.76 worker秒/有效完整跑局。若平均20场战斗，这仅允许每场约0.288秒的全部平均预算，还需承担局外决策与写出。该算例只是预算量级，实际按真实战斗数和搜索强度重算。速度目标是架构选择的压力测试，不是已证明可达的承诺。

必须把 L0 微基准和 L1–L3 实际原型连起来。优先选择支持紧凑可复制状态、共享冷数据、同进程搜索、批量推理、完整跑局分叉的引擎。不能凭随机动作峰值或外部项目自报吞吐直接认定适合长期架构。若代表性负载明显不达标且无可信优化路径，不应因其接入方便便冻结为长期主引擎；可以保留为临时原型或正确性参照。若目标不可行，应说明实测瓶颈、可达上限和研究规模/预算取舍，由用户决定调整合同。

基线量级：H5 每千场有效自然经验约20.57 worker分钟、四 worker活跃wall约5.77分钟（含公开导出）。折算约1.04万场/小时，距拟议10万目标约9.6倍。2A 新增自然训练3164/3400准入，生产57.51 worker分钟；本轮全部生产、筛选、公开导出74.11 worker分钟。不同策略、并发和分布不能当作无损加速倍率。

## 5. 研究路线与依赖关系

| 里程碑 | 近期交付 | 进入后续的条件 |
|---|---|---|
| A. 可信高潜力环境 | INFRA 外部引擎调查、同机 L0–L3 原型与性能预算；RUN-0 先完成小型端到端基线 | 具备合法完整跑局、快照分支、可替换策略、可重现吞吐；明确正式引擎选择或保留原型的理由 |
| B. 自主战斗改进 | CORE-5H、后续策略引导、主动分歧、多回合教师；基于数据决定网络与监督 | 至少有可独立复验的能力或计算收益；失败明确定位数据、表示、候选或价值误差 |
| C. 真实局外学习 | RUN-1/2：真实经验、构筑与资源价值、奖励/路线搜索 | 对固定战斗后端，局外决策能在新种子上改善完整跑局或明确中间收益 |
| D. 联合优化 | RUN-3 与 CORE 联合更新，低成本生产和高预算教师分工 | 完整跑局策略有可重复改善，报告性能和失败分母 |
| E. 超人能力 | NOSL 正式对照、提高进阶、扩角色与稳健性 | 可比规则及独立人类基准；不由合成胜率外推 |

A 与 B 可并行，RUN-0 不等待战斗模型升级；RUN-1/2 在可执行环境上逐步开展；联合优化需要真实资源结果接口，但不需要先完成所有机制迁移。SL 根据 NOSL 实际进展重新审查，不列为当前必做里程碑。

## 6. 评价与研究管理

每项任务在训练、选择、确认前锁定目标、候选方案、预算、数据身份、主要指标与升级条件。不同策略按同种子、同构筑或同根配对；构筑族或整条跑局作为重采样单位。全尝试通关/获胜比例、真实死亡、严格完成和失败原因同时报告；共同终局配对效用仅解释共同完成子集。失败不补为死亡，也不从全尝试分母消失。开发、确认、封存及其衍生样本必须隔离；旧确认可作开放回归，不能再作为新独立确认。

规则执行正确性、公开信息隔离、资源账本与经验来源是硬约束。搜索允许启发式、合法 Monte Carlo、局部约简和有限候选；未知质量不得伪造，估计误差与模型误差分别衡量。遵循合理默认、局部例外、实测纠偏，不将全机制认证设为学习前提。外部环境的版本差异通过环境身份和独立迁移评测处理，不静默混合。

工作分工：ChatGPT 审查设计、证据和下一步；Codex 在本地执行实现、实验、报告和提交；用户审查研究方向并在需要时手动推送。各研究线独立 worktree、构建、日志和缓存；冻结提交之间用只读交接、独立适配器或经审查合并。避免同机重负载计时互相污染。普通任务建议约120 worker分钟的计划预算；按实测调整，超预算和长跑需说明或另获授权。先保留现有资产，不重复全量原生审核，不为低频规则阻塞主线。

## 7. 下一步执行顺序

1. CORE-5H 已完成并冻结，保留 V2。建议转入 CORE-6A 学习型策略引导，复用已有公开经验；具体执行任务仍待用户交付 Codex。
2. INFRA 优先开展外部环境选型，验证真实完整跑局负载和长期性能余量；不主动进行新一轮大规模规则移植或无目的采集。
3. RUN-0 同步准备公开决策接口、已有原生跑局资产、固定局外基线和记录协议；可用现有环境完成原型，不把慢原型锁定为正式后端。
4. 在选型结论后安排第一批真实完整跑局与跨线汇合，优先向 CORE 提供真实构筑和资源经验，再决定扩大训练、结构知识或策略教师的投入。
