# M1-PRE0B Ironclad 吞吐与覆盖

起点为 `port/v0.113.1@c9a536616822e915c8891f84b43f3df09170e888`。新入口在 `experiments/m1-pre0b`。使用相同 `ironclad.v2` 根分布、根生成种子、行为种子、冻结 v4 权重和 CombatSolver `0.51.5-iik.3b`。角色、幕次、房型和卡组抽样仍按原序号生成。逐步保存公开观察、合法菜单、真实选择、动作 logp 和预测终局。合格轨迹可为预测胜局或败局，数据记录为 `prediction_only`。参考 [PRE0 口径和证据](m1-pre0-ironclad-high-throughput.md)。

## 覆盖根因

- Frantic Escape、Infection、Toxic 和 Wither 已加入版本化可见生成卡支持范围。N2E 未知机制仍以卡 ID 和 unknown 资格进入原 v4 编码，预测可执行性由 Solver 决定。
- Knowledge Demon 的敌方回合需要玩家从两张公开诅咒中选一张。原桥只查询通用选择，遗漏了冻结 Solver 的 `PendingKnowledgeDemonChoice`。新桥从当前请求发布实际候选和最少、最多各一张的选择菜单。v4 独立执行选中与确认，桥把该选择提交至冻结 Solver 已有的敌方阶段动作重放。预测重放从该动作的稳定起点开始，使用原内部续体检查。其他不支持的边界仍记录失败原因。
- Kaiser Crab 的 Crusher 在原生建根时调用 `Godot.CanvasItem.SetVisible(bool)`。旧 Stub 缺该方法，导致战斗初始化异常后宿主落到奖励界面。隔离构建添加可见性 setter，恢复真实战斗入场。若宿主返回其他边界，新入口记录具体 phase。
- 决策上限从 128 扩至 256。原截断根用相同策略种子继续逐动作决策，按终局与尾部回合 HP 演化判断；截断仍是独立状态。

320 根配对中，原有 297 条完整轨迹全部匹配公开观测、菜单、动作和终局，行为 logp 容差 2e−6。原失败中的 20 个生成牌阻断、1 个 PendingChoice、2 个 Kaiser Crab 建根异常均恢复。第二幕还产出 The Insatiable 的完整预测轨迹。保留全部根和失败记录。

## 结构性优化与计时

- 现有合并建根 RPC 保留。逐动作响应省略内部审计戳、动作审计对象和交互审计对象。终局源状态自检保留。C# 计时单列根模型目录、入参解析、建根与逐步预测及观察构造。Python 的逐步 RPC 计时减 C# 区间后包含协议编码、管道传输与解码和调度等待。
- 可选择缓冲私有命令及响应日志，取消每步重开文件和强制刷新。预测记录仍以覆盖完整菜单的公开投影为准，SQLite 事务独立提交。进程被强制结束时，隔离日志尾部可能没有刷新，事务记录可恢复。
- 调整跨 lane 批量推理的收集窗口，分别记录实际张量前向执行时间、批次等候时间和调用次数。模型结构、权重和动作策略保持原实现。
- SQLite 使用公开轨迹和对应私有任务的批事务，最多每批约 12 项或约 0.2 秒触发写入，排空时提交余下数据。调度先补充任务再写。逻辑分片仍是每条 gzip 记录，继续支持 PRE0 的物理分片导出工具。

## 全量同根配对

按序号连接 PRE0 正式库的全部 7,401 个根，私有入场配方逐条相同。原 6,845 条完整轨迹的公开观察、菜单、实际动作、推进标记及预测终局全部一致，行为 logp 容差 2e−6。原 363 个生成牌阻断、94 个 PendingChoice、91 个 Kaiser Crab 异常分别全部获得完整预测终局。在共同前缀里，第二幕 Boss 完整轨迹为 Knowledge Demon 94、The Insatiable 97、Kaiser Crab 91。

8 个原动作上限样本有 7 个在 256 预算内结束。剩余 Axebots 根 831 在尾部 12 回合里敌方停在 7 HP，玩家由 136 降到 81 HP。该模式是伤害输出停滞和持续受伤，整场状态并未陷入重复循环。用单样本冻结 v4 和 512 动作上限单独重跑，前 256 个实际动作完全一致，第 280 个决策后在回合 173 预测死亡。该诊断样本独立保留，正式统计仍记 1 条截断。

12 Worker 动态批和 4 Worker 单样本的首 320 条也通过同模型逐步对照，行为 logp 容差 2e−6。正式库逐条通过公开负载摘要、合法动作绑定、终局资源、私有任务配对和 SQLite 完整性核验。强制终止生产进程后保留 65 个已提交任务，恢复补齐 31 个，全部 96 个公开记录的 SHA-256 与独立运行一致。另在 4 Worker 下强制终止一个宿主，记录退出码 15，自动启动第 5 个宿主后完成全部 48 次尝试，47 条完整。

## 复现

从仓库根执行。新运行使用独立目录。

```powershell
python -X utf8 experiments/m1-pre0b/build_host.py logs/pre0b-local-host
python -X utf8 experiments/m1-pre0b/run.py logs/pre0b-local --host logs/pre0b-local-host --fast --workers 12 --batch 12 --batch-delay 0 --recycle 96 --seconds 605 --buffered-logs
python -X utf8 experiments/m1-pre0/verify.py logs/pre0b-local/dataset.sqlite
python -X utf8 experiments/m1-pre0b/compare.py logs/m1-pre0-formal-8b/dataset.sqlite logs/pre0b-local/dataset.sqlite
python -X utf8 experiments/m1-pre0b/long_probe.py logs/pre0b-local/dataset.sqlite logs/pre0b-local-long --host logs/pre0b-local-host
```

PRE1 可直接使用 `experiments/m1-pre0/dataset.py` 的 `batches(path, size=32, split="train", complete=True)`。输出仍支持原 `export_shards.py` 及其带摘要的 JSONL gzip 分片。恢复保留 PRE0 的 task ID、内容校验和单写者事务语义，使用相同宿主、分布、策略和推理模式重开现有输出目录。单样本模式用于逐字节验证，先用 `--workers 4 --batch 1 --batch-delay 0 --recycle 96 --count 320 --buffered-logs` 生成参考，再用 `recover.py <新输出目录> --host <同一宿主> --reference <参考 dataset.sqlite>` 运行故障探针。动态 batch 的数值舍入会随同批决策组合变化。
