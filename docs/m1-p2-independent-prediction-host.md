# M1-P2 独立预测宿主与安全常驻求解

**现有 CombatSolver 0.51.5 的预测根无法用现成的快照或 continuation 在另一进程重建。** 两个冷源根均可捕获、分叉，并与原生根逐字核对。在同一个无活跃战斗的进程里，A→B→A 三次均可往返读取 continuation 文本，三次都在构造预测根之前停止。当前冻结入口继续逐根冷隔离。

基线为 `fb7be86e04b12eb114b86cba96fab9451043049d`，`port/v0.113.1`，起始工作区干净。Windows build 26200、16 逻辑处理器、Python 3.10.11、SDK 10.0.404、CoreCLR 9.0.7，游戏 v0.113.1／Build 26660232。隔离构建校验原始 Solver DLL，运行同时校验原生 DLL。负载实验另行校验冻结 F4 宿主与 S2B 计划。使用 F5A 的开发准入两根及已经评测的六个 RPC 超时根。未读取封存测试根。

## 根的边界和实施决定

| 依赖 | 当前入口及生命周期 |
| --- | --- |
| 规则和根元数据 | `CombatRootSnapshot.Capture` 在主线程从 live combat 取得规则、回合和阶段、楼层、敌方意图、治疗及资源元数据。快照保存标量、标识和不可变集合，也保存原生对象引用。 |
| 对象标识与行为 | `PlayerIdentity`、`Enemies` 直接保留原生对象。`SimulatedCombatState` 构造时保留 `RunState`，从当前跑局提取卡池、解锁和房间上下文，从活跃战斗采集模型及 hook。其复制构造仍共享若干根引用。模型 ID 需要与实例、所有者、次序及监听者重新绑定。 |
| 可变预测状态 | 私有根模拟器持有战斗状态、状态仓库及战斗历史。 `ForkSimulator` 调用 `CombatPredictionSimulator.Fork`，通过同一个复制上下文复制分支状态及仓库，复制历史和 RNG，并检查待决的普通卡牌和执行续体。分叉语义以该进程、该根的对象图为前提。 |
| RNG 与对账 | 模拟根从原生 run RNG 序列化状态及按玩家标识索引的非战斗 RNG 建立预测流。 `ContinuationStamp` 包含状态与 RNG 的对账文本。捕获前后比对 live stamp，并检验模拟投影。文本类可反序列化为文本包装对象，构造预测状态还需要玩家、分支存储和模型行为。 |
| 静态与原生设施 | 捕获会锁定 mirror 注册表、预热动态变量、枚举 hook、读取原生战斗历史。显示名、策略和战损捕获也从 live 取输入。主机具备模型库、补丁和全局适配器，原生跑局与事件生命周期仍需隔离。 |

冻结 F3B/F4 共用 `RunFirstWin` 的 native capture、策略、显示名、初始 Step 和原生投影检查。F4 随后重建并核对首胜前缀再做局部改进。公开运行入口和现有 `ForkSimulator` 均缺少由进程间输入初始化根的路径。一个最小候选设计是让根采集端导出版本化的模型与实体 ID、可变状态、规则、历史和 RNG，接收端显式构造有作用域的预测对象及身份映射，再用现有 stamp 在根和每步做差分。风险集中在对象重绑定、私有模型状态、hook 与历史、随机流及跨根清理。在目前接口下，这需要新的 Solver 构造契约。实验仅验证现有输入能否跨过构造边界。

`synthetic_start` 在 `_runState != null` 时拒绝再次挂载。它保护原生模拟器的一次挂载假设，覆盖原生 `RunManager` 和战斗管理器中的当前对象、由其衍生的 RNG、卡牌、监听者与待处理动作。门禁本身只检查 adapter 的 run state，生命周期内其他设施的空闲也需要独立核查。P1 在已结算地图曾实测 profile 污染，对活动战斗实施重置还需要额外证据。探针保留该门禁。

## 实机反例

A 为 strength / `BOWLBUGS_WEAK`，B 为 self-hp / `CORPSE_SLUGS_WEAK`。两根均与 F5A 固定的原生根身份及 RNG 相符。各用独立源进程执行以下探针。

1. 捕获根并各取两个 fork。原生前后审计一致，预测投影与原生 continuation 一致。两个 fork 的玩家战斗状态与 RNG 对象分别独立，快照的玩家与首个敌人仍分别指向 live 对象。
2. 对真实快照尝试默认 JSON 导出。两根都沿原生卡牌属性抛出 `This card is not an ancient card`。探针另保留用纯元数据和精确 stamp 进行导入的路径。对象还持有私有根模拟器，默认属性遍历不能成为完整的导出契约。
3. 另起进程，不运行 `synthetic_start`，提交 A→B→A。两条不同的 stamp 均完整往返，三次尝试的 `live_combat` 与 `native_in_progress` 均为 false。类型导入均报告 `CombatRootSnapshot` 无可用 JSON 构造器。绕开 JSON 构造器仍需显式构造私有模拟器及其实例图。

逐根与请求证据见 [boundary.json](../experiments/m1-p2/boundary.json)。F5A 同根冷参考首胜分别为 19 和 7 次转移。该实验的 A→B→A 是导入准入对照，未产生常驻预测终态、F4 改进或新 L3。事件订阅、运行态长期内存、异常和取消后宿主复用仍未进入验证。按阶段门槛未扩展到 16+8 求解对照。后续若引入独立构造器，需先比较两根 F3B/F4 完整预测证据，并把任何异常、取消或时限后的进程视为丢弃，直到验证可清理边界。

冷源握手、合成初始化、身份生成及比较在逐根结果中独立计量。导入请求的首次 JIT 和后续请求仅是导入失败路径的耗时。即使未来能离线导入，潜在收益也取决于是否能摊销模型、程序集、JIT 和原生入场，以及导出是否仍要逐根支付原生成本。独立固定帧重建和原生重放另计，沿用 F5A 的分段证据，当前没有实测的节省量。

## 并发超时

F5A 六 worker 的六条失败都在 `i1_f3b` 等响应，最后一条已完成响应为 `f2_audit`。 `bank.Session` 的 12 秒 RPC 计时从请求日志写完、入写队列之前开始。包含实际写管道、宿主调度、预测准备、搜索、响应序列化、stdout 读取和日志写入，另受剩余案例期限限制。启动握手、此前的原生建根及后续审计均有各自请求。冻结搜索内部也有 12 秒热循环壁钟上限和转移预算，检查发生在搜索边界，外部相同长度的时限可能在内部返回 `wall_cap` 之前结束。客户端对读超时或取消执行强制关闭，成功的 `wall_cap` JSON 与客户端 `time_limit` 可以区分，但超时日志无法定位到 RPC 内的准备、搜索或回包，也没有部分转移数。

用这六根在冻结宿主上按 1→6→2→6 worker 各跑一批。每批只跑冷根恢复、首条 F3B 搜索及前后审计，启动按 worker 数同步释放。没有 F4、固定预测及严格原生重放的混合队列。逐根状态、动作与帧摘要及计费与串行一致。以下统计来自 [load.json](../experiments/m1-p2/load.json)。

| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 6/6 | 563 | 498 | 430 | 1,246 / 1,621 | 20.59 / 0.29 | 120.0 |
| 6 | 6/6 | 834 | 724 | 672 | 1,738 / 1,767 | 4.53 / 1.32 | 692.4 |

两轮六 worker 均拉长单根 RPC，预测准备和热循环都有增加。CPU 是进程搜索区间累计，包含进程内其他线程。总工作集接近 F5A 六 worker 的量级。该实验没有复现 12 秒超时，也没有采集 GC 暂停、系统 CPU 利用率、调度等待或缺页事件，无法把历史故障归因到 GC、内存压力或某个特定阶段。并行墙钟直接按批计量。各阶段 P50 不相加，六根的最大值只描述当前样本。

在含严格验证的混合负载，先用 F5A 对失败根成功的两个 worker，保留现有硬时限。若要增加并发，先采集请求相关 ID 和宿主侧 capture 开始/完成、进入搜索、完成搜索、开始回包的时标，把进程 CPU、GC 停顿及工作集附在相同阶段。以后可以把转移／软搜索预算留在求解器内部，由外层绝对截止时间为根准备和回包保留可测余量。任何阶段未完成仍保留失败和已有预算上界。

## 复现与检查

需本地固定原生 DLL、CS1 Solver DLL、S2B 正式归档和 F4 冻结宿主。在仓库根执行，运行输出使用新目录。

```powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
python -X utf8 experiments/m1-p2/build_probe.py
python -X utf8 experiments/m1-p2/run_probe.py boundary logs/m1-p2/boundary-repro
python -X utf8 experiments/m1-p2/run_probe.py load logs/m1-p2/load-repro
python -X utf8 -m pytest experiments/m1-p2/test_evidence.py experiments/m1-f5a/test_profile.py -q
```

实测 A/B 冷建分别为 2,061／2,192 ms，捕获为 231／290 ms，两次 fork 合计为 14.3／15.0 ms。导入进程握手 293 ms，三个导入请求为 379.2／2.6／2.0 ms。独立构建成功，7 条既有 GodotStubs 警告。只运行相关定向测试及本文实机探针，未运行全量 pytest 和五角色批次。搜索策略、计费、标签及严格验收无变更。
