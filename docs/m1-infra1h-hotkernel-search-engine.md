# M1-INFRA-1H · HotKernel 高预算公平搜索引擎

独立分支 `research/m1-infra`，冻结起点 `800310c631286a8cfb707e3d2a157d0d1017a66d`。五个负载均使用 STS2 v0.113.1、Ironclad、5C 高预算 V2、原 G2、开局效用、候选顺序、搜索预算及 NOSL 信息规则。5D、5E 的训练、开发、独立复评沿用 0B 已开放的分配。每个性能 treatment 使用一个 worker。

五套完整面板共有 162 条生产记录。严格候选的所有记录均对照冻结 0B 逐字段通过。原版累计 1041.61 秒，关闭逐命令峰值采样后 721.23 秒，修正后的 1A 批处理 678.36 秒。严格候选 1131.76 秒，分别达到同期原版和修正 1A 的 0.92×、0.60×。带分差回退及实例绑定修正的后一版本按下文的有界生产验收单列。倍率按相同面板的总 wall 计算，包含复杂根和所有回退。

## 遥测与计时口径

原 IntegrationProbe 在每条命令完成后调用 Windows `PeakWorkingSet64`。生产规划、动作选择、合法性和异常处理都不消费外层峰值字段。部分早期 F/B 系列独立诊断会读该字段。修正宿主默认关闭逐命令采样，`INFRA1H_REQUEST_RSS=1` 恢复旧字段。0B worker 在宿主进程关闭时使用 Windows 进程句柄取得峰值工作集及内核/用户 CPU，Python worker 同时保留自己的资源收据。

正式 wall 自启动 worker 至经验 gzip 完整关闭，worker 时间另含退出清理。账本按实验命令从启动至退出累计，包含构建、失败和全部诊断。单根时间由相邻行落盘时刻之差得到，首根含启动。不同处理发生在不同机器时段，单遍之比是观察值。归因遍与正式遍单列。嵌套的 C# 计时器与 Python/RPC inclusive 时间不能相加。每条经验只排除顶层 `seconds` 后逐行规范比较，检查根次序、错误、候选、概率、参考覆盖、预算、动作、战略 C、终局和准入。保留压缩原文和整文件哈希。[运行协议与命令](../experiments/m1-infra1h/README.md) · [离线验收器](../experiments/m1-infra1h/export.py)
