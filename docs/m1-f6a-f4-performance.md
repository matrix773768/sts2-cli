# M1-F6A F4 胜后优化剖析与等价改动

**Replay 是 F4 最大的实测热点。** 冻结常驻路径的 11 个预热根共用 3.31 秒热搜索，其中 Replay 1.97 秒（59.4%），完整状态摘要 0.65 秒（19.6%）。Replay 内的 Fork 为 0.19 秒。精简记录和哈希实现通过逐候选等价对照，求解线程分配下降 **6.9%**。热搜索在分批对照中少用 4.7%，同根交叉复测却多用 2.0%，完整批次吞吐也未提高。当前证据支持减少分配，生产默认继续使用冻结路径。

## 冻结范围与实验

基线为 `f8d5900`，`port/v0.113.1`。Windows、SDK 10.0.404、CoreCLR 9.0.7、游戏 v0.113.1／Build 26660232、CombatSolver 0.51.5。隔离宿主固定 Solver 和游戏 DLL，输出记录宿主哈希。复用 B1B 的六个开发根及其难度标签，覆盖两个角色、四种遭遇、两幕。先做三个位置的 A→B→A 试批，再扩展到每批六根两轮。验证和封存测试数据均未打开。

两种模式都采用 B1B 冻结配置。F3B C 与固定 F4 共用 512 次预测转移上限，禁主动药水，F4 计费包含保底胜路重建。候选以终局 HP、相同的药水槽位和发现次序终选。两组都执行相同首胜原生退役、地图清理和 profile 核对。F4 的终选是预测记录，原生退役证据对应首胜。猎杀者 E3 风险照常保留。

正式计时使用固定→精简→精简→固定四个独立常驻进程，每进程 12 个位置，阶段插桩关闭。两个另外的常驻进程开启剖析，每种模式 12 个位置。还做了 12 个位置的同根交叉对照，两次 F4 独立捕获与搜索，交替请求顺序，每根只退役一次。后者用于比较 F4，完整批吞吐只从四批单次 F4 的结果计算。各模式在搜索及退役前后核对原生审计。所有记录与 B1B 冻结冷结果一致，包括根身份、RNG、候选动作与顺序、逐步预测摘要、转移数、终选 HP、资源及退役帧哈希。

Replay 内最大的 Solver 独占子阶段是卡牌执行（547 ms），其次是快照（248 ms）、洗牌预测（192 ms）及 Fork（192 ms）。Solver 的这些子阶段有累计时间和分配量，现有测量器仅暴露 Fork 的可用调用计数。摘要次数包括每次记录及搜索后的根校验，记录次数含构造的根帧。保底 127 次、全部 2,846 次转移。原 F4 已重复利用价值为 1,680 次动作的保留前缀。25 次成功 Rollout 走到已知胜路而没有新增候选，发现时已支付转移。重复胜路键不足以证明不同候选的执行可省略，仍需保留相同异常、后继状态和计费。回复计量不含 Python 解码与日志落盘。

首根冻结 F4 热搜索 159 ms，含 146 次转移及 9.18 ms Fork。该根之后同一批还会复测，各根复杂度不同，首根与整批均值不能直接估 JIT 差异。剖析使用真实阶段作用域，有插桩成本；墙钟结论以关闭详细阶段计量的配对为准。完整结构化阶段为 [profile.json.gz](../experiments/m1-f6a/profile.json.gz)，汇总含分配量与单位成本。[summary.json](../experiments/m1-f6a/summary.json)

## 等价改动及实测收益

精简模式只在 F4 且未请求完整 history 时启用。省略不会返回的每节点历史条目及富牌堆／Power 展示数组，仍生成全部原有续体摘要并保留稳定节点序号。摘要仍对原始 UTF-8 字节做 SHA-256，复用临时字节缓冲区并直接输出小写十六进制。每次分叉校验、保底及最终根校验、候选生成与预算规则均走既有路径。每根重复使用只含已保留锚点的集合，释放及遍历顺序无变化。请求完整历史时使用原有完整记录路径。原生终局比较、原生退役和冻结 Solver DLL 未修改。

以下为正式配对 P50／P90，预热组每模式 22 个位置，其中简单 10、复杂 12。全根墙钟含退役，不含首次进程握手和最终回收，批次吞吐则包含二者。

| 计量 | 冻结 | 精简 |
| --- | ---: | ---: |
| 简单根 F4 热 ms | 172／305 | 176／264 |
| 复杂根 F4 热 ms | 712／937 | 645／908 |
| 所有预热根 F4 热 ms | 240／906 | 232／900 |
| 所有预热根全根 ms | 536／1,522 | 539／1,406 |
| 原生退役 ms | 130／317 | 129／344 |
| F4 转移数 | 167／496 | 167／496 |
| 每批完整根／秒 | 1.18、0.99 | 0.96、1.17 |

预热 F4 热时间合计从 **9.01 降至 8.58 秒**，全根合计约 **16.46／16.48 秒**。同根交叉样本排除首次 F4，11 对合计 **3.94／4.02 秒**，配对节省 P50 为 **−5.7 ms**。因此未观察到可重复的耗时加速，完整批次的吞吐差异也落在批间波动内。预热 F4 求解线程分配合计从 537.3 降至 500.1 MB（6.9%）。GC 暂停累计从 327 降至 218 ms，进程峰值工作集 P90 约 142／146 MiB。这些是小样本观测，吞吐、峰值与 GC 收益尚未建立稳定因果关联。[分批配对](../experiments/m1-f6a/paired.json.gz) · [同根交叉对照](../experiments/m1-f6a/local.json.gz)

## 优先方向

进一步逐候选等价加速的主要障碍在 Replay 本身。卡牌与回合推进、快照和洗牌必须在各自状态分支执行；换策略或锚点会改变续体，已有胜路去重发生在终局。可研究在相同父续体和相同动作下复用完整后继，前提是独立验证 RNG、私有模型、故障和所有调用者可见结果，且维持现有转移计费。当前数据不支持只靠少做 Fork、缩短锚点排序或压缩 JSON 获得大幅提升。

研究优先级是 **F4 的候选效率和 Replay 每转移成本**。需要保持完全相同候选序列的短期生产优化，可以独立剖析原生退役的协议与富观察开销。算法实验可单独试验按可观察的失血窗口调度候选，以成对固定预算、终选 HP 尾部和资源差分验收。

可以证明的质量停止需要明确上界及目标合同。在确认无机制能提高最大 HP 或其它目标资源、已有路线达到可证明 HP 上界、资源约束满足且平局规则保证保留更早路线时，后续候选无法改善该目标。达到入场 HP 本身无法证明上界。即使能证明终选相同，若减少候选或转移，也应作为单独的算法变体。F5B 的经验停搜始终关闭，本阶段未加入新停止规则。

## 复现与验证

仓库根使用本地游戏 DLL、RitsuLib 和 CS1 冻结 Solver。输出目录需为新路径。

```powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
python -X utf8 experiments/m1-f6a/build_probe.py
python -X utf8 experiments/m1-f6a/run_probe.py pilot logs/m1-f6a/pilot-repro
python -X utf8 experiments/m1-f6a/run_probe.py paired logs/m1-f6a/paired-repro
python -X utf8 experiments/m1-f6a/run_probe.py profile logs/m1-f6a/profile-repro
python -X utf8 experiments/m1-f6a/run_probe.py local logs/m1-f6a/local-repro
python -X utf8 experiments/m1-f6a/summarize.py logs/m1-f6a/paired-repro/results.json logs/m1-f6a/profile-repro/results.json logs/m1-f6a/summary-repro.json --local logs/m1-f6a/local-repro/results.json
python -X utf8 -m pytest experiments/m1-f6a/test_f4_performance.py experiments/m1-b1b/test_resident_production.py -q
```

隔离构建、实机试批及正式对照、5 项定向测试通过。试批为增加锚点和替代动作计时前的构建，正式数据使用同一最终宿主。未运行全量 pytest 或五角色批次。
