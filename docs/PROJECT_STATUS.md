## 本阶段交接

**最新长期架构共识（2026-11-19，规划/待验证）：** 详见 [端口驱动 NOSL–SL 双层决策架构](research-port-aware-nosl-sl-architecture.md)。共享机制表示学习条件组合与出牌顺序；三端口（输出/防御/运转）是可选、可消融的时序能力辅助表示；NOSL 仅用合法公开历史和合法动作实例做快速直接策略决策，可由价值头辅助训练；SL 在同一策略基础上于当前节点合法试探、修复、先固定胜路后优化资源；离线搜索数据需严格区分隐藏 RNG 教师与在线可见信息。Card ID、简单规则、四战略、LS2B StrategySpec 均作为独立基线或数据生成手段保留。不声称已经训练出该 NOSL 网络、实现合法在线 SL 或取得整局能力提升。

**建议下一研究切片（尚未实施）：** 可关闭的机制感知 NOSL 直接策略及端口/价值辅助的最小基线；先测合法动作接口、受支持完整单轨迹、训练信息边界与跨组合泛化，再将冻结 NOSL 接入 SL 搜索。模拟预测覆盖、多目标/选择、真实多幕局史和评估隔离与之并行，不以扩大 StrategySpec 枚举作为硬性前置。具体里程碑名称和算法待实验设计确定。

**M1-LS2B 已完成研究侧端到端实验。** 50 个开放开发根用于采集提议与编辑经验，冻结模型后在 40 个新合成根上比较四臂。学习臂与冻结 F3B C/F4 在 128／256 Replay 档均为 6／7 胜。256 档各有 3 个独有胜根，学习臂有一次预测死亡经编辑后重建首胜，最终锁定 8 HP。两档各在 17/40 根改变首个实际动作序列，总体发现率持平。StrategySpec 执行分支保留为研究对照；后续可检验前缀复用、选择边界与真实局史迁移，但新的长期学习主线转为机制感知 NOSL 直接策略。正常 SL 在线资格仍待验证。 [M1-LS2B 报告](m1-ls2b-compositional-strategy-search.md) · [研究主线](research-learning-guided-combat-search.md)

## 1. 项目目标与工作边界

长期目标：在允许 Save/Load（SL）的规则下，利用忠实于原生《杀戮尖塔 2》的无画面模拟器，组合模拟、搜索与学习，提高直至争取超越顶尖人类玩家的通关胜率。

当前研究重点是**高水平、低延迟的战斗决策**。默认战斗由原生引擎和简单策略执行。隔离实验使用真实跑局的原生根，比较冻结 Q1+Choice、简单策略、原生参考路线和可逐步验证的 [Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver) 离线教师。先建立战斗能力基准和可归因的胜负证据，为后续地图路径、卡牌奖励、事件、商店、休息点及资源分配等 M2 局外学习提供基础。

当前分工：本 ChatGPT 项目对话负责方案、审查和阶段验收；本地 Codex 负责源码、构建和实测；GitHub Desktop 可用于人工推送。各 Codex 主阶段建议开新对话，先读本文件与 `CLAUDE.md`，再检查 Git 状态。

## 4. 当前能力边界与不变量

**已支持且有实际证据：** 从合法地图检查点保存、独立进程加载、同一命令序列完整响应/地图重放；多个已测试场景的原生序列化 RNG、unknown-node odds 和地图历史一致；在不可变源检查点上做 A/B/A；真实路线进入第二幕及原生 Ancient 治疗；商店实际购买与删牌状态恢复。

**尚未承诺：** 任意时刻精准 `clone()`。当前 `RunSimulator.SaveCheckpoint()` 在 `MapRoom` 中可保存当前状态；在非地图房间会产生**进房前回退检查点**，并非当前战斗、商店、奖励或事件进行中的精确状态。M1 API 不得把它包装成任意决策可复制。需要显式检查和拒绝不安全位置（不应自动转换并声称精确恢复）。

**正确性不变量：**
1. 相同原生存档、游戏/引擎版本与动作序列，所覆盖路径须逐步一致；不仅对比初始 JSON，也比较后续响应、完整地图，适时比较原生 RNG、odds、历史。
2. A/B/A 从同一份不可变源检查点、独立进程运行；源文件字节和 SHA-256 始终不变。
3. 正常死亡 `game_over(victory=false)` 是有效游戏终局，不是模拟器故障；策略无法处理、非法动作、原生错误、通信错误、超时必须分类报告。
4. 所有真实路线测试只使用合法地图动作；`enter_room`、`set_player` 等辅助构造必须单独标明，不能冒充真实跑局。
5. 不擅自修改已有 M0 测试断言、固定种子或历史期望来掩盖回归。
6. 所有外部资源与存档、日志隔离；设置启动、逐命令、整局超时并清理子进程。

## 6. M1 搜索环境

### M1-A 架构决策

- 可恢复节点是经过验证的原生地图检查点。每个分支启动新进程，以进程退出回收原生单例、待决任务及事件订阅。调用者拥有子环境生命周期。
- 房间内按顺序执行。比较同一房间内的选择时，从地图检查点重放动作前缀，对照完整决策与地图。原生存档、进程内状态和协议观察各有自己的边界。
- 先用独立进程建立正确性与性能基线。常驻复用、进程池和原生内存复制需要另行验证。已观察到的单次加载耗时不足以推算批量吞吐。
