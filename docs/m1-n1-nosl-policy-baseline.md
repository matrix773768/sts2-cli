# M1-N1 初始策略基准

基线提交 `0deb046861aa36f121a21d67e242cfe386cb8da8`，分支 `port/v0.113.1`，起始工作区干净。STS2 0.113.1／Build 26660232，CoreCLR 9.0.7，隔离宿主绑定经过 E3F 实机校准的 CombatSolver `0.51.5-e3f.1`。N1 的入口、测试和统计脚本均在实验目录。

## 信息边界审计

| 层 | 数据与权限 | 判定 |
| --- | --- | --- |
| Q1 决策函数 | 格挡、敌方 HP／格挡／来袭及手中合法牌菜单；按即时伤害、挡伤、斩杀、抽牌和能量打分 | 函数不访问 RNG 或模拟器。原样复用 F3B 的投影输入 |
| AGGRO、DEFENSIVE、ENGINE | 额外使用当前 HP、能量和已绑定选择。AGGRO 优先杀敌与攻击；DEFENSIVE 优先挡伤；ENGINE 调度能力牌、成长、抽牌、祭品与开悟，危急时优先防御 | 每次只挑一个动作，复用现有分支及稳定菜单顺序 |
| 投影观察和合法菜单 | `ObservePrediction` 用内部模拟对象的当前敌招、`HookMirrors`、计算变量注册表、可打性和费用。回调菜单由 `CardChoiceSupport` 从模拟牌区构造，头槌、幸存者使用既有排序与实例绑定 | 读内部预测信息。部分值可能等价于可见预览，尚未逐字段证明所有镜像与选择菜单都满足公开边界 |
| 转移及审计 | `Step/Replay` 执行一个动作，内部持有抽牌顺序及 RNG。延续摘要、完整牌区和风险只用于审计及边界停止。策略没有动作候选的试算结果、未来回合预测、诊断或其他路线结果 | 单轨迹预测基线，证据为 `prediction_only` |
| 原生公开策略 | 从当前 `combat_play` JSON 构造不可变 `Observation`，包含格挡、当前已展示敌方意图和当前牌／目标的合法菜单与 UI 预览。每次只提交该原生动作，下一次读取动作完成后的实际公开状态 | 在该专项的牌组及动作范围内实现可审计的 NOSL。根快照只用于隔离校验。遇到未支持的交互边界停止 |

完整牌区和起始种子留在实验审计侧。显式禁止从日志、帧摘要、未抽牌序与其他策略回传数据到决策器。原生公共 JSON 的 `damage_by_target` 与执行索引由同一存活敌人序列生成，意图多段伤害按公开次数汇总。原型只消费几个公开字段，目标预览为空的牌不会凭内部模型补值。该接口目前覆盖受测火焰屏障牌组，没有给四种原策略建立全卡池的原生适配。

## 协议

每个策略单独向同一个未改变的原生战斗根请求一个新预测起点。仅选择和推进一条线，无回溯、失败诊断、前缀替换和胜后优化。每条最多 48 次动作及预测尝试，沿用 12 秒热墙钟与 448 MiB 保护。每次核对原生根未改变，宿主另核对预测根摘要。所有组禁主动用药。热耗时包括观察、决策、转移及逐步记录，排除建根、预测根准备、RPC 输出和原生核对。预测尝试若因不支持而失败，可以比已完成动作多一步。建根级不支持没有热轨迹，仍计入胜率分母。

S2B 取已有 `early` 开发条件；S3B 使用冻结的 24+72 个第二幕困难开发根；F3A 使用五个 F3B 已公开的严格恢复根，来自同一条第一幕历史的辅助分支。前两组均为合成根，自然可达性为 unknown。F3A 标为真实跑局来源、辅助局史，证据仅覆盖对应入场路线。S2B 初次取样读取了混合划分的计划清单并选出开发配方；没有载入验证或测试战斗归档、检查点和路线。复现入口使用固化的开发配方。

## 后续学习

先把原生最小接口扩展到可公开操作的牌堆计数、弃牌／消耗候选和牌组公开信息，并对动态预览、能量和多段意图做投影／原生差分。对无法投影的动作保留 unsupported 及机制 ID，训练和评估时单列覆盖率。

用同一根上独立得到的策略轨迹构造开发期监督信号，先学习目标、挡伤、过牌与成长的排序，再比较首次胜率与有限预算下的边际救活率。对目标选择记录即时来袭、打穿格挡的有效伤害、斩杀、预期反伤与后续决策，单独分析有首杀价值的换目标和因反伤而应暂缓击杀的情况。按独立局史划分数据。相同局史的分支、同构筑多种子和同一根的反事实策略不能冒充独立跑局。

SL 增益实验本轮省略。后续可从同一批预选开发根出发，用固定额外预算比较各策略的动态后缀修复。首次结果保留，修复的额外转移和独立原生成功率另计。尚未训练模型。

S2B 每种策略的四个 unsupported 都发生在预测根初始化，原因是 Neutralize 的 Harmony 镜像检查。S3B 的 unsupported 均有轨迹，边界码和预测缺口留在原始帧；其余停止均为表中的胜负。F3A 四策略都预测赢两场 TUNNELER、输三场 BOWLBUGS。

若离线尝试四条反事实路线后选择任一胜路，覆盖是 S2B **28/32**、S3B **6/96**、F3A **2/5**。这项上界消耗四次独立尝试。S3B 历史 F3B C 的 7/96 使用 512 次以内的路线搜索，不能用它直接估计将同样搜索预算加到某一条固定初始路线时的增益。

## 火焰屏障／BOWLBUGS 机制对照

冻结基准后运行两套对照，均从原始根独立执行一次，随后每步按新观察重新决策。

- **预测目标变体。** `THREAT_V1` 以 ENGINE 为底，把普通攻击的目标优先级从「HP＋格挡－来袭」改为先看来袭，再选耐久低者。`DURABLE_V1` 在代表根上改为优先攻击 HP＋格挡最高的目标。其余 ENGINE 规则，包括格挡、斩杀、成长、能量和抽牌优先级，继承冻结实现。24 个 BOWLBUGS 根上，THREAT 改变了 11 条动作序列，配对结果逐根相同，均为 0 胜、22 死亡、2 个待决选择。代表根 `f2f29fd990637955` 的两变体都死于第 5 回合、16 动作、敌方总余 45 HP；当回合痛击在两个变体分别指向 combat id 2 和 1。原策略四条均死亡，敌方总余 43–57 HP。S3B 已有独立严格原生核对的 21 步胜路，锁定 20 HP，说明该根确有胜路。
- **原生公开观察变体。** `PUBLIC_SCORE_V1` 以公开的即时伤害、挡伤、斩杀、抽牌、能力与费用评分选牌；`PUBLIC_THREAT_V1` 保留该张牌和即时斩杀，普通非致死攻击再在能打穿格挡的目标中优先选当前来袭最大的敌人。同分沿用原生菜单顺序。四个火焰屏障／BOWLBUGS 开发根上，两组均原生死亡 4/4。在代表根，第 2 回合同一张攻击由公开目标索引 0 改到 2，第 5 回合又由当时的索引 0 改到 1。两组均走 15 个动作，终局敌方总余从 43 变成 50 HP。其余三根的动作数分别为 9、10、15，终局敌方总余分别为 102、95、110 HP，两组相同。当前规则没有改善首次胜率。目标排序须联合反伤触发、有效伤害和斩杀时机评估。

公开索引随存活敌人重排，只在对应的一步有意义。预测 combat id 在相应轨迹中稳定。公开对照的计时含逐步 RPC，预测计时在进程内，两组使用不同的测量区间。两套规则和结果分别保留。[预测对照](../experiments/m1-n1/target-experiment.jsonl.gz) · [原生公开对照](../experiments/m1-n1/public-target.json)

## 原生抽查

按每个队列首条预测胜路抽查。S2B Q1、S3B AGGRO、F3A Q1 分别 **12/12、20/20、37/37** 步严格匹配并实际获胜。抽查先在独立预测进程固定重放并核对帧，再在新原生进程按动作逐步执行，核对 continuation 与正常胜利回调。抽查只验证这三条路线，不能审定投影策略的信息边界。基准账本保留预测证据；严格检查结果单列。[独立原生核对](../experiments/m1-n1/native-audit.json)

## 复现与检查

在仓库根使用同版本游戏 DLL、RitsuLib、E3F Release 构建 `logs/m1-e3f/release` 及原 F3A 开发检查点 `logs/m1-f3a-formal`。S3B 输入来自已归档的两个开发批次，S2B 使用实测的 [32 条开发配方](../experiments/m1-n1/s2b-early.json)。输出目录须为新目录。F3A 使用同一 N1 代码叠加到可读档的 F3B 隔离宿主。实测中原合成宿主主动拒绝 F3A 读档，随后保留已完成的 512 条合成结果，用读档宿主完成 F3A 的 20 条记录。需要复用同一完整合成前缀时可传 `--synthetic-prefix`。

~~~powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
python -X utf8 experiments/m1-n1/build.py
python -X utf8 experiments/m1-n1/benchmark_n1.py logs/m1-n1-repro

python -X utf8 experiments/m1-n1/benchmark_n1.py logs/m1-n1-target-repro --baseline logs/m1-n1-repro/results.jsonl.gz

~~~

两个隔离构建成功。定向测试覆盖开发样本与基准覆盖、单轨迹及同根摘要、原生观察字段、合法目标变体及证据档案。没有运行全量 pytest 或五角色通关。实验未修改冻结 F3B C、F4 的生产源文件或入口。
