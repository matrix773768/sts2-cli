# M1-RUN v0.1

## 完整跑局与局外战略决策

**版本 0.1 | 2026-11-28 | 新研究线设计稿**

项目：`matrix773768/sts2-cli`。本线面向 NOSL 完整跑局，继承 [PROJECT-VISION v2.0](project-vision-v2.0.md)、[M1-CORE v2.0](m1-core-v2.0.md) 与 [M1-INFRA v1.0](m1-infra-v1.0.md) 的公平信息、性能和数据合同。RUN 为拟议独立研究线，尚未建立正式基线或选定长期后端。

> 尽早从新游戏连续运行至真实胜利或死亡。以真实构筑与资源分布支持战斗学习，并逐步通过搜索与自主学习提高局外决策，最终联合优化完整通关目标。无需等待 CORE 获得稳定代际收益，也不需要先完成所有游戏规则的独立移植。

## 1. 研究范围与成功标准

首期选择 Ironclad、单人、较低进阶（建议从 A0 开始），使用固定游戏版本和可审计种子协议。正式任务只利用合法公开信息，不因死亡重开，不用 Oracle 或人为添加资源制造成功率。游戏版本可根据外部后端的实际支持选择；旧 v0.113.1 数据、权重及能力基线完整保留，不静默混合版本。

RUN-0 的工程目标是合法完整闭环，而不是第一版即有高通关率。低能力、正常死亡仍是有效数据；机制失败、超时、非法或未解决不等于死亡。以后逐步比较局外策略、战斗策略及联合优化在相同真实跑局任务上的表现。最终面向 NOSL 超人能力，不把 SL 作为当前必要阶段。SL 仅在未来 NOSL 证据支持且明确规则后启动独立研究。

## 2. 为什么真实跑局必须尽早进入研究

当前 CORE-5G 有4,096个无活动遗物/药水的独立自然训练族、19,936 C，已获得规模和优化强度改善预测的证据。但该构筑分布并非真实取得过程；单场终局效用也尚未表达下一个节点、金币、药水、先古遗物及成长的完整价值。

5D 已归档236个合法原生战斗开局，三章分别216/16/4根，独立种子33/4/1个；每章有地图存档重载抽检。观察到的69种遗物在旧静态遗物表中显式覆盖仅燃烧之血。这是起始资产，不是充分的后期真实分布，也不证明现有战斗策略已支持遗物域。RUN 应主动补真实路径、资源与机制频率，以实际阻断及战略价值决定后端/编码需要扩展的内容。

```text
局外策略 ──► 真实构筑、路线、资源 ──► 战斗根
    ▲                                  │
    │                                  ▼
跑局价值/反事实 ◄── 真实战斗资源结果 ◄── CORE
    │                                  │
    └──────── 完整跑局经验与联合学习 ─────┘
```

合成战斗仍用于机制、困难课程、控制变量和规模对照；真实完整跑局逐步成为另一主要经验来源。真实状态中的先古遗物、升级、消耗、生命与金币变化不应被合成重建抹去。优先复用能真实执行它们的环境，而不是先为所有组合人工制定价值规则。

## 3. RUN-0：环境与最小完整闭环

### 3.1 环境选择及接口

INFRA 负责外部引擎选型与长期性能潜力验收。RUN 可以在现有原生环境上先完成可运行原型，也可以直接使用可用的外部候选，但不因原型成功就将其冻结为长期后端。优先共用稳定的 `open / observe / legal / step / checkpoint / fork / restore` 等概念接口，以及合法条件世界采样；定义完整跑局状态与战斗子状态之间无损资源交接。具体语言和实现由 INFRA 选择。

- 真实状态：地图及尚未公开的生成结果、所有 RNG 流、牌实例、遗物和计数、药水、事件状态、战斗与奖励待选。仅环境侧持有。
- 公开状态：角色、进阶、章节/楼层、可见地图与已访问路线、HP/上限、金币、牌组/升级/公开实例属性、遗物/计数、药水及当前合法选项、已公开敌人/奖励/事件历史。
- 决策接口：返回稳定观察、合法动作及目标/选项绑定；真实执行产生下一公开决策或实际终局。回退动作只能从合法菜单选择；不自动跳过奖励、强制改血或隐藏失败。

私有种子、未来地图内容/奖励、未公开战斗牌序和随机流不能成为策略输入。完整跑局分叉允许环境复制与合法重采样，不修改实际比赛轨迹。在候选后端中应验证快照恢复、资源持久性、楼层切换和分支隔离；不要求先为全卡池做逐项原生认证。

### 3.2 固定局外基线

初版先采用透明、可解释的规则/启发式策略。它的目的在于自然地产生跑局经验，建立可替换比较基线，而不是硬编码大量人类攻略或所有卡牌协同。

| 决策类型 | 第一版原则 | 后续研究 |
|---|---|---|
| 起始/先古遗物 | 按合法资源、牌组与持续效果选择；真实副作用保留 | 能量、抽牌、成长收益及构筑协同 |
| 卡牌奖励/跳过 | 依据即时输出、防御、运转与牌组需求；允许不拿牌 | 反事实续局、未来协同与稀释成本 |
| 地图路线 | 可见节点、风险与收益、HP及后续恢复机会 | 多节点条件搜索和动态风险管理 |
| 篝火 | 依当前生命与未来压力比较休息、升级及合法选项 | 资源边际价值及成长机会成本 |
| 商店 | 选择购买、删牌、保留金币；按合法价格和资源 | 多动作预算分配、延迟购买价值 |
| 事件 | 依据公开选项及规则结果；未知事件用明确合法回退 | 公开风险及长期价值估计 |
| 药水 | 允许合法即时/保留选择，完整记录使用和库存 | 战斗与局外联合资源机会成本 |
| 战斗 | 选择已验证的适用后端和固定策略；记录回退 | CORE 价值、搜索教师与策略蒸馏 |

现有 H5 tactical32 排除活跃遗物、宠物与非空药水槽，不能直接认定可执行所有真实跑局。初期优先利用能够正确处理真实机制的环境及合法基础策略；旧模型若缺信息，标为迁移挑战者而非正式强策略。混合后端必须明确一致的资源边界、状态恢复和策略身份，不用不可靠的状态转译强行续战。对实际阻断最高频的机制优先修复，原生回退不能伪造真实成功。

### 3.3 RUN-0 交付与验收

先冻结一个小型工程面板验证主要决策类型的连续合法执行，再在事前冻结的代表性完整跑局面板评价（建议初次约128–256个种子，依实际耗时和覆盖调整）。少量成功通关仅是可行性见证，不能代替总体完整率和通关率；若自然通关极少，可另设合法课程、既有后期存档或强起点用于接口诊断，但分开报告。

输出完整跑局、真实失败与资源轨迹，按章节统计到达、Boss结果、战斗数、遗物/药水、局外决策数、机制阻断及实际成本。冻结局外策略、战斗后端、模型和所有回退规则。完成条件为可从新游戏连续执行真实局内外决策至合法终局，获得可重跑的证据和明确支持范围；不能把跳过困难战斗或人工补资源的轨迹算作自然完成。若长期性能不足，返回 INFRA 选型问题，而非在 RUN 中整体重写模拟规则。

## 4. RUN-1：局外价值、资源与构筑学习

令 s 为公开跑局状态、a 为合法动作，π 为固定后续局内外策略，定义 `W^π(s) = E[R | s, π]`。首要最终奖励 R 为实际通关（胜1、败0），失败/未知不补0；辅助预测包括章节到达、战斗资源结果、构筑强度、金币/药水及剩余节点。中间奖励或风险偏好作为可验证的研究假设，不未经检查取代最终通关目标。

局外价值学习优先使用完整自然跑局和实际状态转移，可结合 MC、TD、多步目标及策略/价值共享。一个跑局中的多个节点共享终局，按跑局族管理统计与训练权重。按章节、构筑来源、HP、资源及策略分层，不以到达后期的生存筛选子集直接估计总体通关率。早期数据不足时保留透明启发式作为生产策略，并用合法的已有后期根补充机制学习，课程数据另标。

初期模型可使用共享实体表示，包含牌组、遗物、药水、资源和可见地图/未来节点结构。借助战斗模拟、CORE 的 C 价值与真实战斗结果学习牌组供给与敌人需求。是否复用 CORE 表示、使用独立 RUN 价值或共享网络由实验决定。暂不人工枚举所有协同规则；优先让模型从经验和合法搜索中学习。

资源价值研究需区别同样 HP 损失的未来后果。例如损失生命但保存关键药水，与无伤却耗尽药水，后续通关价值可能不同。保留真实联合资源结果，不先把各资源分数无条件线性相加。研究局外决策时先冻结战斗策略，以分离改进来源。

## 5. RUN-2：局外搜索、反事实与策略学习

对同一公开根 s 的候选动作 a，目标是比较固定续策下的 `Q(s,a) = E[W(S_future) | s,a]`。后续模拟深度可从下一公开事件/战斗到若干节点，再逐步研究完整续局。局外分支比单回合战斗时间尺度长，不必对所有状态统一采用昂贵整局搜索。选择高价值关键奖励、构筑变化、路线分岔和资源取舍进行更充分搜索。

| 研究模块 | 核心方法 |
|---|---|
| 状态分叉 | 从同一合法公开根保存环境快照，分别执行候选；实际策略不能读取私有世界。 |
| 条件世界 | 对未知未来按合法公开条件采样；共享同一世界或随机流降低比较方差，记录动作导致的事件分歧；不强行令两条路线产生相同不可能的奖励。 |
| 搜索截断 | 固定后续策略和深度，用真实资源或经验证的 W 评价；另以独立世界和更长续局检验教师收益。 |
| 策略学习 | 利用搜索教师、主动探索及真实局外回报训练候选引导或直接策略；避免模仿不可靠的知情 Oracle。 |
| 计算分配 | 低成本策略生产大量自然局；昂贵教师研究少数分歧或潜在高收益根；报告每单位成本的真实收益。 |

局外行动可能改变未来牌池、随机流消耗、路线或事件支持集。共同随机数设计需尊重这种因果变化，不能通过共享种子把不可同时出现的未来硬绑定。选案与独立复评隔离，保留分歧采样与随机代表根。完整回合、局外多动作（例如商店组合）可作为条件程序，但最终执行必须逐个合法公开菜单绑定。

## 6. RUN-3：战斗与局外联合优化

首先建立固定局外策略的完整跑局对照，检验 CORE 的能力变化是否真正提高通关潜力；再固定战斗策略研究局外更新；最后联合更新并与各固定版本比较。避免一次同时更换后端、战斗策略、局外策略和奖励而无法辨识贡献。

令 s 是战斗前公开跑局状态、μ 是战斗条件策略、Y 是真实战斗后资源与持久状态结果，W 是固定局外/后续跑局价值。联合目标为 `E[W(Y) | s, μ]`，失败为吸收终局。旧 CORE 战斗效用作为对照，后续可将药水、HP、金币、永久成长、路线风险等真实联合结果输入 W。若需要条件价值模型，显式记录目标续策、输入及终局定义；不能直接把旧净战损分布解释为通关概率。

跨线迭代：RUN 生成真实构筑和战斗根 → CORE 学习真实资源结果与战斗策略 → RUN 用更强战斗接口评价构筑和路线 → 新的完整跑局经验更新两类策略。每轮允许冻结一个组件作为对照并拒绝无效更新。随着学习增益与性能需求提升，考虑策略/价值共享、搜索蒸馏及完整跑局强化学习；不预定 PPO 或其他特定算法。

## 7. 评价、性能和阶段安排

| 评价域 | 问题与主要指标 |
|---|---|
| 冻结合成战斗 | 战斗机制、价值、搜索能力与成本；保留历史 CORE 面板 |
| 真实跑局战斗根 | 真实构筑、遗物、药水及资源下的迁移与完成率 |
| 固定局外完整跑局 | 不同战斗策略对全尝试通关、章节到达、资源和成本的贡献 |
| 固定战斗完整跑局 | 不同局外策略的真实增益 |
| 联合策略完整跑局 | 最终 NOSL 通关率、稳健性、总体计算及人类可比性 |

统计以整局种子/路线族为单位，按相同开局种子配对，衍生状态不能跨 split。记录全尝试通关率、真实死亡、机制失败、超时、共同完成效用及失败原因；报告章节到达和平均有效战斗数，避免筛选成功局夸大能力。新的独立确认不参与选择或训练；旧面板回归不再称独立。逐步扩大确认种子以控制不确定性，并预先定义基线更新条件。正式与人类比较需同版本、进阶、规则、种子协议及合法信息；不引用外部模拟器内部成绩作为已验证原生通关率。

继承 INFRA 前置性能合同：底层单核10万–100万规则动作/秒、热复制微秒级目标；快速完整跑局四 worker四小时1万局。后者对应约5.76 worker秒/有效局的设计预算。完整跑局吞吐必须包括地图、奖励、商店、事件、战斗、真实推理及经验写出；按实际局深/动作数、通关率与完成率分层。RUN-0 原型不要求立即达到最终目标，但正式后端冻结前要完成代表性端到端负载并论证长期余量。高预算教师另行能力—成本曲线，不用大量早期死亡达标。

| 阶段 | 当前状态 / 进入条件 | 主要交付 |
|---|---|---|
| RUN-0 | 拟启动，与 INFRA 选型、后续 CORE 研究并行 | 统一公开接口、可运行全局基线、真实路径/构筑/资源经验、性能报告 |
| RUN-1 | 有足够真实终局和状态覆盖 | 跑局价值、资源与构筑预测、独立整局基线 |
| RUN-2 | 可恢复完整跑局根，有合法条件采样 | 局外搜索、配对教师、独立决策收益及成本 |
| RUN-3 | CORE/RUN 资源及续策身份接口可靠 | 固定组件对照、联合优化、通关能力证据 |
| 后续扩展 | 依据实际完整跑局能力与吞吐 | 更高进阶、其他角色、正式 NOSL 人类对照；按需考虑 SL |

## 8. 研究交接与首任务建议

RUN 使用独立工作树/分支（建议 `research/m1-run`，实际起点由已冻结环境选择决定）。不修改 CORE 已冻结的5H资产、后续并行任务源码或 INFRA 冻结发布。共享环境和经验时只读传入确切版本；写入、构建、端口和日志隔离。第一项任务可调查已有 sts2-cli 原生地图和存档资产、定义公开动作接口、准备固定规则基线及记录协议；优先完整跑局原型，避免提前设计全部局外神经网络。正式高负载实验依据 INFRA 的环境实测安排，普通任务建议约120 worker分钟计划预算，长跑另行授权。

证据起点：[CORE-5D 原生构筑准备](https://github.com/matrix773768/sts2-cli/blob/5bb7c68bbb66e25b419460743d09f74568ca3372/docs/m1-core5d-autonomous-learning.md)；[CORE-5G](https://github.com/matrix773768/sts2-cli/blob/1afd5ea78ebc1555ca5725533b2a1f1ec3783146/docs/m1-core5g-scaled-value-learning.md)；[INFRA-1H5](https://github.com/matrix773768/sts2-cli/blob/7b0f21e4420d1ebf61e7103a874e77af3c8313c5/docs/m1-infra1h5-production-qualification.md)。本版任务、首期范围与评测规模是拟议设计；未开展本地环境测试、未决定主后端、未建立 RUN 实施分支。
