# M1-PRE0 Ironclad 高吞吐 NOSL 数据生产

## 口径与基线

从 `port/v0.113.1@afdc9f219f6db6b669cb1b3daa381f8f1e6da414` 开始。每次尝试均启动一个真实的预测 episode，按当前公开观察逐动作调用冻结 v4，直至 Solver 终局、动作预算或明确的失败边界。完整轨迹要求预测胜或败、有可用终局、每个选择均来自当步合法菜单、序号连续且均已推进。按 `prediction_only` 保存。终局标签取 Solver，原有 L3、F3B/F4 和训练入口保持各自原来的代码与证据。

端到端从 Python 入口开始，计入导入、产物校验、目录、策略加载、调度、逐步推理、事务落盘和进程回收。生产窗口从准备完毕后首次提交前到最后一笔提交及 Worker 回收后，含各 Worker 的首次启动和周期回收成本。两种口径的分子均为实际提交的尝试、完整轨迹或完整轨迹的决策。CPU 和工作集为 Windows Meter 每 200 ms 采样的 Python 加已登记宿主。压缩字节率计数据库净载荷，输出增长率计数据库、隔离日志及宿主目录的逻辑字节增长。

I 阶段历史采集账本包含 6.63 条/s，采用较早宿主及当时的原生退役和旁路审计。历史 Ib 的 6.80 训练条/秒、5.01 整程条/秒使用窄卡池和当时的资格口径。冻结 v4 的 P0 预测段以两名冷 Worker 在 24 个全职业 999 HP 根上测得 0.837 尝试/秒和 0.732 明确预测胜败/秒。PRE0 的原宿主 24 根混合 Ironclad 对照为 15 条完整轨迹、282 个有效决策，4 Worker、0.52 端到端条/秒、0.95 生产窗口条/秒。旧宿主拒绝 9 个精英或 Boss 根。未复现约 6 条/秒的历史成绩。历史边界见 [P0](m1-nosl3c-iii-p0-throughput.md)。

## Worker 和存储

- `experiments/m1-pre0` 独立构建宿主。运行时校验游戏和冻结 Solver，逐进程检查实际加载的 Solver 版本与 SHA-256。PRE0 重新编译隔离宿主，扩展同幕原生目录的普通、精英和 Boss 房间构造。合并原有建根、预测源绑定和 episode 建立为一条 RPC。
- 常驻 lane 同一时刻只持有一个根。每根新建策略记忆与行为 RNG。结束时释放交互 episode 和两个桥接资源，再在动作执行器及同步队列空闲时放弃未推进的原生入场战斗。清理后重新创建 RunSimulator 并核对初始 profile。达到生命周期、每进程任务数或采样工作集上限时回收。异常或复位失败时关闭进程，下一任务重建。逐根冷模式保留作配对和隔离后备。P1/B1B 的原始复位要求已结算在地图上，预测副本执行动作后，原生根仍处在入场战斗，因此为 PRE0 增加了专用的放弃清理入口。参考 [P1](m1-p1-hot-worker-experiment.md) 和 [B1B](m1-b1b-resident-prediction-production.md)。
- 调度器最多保留一项任务每 lane，写入后随完成随补充。LS2A 的压缩负载与事务账本设计用于逐轨迹 gzip BLOB 和 SQLite FULL 同步事务。公开训练记录和隔离的根配方、故障明细及时间成本在同一事务写入，任务序号和 ID 唯一。不同启动的 Worker 数与回收限额可调整，同一数据目录锁住数据合同、配置、宿主、模型及批推理模式。恢复跳过所有已提交任务，包含有明确定性的失败结果。
- 策略只接收现有 II-D 公共投影处理后的 observation 和自己的历史。种子、运行时 RPC 日志和私有错误详情位于隔离元数据或宿主日志。每步存完整合法菜单、实际动作及行为 logp。公开记录存预测终局、资源、预测 gaps 与公开 N2E 资格。完整的 end-turn 致胜按 Solver 结果记录。
- 版本化 Ironclad 配方包含 12–20 张牌，25% 可升级牌升级，999、160、80 入场 HP。资源采用无遗物及药水的固定合成分布。卡组去升级多重集的哈希控制 80/10/10 划分，同源根和卡组家族落在同一分区。运行时检查原生职业池、入场排除项和生成牌允许表，覆盖手牌、可见牌堆和公开选择候选。看到未知牌时保留 unsupported 原因。允许表以原生目录和已知状态牌/生成牌为起点，覆盖报告基于实际观察。
- 任务队列、推理队列和动作长度均有上限。Worker RSS 上限在根间检查。SQLite 有页数上限，输出树每 64 笔提交检查一次，达到预算后停止补充并排空在途任务。宿主日志在两次检查和排空期间可能超出软上限。

## 复现与 PRE1 调用

从仓库根执行，使用已部署的 II-K.5 游戏、运行时和冻结 Solver。要重建分开建根 RPC 的配对宿主，构建时增加 `--separate-root-rpc`。

```powershell
python -X utf8 experiments/m1-pre0/build_host.py logs/m1-pre0-host-local
python -X utf8 experiments/m1-pre0/run.py logs/m1-pre0-local --host logs/m1-pre0-host-local --fast --workers 8 --recycle 32 --batch 8 --seconds 605
python -X utf8 experiments/m1-pre0/verify.py logs/m1-pre0-local/dataset.sqlite
```

`--checkpoint <training.sqlite> --update <step>` 以只读方式加载历史 v4，验证事务摘要及模型哈希。正式性能测试冻结 P0 初始化权重。已用 P0 更新 1 检查点另试跑 4 根，4 条完整、91 个有效决策。创建输出目录中的 `STOP` 文件可停止补充并排空。在原路径移除该文件后用同一配置、宿主、权重和批模式恢复。进程被强制打断时，SQLite 恢复未提交事务；再次运行时这些任务重新排队。数据的容量控制使用 `--disk-mib` 和 `--worker-mib`。

PRE1 在将 `experiments/m1-pre0` 加入模块路径后使用 `dataset.batches(path, size=32, split="train", complete=True)`。每批返回已校验内容摘要的公开轨迹；`complete=False` 可读失败诊断。行为模型身份、策略版本、逐步 logp、终局和合法菜单保留于同一公开合同。`verify.py --reference <另一个 dataset.sqlite>` 对同一根序列比较公开轨迹与预测结果。私有表和宿主日志不经过 reader。



需要物理分片时，用 `python -X utf8 experiments/m1-pre0/export_shards.py <dataset.sqlite> <output> --split train --size 256` 从已关闭的数据集导出。每片 gzip JSONL 原子发布，清单记录分片行数和 SHA-256。中断后以相同参数重试会核对并复用已发布片。PRE1 可用 `export_shards.read_shards(output)` 按片读取，仅含完整公开记录。4 片共 28 条的小样本导出已逐条与 SQLite reader 对照。
