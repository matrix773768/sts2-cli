# M1-I2 可复用 CombatSolver 战斗执行与连续跑局

2026-11-18。Ironclad A0 固定种子 `run_1` 从 Neow 启动，在同一 Headless 进程中连续完成三场经逐动作验证的 CombatSolver 胜利，并各自领取奖励、返回地图。第四场由回退策略获胜，第五场由回退策略正常战败，收到原生 `game_over(victory=false)`，引擎退出码 0。整局实验计 106 个动作请求，其中一个是验证用的故意拒绝请求。

实验沿用 M1-I1 的隔离构建和真实 `CombatState` 捕获。版本与 M1-I1 相同，为 STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7、CombatSolver 0.51.5 / `78e4545e825e58c3d999354b1ffcd54241b1d2cf` 未优化基线。运行入口校验游戏与求解器 DLL 散列。生产入口及 Steam 文件没有变动。

## 接口与执行

实验协议在原 M1-I1 命令上增加 `schema_version=1` 和 `mode=offline-teacher`。`i1_begin` 绑定当前原生玩家决策和敌人实例并取对照帧，`i1_capture` 运行单次有界搜索。完整预测胜利且动作形状受支持时返回 `complete_win`、计划及逐步预测帧。截断而没有完整胜路时返回 `budget_exhausted`，其他未找到完整胜利的结果用 `no_complete_win`。当前机制或计划动作不支持时返回 `unsupported`。计划状态及求解器边界分别记录，故节点截止前找到的完整胜路可以继续验证。第六层同时出现节点边界和用药动作，接管状态按不支持动作记录，且 `predicted_win=false`。

`i1_step` 检查当前回合、卡牌 ID、状态键和出现序号，并用当前 Combat ID 映射存活目标。原生合法性检查通过后调用现有 Headless 动作入口，返回实际动作参数和原生采样帧。控制器比较根、求解前后的现场状态和每步结果。战斗终止钩子只装一次，在原生清理前采样。每场执行或预检回退后发 `i1_release`，释放旧战斗、采样闭包、终态和战损追踪引用。奖励和后续房间仍由原生跑局处理。

已知的预检拒绝可在未改变现场时交给 `room_policy.combat_action`。映射不合法、首次差分、引擎异常和超时分别记录并停止，避免在动作可能已执行的状态继续。原生死亡独立记录为 `defeat`。若完整计划执行中收到原生正常死亡，将同时记录该回放与预测不符。回退执行和奖励动作单独写入轨迹，回退胜利不计入求解器验证通过。

原生执行列包含 IPC，求解器接管行还含逐步差分帧采样。执行列排除奖励和故意拒绝验证。整局握手约 239 ms，初始化并到达 Neow 决策约 2,070 ms，无读档恢复。整局约 14.72 s，工作集峰值约 164.4 MiB。首行是进程首次搜索，后四行是不同战斗根的实际进程复用。未做同根预热，不能从这些样本分离场景复杂度与预热收益。

前三场锁定胜利时 HP 分别为 76、76、75，原生胜后分别为 80、80、81。两场回退从 81→34 和 34→0。报告 JSON 记录起点及结算后的牌组、遗物、金币、最大 HP 和药水；HP 指标是两个决策边界间的净变化，未测累计受击伤害。对账覆盖有序牌堆、双方战斗资源、Power、怪物 AI、卡牌动态变量和续用 RNG 戳。奖励发放和永久资源变化使用原生观察。

每场最多 1,000 节点、DOP 1、6 s 软预算和 8 s 取消令牌，命令等待上限 12 s。计划最多 48 动作，回退及结算共享每场 80 个动作上限，整局最多 480 个动作且截止 120 s。托管堆硬上限 256 MiB，命令结束后检查 512 MiB 工作集高水位。工作集检查是检测阈值，不能当作对原生分配的硬限制。

## 复现与范围

沿用 [M1-I1](m1-i1-combat-integration.md) 的本地依赖配置，从仓库根运行：

```powershell
python experiments/m1-i1/build.py
python -X utf8 experiments/m1-i1/run.py
python -X utf8 experiments/m1-i2/run.py --seed run_1 --verify
```

构建通过。M1-I1 原固定检查点独立重放仍通过 13/13 步。M1-I2 的定向验收要求同一局至少两场完整对账并完成结算、收到正常游戏终局且进程退出码为 0。同时注入错误回合，确认原生动作未执行且状态帧不变。默认输出为 `logs/m1-i2/report.json` 及独立引擎日志，出现差分时保存首差的期望与实际帧。未运行全量 pytest 或五角色批次，改动限于实验构建和既有冒烟策略的导入方式。

接管范围为 Ironclad A0 普通战首个玩家回合的出牌和结束回合。药水、战斗内选择、复杂续体、战斗中途重根、精英和 Boss 仍需覆盖。实测涵盖完整胜利、因计划含药水而回退、非法回合拒绝和回退战败，未做预算取消、通信超时或预测差分的故障注入。进入学习实验前还需要更多原生根、失败样本、稳定标签和日志协议，以及对奖励与持久资源的更广回归。

该实验使用隐藏 RNG，数据标为 `offline-teacher`。正式在线 SL 策略需要仅用公开状态和当前房间合法试探获得的信息，并建立对应的观测、信息记录与搜索控制。
