# STS2 AI：共享卡牌机制表示与战斗—局外联合学习架构

> 讨论共识：2026-11-19（Asia/Singapore）
> 文档性质：**研究架构与分阶段实施计划**，不代表模块已经实现、模型已训练或完整跑局效果已验证。
> 研究基线：M1-N2D 完成后的 port/v0.113.1，提交 ba36decc623c6b6499e7f1b6c34a2663f0953341。M1-N2E 已在 port/v0.113.1 以 af6a1a6799e38f1f59ae014e179a6a157d46f8be 提交；本文不替代其实际代码、资格与验收报告。

本文补充 [PROJECT_VISION.md](PROJECT_VISION.md)、[research-direction-and-value-model.md](research-direction-and-value-model.md) 和 [research-nosl-policy-learning-roadmap.md](research-nosl-policy-learning-roadmap.md)。**最终目标仍是在正常 Save/Load（SL）规则、明确算力预算与未见种子下，提高完整跑局通关胜率**；共享卡牌表示是服务该目标的一种待验证架构，并不替代高性能 CombatSolver、局内合法搜索或局外规划。

## 1. 问题重构：战斗出牌和局外加牌并非独立任务

过去的 NOSL 试验主要学习当前合法动作的评分。然而一张卡牌的收益取决于它的**机制**、已有卡组、遗物、资源、敌人、战斗阶段以及后续行动：

- 战斗内：这张牌现在应否打出、对谁打、在什么顺序打？
- 战斗外：是否应加入、升级、删除或放弃这张牌，以及未来构筑要向哪个方向发展？
- 两者有共同知识：费用与能量、抽弃牌与循环、持续成长、多段攻击与力量、生成牌与增伤、护甲与触发效果等。

不宜把卡牌价值定义为固定标量 V(c)。更准确的是**条件价值**，并且组合通常非加性。设 J(D;x,\pi) 表示入场条件 x 下、固定战斗策略 \pi 对卡组 D 的某个战斗结果效用，协同可由

\[
I_\pi(a,b\mid D,x)
=
J(D+a+b;x,\pi)-J(D+a;x,\pi)-J(D+b;x,\pi)+J(D;x,\pi)
\]

作探索性描述。这里 J 对敌人和随机性做明确约定的平均；有限样本的差值不是真实因果效果的自动证明，也不是固定的卡牌评级。同种子改变卡组，可能改变开手、动作和后续 RNG 消耗。该量依赖固定的战斗策略，不能直接当成完整跑局加牌收益。

**核心共识：共享“卡牌如何发挥作用”的机制知识，不强迫战斗策略与局外选择共享一个固定的价值分数。**

## 2. 已有证据与研究假设的边界

- M1-N2B：15 维公开动作评分器经 CEM 和随机参数搜索，独立开放报告组分别胜 15/24 与 16/24，超过受测固定攻／防；没有证明 CEM 优于随机。
- M1-N2C：固定初始均值胜 32/48，两次新增 CEM 各胜 30/48、新增随机搜索胜 34/48 和 33/48；增加参数搜索预算尚无稳定泛化依据。
- M1-N2D：64 个合成根中固定均值胜 51/64，两条锁定随机策略各胜 49/64；报告子集为 26/32 与 22/32。结构检查发现公开 HP、回合、剩余能量、非斩杀目标威胁、不同弃牌候选等信息不能充分影响当前动作评分。382 个公开决策点的独立原生复放在受测字段一致；正式预测仍保留 prediction_only。
- 现有 N2A.1 的 Observation 覆盖有限的当前手牌、敌方意图、部分动态预览等，**尚不构成完备的公开卡组／弃牌／消耗牌／历史表示**。更丰富的输入需要逐项资格审计。

上述结果支持调查表示瓶颈，但**没有证明神经网络一定优于扩充特征的轻量评分器**，也没有证明共享编码器能泛化到新卡或提高完整跑局胜率。

## 3. 目标结构：三层、两头、一个长期目标

### 3.1 第一层：经过核实的卡牌机制合同

游戏规则引擎负责忠实状态转移，学习器不必重学“某张牌实际造成多少点伤害”的确定规则。模型需要理解的是规则效果在上下文中的条件价值。

- **CardSpec**：版本化静态身份、费用、类型、升级变化、有序效果、目标、条件、触发和生命周期；复杂效果允许明确的部分覆盖和未知标记。
- **CardInstance**：当前实例的升级、合法公开修改与实例身份。重复卡不能合并成不存在的单实例；实例引用不得泄漏根 ID、隐藏牌序或 RNG 指纹。
- **CardContext**：当前合法观察下的动态费用、已核验伤害／格挡／过牌预览、目标、Power、缺失掩码及其资格来源。静态机制与当前动态数值必须分离。
- **DeckSpec / Card Multiset**：完整已知卡组的多重集合，含卡数、升级、可公开修改与来源版本；对**真正无序**的卡组采用排列不变表示，但手牌合法动作仍要保留准确实例／目标绑定。
- **PublicRunContext / PublicHistory**：角色、已揭示遗物、HP、药水、金币、进度、当前可见地图、已合法观察的历史；只能在对应决策时刻使用合法可知信息。

机器学习输入应包括**数值、类别、有序效果节点、集合、可变长度掩码、未知及机制资格标记**。未知不是零；不允许为填齐输入调用内部隐藏状态。Card ID 可以保留作身份对照或残差，不是唯一语义表示。

若原生规则由程序控制流实现而没有完整声明式 API，优先从可信元数据和定向原生机制证据建立**有限覆盖、可追溯合同**，不在第一阶段发明完整通用效果解释器。

### 3.2 第二层：共享编码器与有条件的组合建模

示意形式：

\[
e_c=g_\phi(m_c),\qquad
z_D=F_\psi(\{e_c:c\in D\},\,x).
\]

m_c 是结构化机制而不只是 Card ID；x 包括合法资源、遗物和阶段。允许重复牌、升级及机制节点之间的交互。

第一版可优先比较简单聚合／Deep Sets 与小型 Attention；模型应有足够的状态条件交互，而不是假设卡牌向量相加就能表达全部协同。**Attention 的存在本身不代表学会协同**。只有在卡组组合留出、对照和反事实近似实验中取得可重复改善，才有相应证据。

为实现层级隔离，应保持：
1. 规则语义的确定字段；
2. 当前公开状态下已经核验的动态字段；
3. 由模型估计且可能错误的条件价值与不确定度。

编码器可共享，任务专用头与训练目标不必共享。

### 3.3 第三层 A：战斗策略和战斗价值

\[
Q_{\theta}^{\pi}(h,a)
\approx
\mathbb E_\pi[R_{\rm combat}\mid h,a].
\]

h 表示当前合法公开历史（若其不足以概括隐藏信息，则价值是基于历史信息状态的条件估计），a 为当前合法动作、目标及复合选择。

战斗模型使用玩家／敌人状态、手牌实例、公开卡组与共享卡牌编码器，输出**合法动作评分或概率**。可另设战斗价值或风险头，以提升长期决策而不是仅拟合即时伤害。

- NOSL 训练时一条 episode 只走一次路径；离线训练可跨独立 episode 比较参数，但在线策略不能读取隐藏 RNG 或其它试探结果。
- 后续可作为允许当前节点内 SL 的搜索器的**候选动作排序、战略生成或叶子价值评估**。正式 SL 的合法查询边界与计算预算独立约束；NOSL 单线质量不等于 SL 搜索质量。
- 首轮保留 N2C 15 维初始均值与 N2D 窄范围交互特征为强基线。学习模型必须测量推理延迟、结果质量和跨构筑损益。

### 3.4 第三层 B：局外卡组与长期跑局价值

先学习**固定战斗策略 \pi 下的条件战斗结果分布**：

\[
P_\pi(\mathrm{death},HP',\mathrm{resources}'\mid D,s,E),
\]

其中 E 是入场遭遇，s 是合法入场状态；这是对冻结 \pi 的表现建模，不是卡组“固有强度”，也不是最终通关概率。

以后具备足够的真实可达完整跑局数据及局外转移合同后，再建模：

\[
V_{\rm run}(s)=\Pr(\mathrm{clear}\mid s,\pi_{\rm combat},\pi_{\rm outside}),
\]

或相应状态／动作价值及风险分布。加牌价值要比较接受不同奖励、跳过、删牌／升级机会成本、未来遭遇与地图路线，不能只拿单一战斗 J(D) 的差代替。**跨节点不能撤回已选地图节点**，在线不得提前读取未进入节点的真实结果；当前节点内部 SL 的合法已揭示知识可进入历史。

长期目标仍需同时考虑通关、罕见死亡、HP、药水、金币、后续成长及真实节点内策略版本对转移分布的影响。

## 4. 如何训练“机制协同”，而不训练一个新卡牌排行榜

推荐先做**可检验的条件预测任务**，再将表示迁移到策略优化：

1. 在可信机制范围内构造多样的卡组、入场资源、遗物、敌人和种子；保留原始候选与排除原因，不挑胜场构造数据。
2. **冻结一个明确的战斗策略**（第一版可用 N2C 15 维初始均值）；用忠实模拟生成正常胜负、战后资源、支持范围和预算记录。根的内容摘要和游戏／Solver／策略版本必须可复现。
3. 学习条件死亡概率、胜利时战后资源等输出；区分不可正常完成的 censored/missing 和正常战败。为概率报告使用适当评分与校准、分层尾部风险，而非仅均方误差或总体准确率。
4. 在固定协议下比较简单卡组机制统计、仅 Card ID 表示、机制编码＋集合聚合、机制编码＋小型 Attention。控制模型容量、数据、训练预算与选择规则；区分“较复杂的网络”与“机制语义”的独立贡献。
5. **泛化分组按完整卡组配方、关键卡牌组合、机制族、遭遇或真实局史**；未见游戏种子只是最低要求，不等于未见卡牌组合。评估组合关系、升级变化、重复卡和机制交互。保持真实来源与合成来源分开，报告机制重叠。
6. 对卡牌组合增益的样本估计使用明确的固定策略和敌人分布，配对多个独立种子；改卡组后未必有逐步相同的 RNG 轨迹，不能把观察差异自动解释为确定的机制因果效应。

**重要偏差：** 固定战斗策略不会使用某种机制，可能导致训练数据系统性低估相应卡组。第一版需要版本化这一目标；后续可用不同冻结策略进行对比、交替训练、再评价，但不在尚未建立基线前同时变化所有模块。

训练一个可用的战斗结果预测器，不等于共享表示已学会策略；预测迁移到动作评分后必须另做 NOSL 单次 Rollout 和 SL 搜索预算公平的实验。

## 5. 推荐实施序列与范围门槛

### M1-N2E：机制语义与数据合同（已完成首版）

N2E 首版已交付静态规则与动态公开信息分离的 CardSpec、CardInstance、CardContext、DeckSpec，有限代表性机制与升级测试、实例绑定、编码接口、缺失资格矩阵、来源哈希及 N2F 训练数据方案。原生静态提取覆盖 22 张卡、44 个基础及升级版本；18 张属于本版静态描述范围，4 张显式保留复杂机制缺口。动态预览仍有 null/缺失掩码，未新增完整战斗效果的 L3 验收；6 项接口测试通过，Python jsonschema 测试因缺少依赖而跳过，另有 PowerShell schema 核验。参见 [N2E 报告](m1-n2e-shared-card-semantics.md)。**N2E 未训练神经网络，未改默认 F3B/F4，也未实现局外价值模型。**

### N2F 开始前的范围检查（N2E 结果补充）

1. 先把 Python `jsonschema` 验证作为可运行测试补齐，必要时隔离依赖环境；PowerShell 校验不代替后续每批训练数据的自动 schema 与版本检查。
2. 当前仅有 22 张受测卡和有限遭遇。优先以**固定 initial-mean 策略、少数机制、配方族隔离**进行小规模数据效率试点，避免直接声称“跨全游戏的卡牌泛化”。
3. 训练前核对冻结策略在每组机制上的正常反馈覆盖、胜负密度与明显能力偏差：完全不可获胜或几乎必胜的配方，在胜率监督上信息有限。未支持与截断不得计为死亡；还要单独报告机制部分覆盖的样本。
4. 先设计可证伪的对照：简单卡组机制统计、同容量 Card ID 与机制编码、尽量少参数的交互模型；仅当机制编码在未见组合的留出组有稳健优势，才扩展到更复杂集合／Attention 模型。新种子并不等于新组合。
5. 预算按真实独立配方族、机制关系、种子块及遭遇统计，不把同一配方多次 Rollout 当成独立构筑。每轮数据准备、标签生产、模型训练与评测分别计时；若覆盖或辨识度不足，应止步在数据资格诊断。

### M1-N2F：共享编码器与固定策略的卡组战斗表现预测

先以少量卡／机制和独立配方留出做可控试点，再按样本规模、覆盖率与性能决定扩展。首轮训练目标是条件战斗分布，不是通关率；重点测量相对简单统计／Card ID 基线的独立增益、校准、资源风险和成本。如果数据不足或机制覆盖太窄，报告负面结果，不用网络容量掩盖缺口。

### M1-N2G：利用编码器的 NOSL 战斗策略研究

比较 N2C 固定均值、N2D 条件特征、Card ID 网络和机制网络，匹配训练预算与评估根，记录失败机制、推理成本、独立新组合上的胜负和战损。可研究从结果预测迁移到动作策略是否真的有利；不预先限定必须使用 PPO、Actor-Critic 或 Transformer。

### 后续：局外价值与完整跑局闭环

在具有自然可达真实根、可信节点内战斗求解器、局外状态／转移与完整跑局评估后，将共享机制表示接入选牌、跳过、删牌、升级和路线选择。可考虑冻结／交替更新战斗头与局外头，避免共同变化掩盖收益归因。最终通过正常 SL 的独立完整跑局和算力预算评估，而不是只用单场战斗分数。

以上名称是研究规划，具体验收以各阶段实际记录为准；并不强制按瀑布顺序串行执行。

## 6. 数据合同、资格、偏差与可复现性

每个学习或评估样本至少记录：

- CardSpec / 编码 schema 版本、卡牌规则来源、部分支持/未知掩码、卡组配方与实例公开属性；
- 角色、入场公开资源、敌人、遗物、合法历史、策略可见信息边界；
- 模拟器／游戏／E3F Solver 版本、策略和模型哈希、预算、动作长度；
- 原始种子及 RNG **仅保存在离线审计侧**，不得进入在线模型特征；
- 原始建根与局史分组、synthetic / real-reachable 标签、选择数据划分；
- 正常死亡／胜利、战斗锁定资源、后奖励资源（若已实际执行）、缺失理由及预测／原生证据等级。

继续坚持 prediction_only 与独立原生 L3 的严格区分。原生抽查覆盖的有限公开字段一致不能被外推为游戏全部机制等价；针对未支持卡牌、复杂选择和已知差分保留明确标记。

不打开旧封存验证／测试；新训练／选模／报告数据要按相关配方和机制族隔离。模型选择和诊断使用过的样本不能被重新称为完全盲测。不同卡组、同一局史和同一个 RNG 输入产生相关观测，不能按 episode 数虚报独立样本量。

对未来生产部署，额外记录 **推理延迟和对高速 Combat Solver 总成本的影响**。在可接受的战斗质量之前，不能仅因为神经网络预测分数高就替换稳定的生产策略。

## 7. 判断这条路线是否值得继续

每个实验需要提出可证伪比较：

1. **语义保真：** 受测卡牌规则、升级、动态上下文和未知字段的核验是否通过？是否正确避免身份／实例泄漏？
2. **机制迁移：** 机制模型在严格留出的卡牌组合或构筑上，是否超过 Card ID 与人工统计基线，且改善能够跨多个机制族复现？
3. **条件价值：** 卡组战斗模型在固定策略下是否有合理的胜负概率校准、战后资源分布和尾部风险？结果是否对策略版本敏感？
4. **决策效果：** 迁移到战斗策略后，是否在单次 NOSL 路线、未来合法 SL 搜索中改善真实结果，而非仅改善训练标签预测？
5. **全局效果：** 接入局外后，是否在正常 SL、未见种子和规定算力下提高完整跑局表现？

若第一批机制模型无优势，应区分样本不足、规则字段不全、表示结构不合适、目标标签质量和优化失败，而非自动扩大网络或宣称共享表示无效。

## 8. 与现有项目纲领的关系
