# M1-S3B 困难开发集与首胜搜索缺陷诊断

基线 `afc982b`，分支 `port/v0.113.1`。Windows、CoreCLR 9.0.7、游戏 v0.113.1／Build 26660232。生产与诊断均显式选择 E3F 0.51.5-e3f.1，启动后验证实际加载 SHA-256 `cea50e9570edbed06c7f0502fdc5949ba3846ee64605f4891b32768b4ef3d51c`。

**冻结开发集已有 96 个不同根，全部合法原生建根，F3B C 首胜 7/96。** 代表性反例表明至少有部分失败是搜索覆盖不足。火焰屏障构筑 `f2f29fd990637955` 在 C 候选耗尽后，由完整 Solver 找到同根胜路，21 步独立原生逐帧一致。

## 冻结范围

复用 S3A 的 144 根计划、固定种子域、HP 档、难度及资源配方。只生成开发重复索引 1、2、3，共 72 根。索引 0 直接复用历史 24 条记录。生成器校验各划分的遭遇互斥，但只为开发遭遇构造 spec。未生成、读取或搜索验证及封存测试根。所有根均为第二幕 HIVE 人工构造，原生可建根及自然跑局可达性分别记录。预测证据保持 `prediction_only`。F3B C 默认算法、禁主动药水和 512 次预算保持冻结，新 72 根仅测首胜。历史少量 F4 结果不进入首胜成功率。

## 增强对照

在运行增强前冻结 [诊断名单与预算](../experiments/m1-s3b/diagnostic-plan.json)。从 S3A 开发记录取六个已候选耗尽的根，各覆盖一个模板，另取原先五个已达上限的根。每次独立冷建并对照原根摘要，保持无主动药水。

- F3B B 使用 512 次计费转移，显式替代 C 的战略路线生成。
- 完整 CombatSolver 走既有 `i1_capture`，宽度 24、1,000 节点、单线程、软限 6 秒和取消限 8 秒，显式禁药。节点上限和实际转移分别保存，成功后构造逐步帧的固定回放另计。
- 只对原先达到预算上限的五根重跑 C1024。扩大预算与更换候选方法分别计量。
- 三个预定根仅提高入场 HP 20，使用同种子、相同牌组和资源。扰动根使用独立 ID 和内容摘要，任何结果只属于改动后的状态。

三条预测均保留 Flex Potion，未主动用药。毒根的原生末步差分限于已有敌方侧窗口 `Y`／`AttackStarts`，保留双方完整帧，未授予严格胜路。其余八个诊断根仍为 `solvability_unknown`。其中两条严格胜路证明相应同根存在可执行胜路，完整 Solver 的 3/11 只是预选困难子集的结果。

火焰屏障／BOWLBUGS 根做了独立 C512 完整轨迹复测，复现 100 条尝试与 486 次转移。完整 Solver 胜路与 Q1 前四步的卡牌和目标相同，第五步使用 Bash 攻击 2 号敌人，Q1 攻击 1 号。C 的 33 条路线复用这四步前缀，零条尝试胜路的第五步组合。这是具体的目标选择覆盖缺口，证据尚不足以归因到一次换目标即可赢。原始失败路线与胜路均可按存档动作及摘要复查。[C512 失败轨迹](../experiments/m1-s3b/trace.json.gz)

三个 HP 扰动分别为 15→35、13→33、7→27。冻结 C 仍无胜路，分别达到 512 次上限、479 次后耗尽、448 次后耗尽。新根身份均不同。结果表明额外 HP 在这些扰动下未让该搜索找到胜路，原根可获胜性仍由原根证据决定。

## 生产与下一阶段

新增 72 根串行生产 **229.36 秒、0.314 条记录/秒**，包含逐根持久化和 worker 回收。4 根成功、42 根候选耗尽、26 根转移上限。68 根因缺少安全退役路线而丢弃进程；除了首次启动，还支付 **68 次**额外冷启动。69 个冷位置、3 个热位置，单 worker 最长连续两个根。额外启动与版本核验 19.75 秒，独占模型初始化 72.36 秒，合计 92.12 秒。工作集峰值约 135.7 MiB，每根墙钟 P50／P90 为 3.11／3.94 秒。会话较短，无法由本批推断长时间常驻的工作集趋势。退出、原子记录以及从连续记录位置恢复均使用 S3A 既有路径。

72 条独立记录占约 21.54 MB，原生进程日志另约 53.47 MB。按同一失败混合和串行成本，100／1,000 根约 5.3／53 分钟，记录约 30／299 MB，进程日志另约 74／743 MB。估计排除额外增强对照和大规模固定 F4，也不外推胜率。

F6B 优先验证**同一张合法卡的目标备选**。先锁定 `f2f29f…` 的前四步锚点，比较现有目标与 2 号敌人，分别使用固定动作续推和同预算的战略后缀，检验何时出现可复现收益。再用相同 512 转移在四遭遇开发组比较覆盖、预算耗尽、unsupported、严格抽查和终局 HP。为火焰屏障类构筑增加首个观察窗口内的防御反伤／集火替换，是当前两个原生见证支持的方向。毒根适合分开做持续伤害和敌方侧快照审计。

五个把 C 上限翻倍的反例都只多探索到候选耗尽，优先改善候选生成。完整 Solver 可作为开发哨兵与离线教师，单独记节点与转移成本。后续可按第一个失败窗口选用教师，并将目标替换、终局快照差分和低资源生存分开归因。
