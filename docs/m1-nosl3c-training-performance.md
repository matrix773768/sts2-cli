# M1-NOSL3C-Ib 训练吞吐与计算优化

基线为 `2d44a92` 的 NOSL3C-I。实验复用无药水、无遗物的合成根、公开观察合同、动作绑定、样本判定、模型、验证根、策略采样方式及冻结奖励 $W(1+0.12H)$。性能对照从同一初始化和相同根位置开始。较大基准只扩大单次更新的根数。正式 3C-I 的 2,048 条训练记录用于复核历史快照的单批计算，保存在原实验位置。本阶段测量运行的输出写入各自的新目录。

## 计时边界

- **训练吞吐**以合格轨迹数除以训练采集墙钟、优化墙钟和更新后的 SQLite 检查点写入之和。整次运行另计进程启动、初始选模评价、检查点导出、CPU/RSS 采样、账本统计及最终公开账本导出。训练和初始评价的尝试单独计数。
- **采集分解**以 worker 累计秒报告进程启动、根初始化、捕获、退役、重置、逐动作 RPC、公开张量化、推理和 GRU。握手包含在启动，程序集／模型数据初始化包含在建根，原生 replay／observe 包含在模拟与 RPC，GRU 包含在动作抽样与历史更新。不同 worker 的计时互相重叠。SQLite 和审计写入记录主线程墙钟，可能与其他根的模拟重叠。
- **训练分解**记录公开特征、训练前向、损失图构建、GRU、Actor 单独梯度诊断、Actor／Critic／熵联合反向和 Adam。Critic 梯度由联合反向计算。完整优化时间还覆盖归约、梯度裁剪、校验、指标和模型摘要。采集侧 P50/P95 包括同步特征、推理、选择和历史更新。
- Windows 进程资源采样每 200 ms 记录 Python 与活跃原生 worker 同时占用的工作集。CPU 以累计 CPU 秒除以墙钟，给出平均占用的逻辑核及其占全机逻辑核的比例。原生进程在握手后登记，计入其累计启动 CPU；峰值 RSS 可能漏掉极短的内存峰值。精确逐阶段计时保存在证据 JSON 中。

## 实现

1. `micro` 继续使用原标量网络，把若干完整轨迹的损失合并。每个 microbatch 进行一次 Actor 输出头梯度诊断及一次联合反向，跨 microbatch 累积梯度，最后统一裁剪并执行一次 Adam。每条轨迹的 Actor 和熵项按步求和，Critic 按步平均，然后三项分别对合格轨迹取平均。药水输出行继续通过检查。
2. `features` 合并合法菜单的重复查找。跨根缓存仅包含由公开 Card ID 与升级状态确定的静态规则张量，实例费用、目标、区域、资源和记忆仍从当前公开决策构造。静态缓存有固定容量，权重相关张量留在其所在计算图中。
3. `batched` 在每个时间步批量计算长度仍然有效的轨迹。对卡牌、手牌关系、敌人和菜单进行容量填充和掩码；非法填充位的 logit 为负无穷，熵在有效位置计算。历史 GRU 沿各自轨迹推进。批次内时间顺序、动作绑定和回报归权保留。
4. 更换 worker 数量和提前派发都在同一冻结权重的采集批内完成。提前派发把下一根提交给空闲 worker 后才写入刚完成的根。事务提交、排序读回、原生退役和所有资格检查沿用旧路径。训练更新在全部根完成后执行。跨更新预采集会要求重复旧策略或引入陈旧策略数据，本轮采用批内并行。

### 优化线程和 microbatch 的完整验证

在相同 10 worker 设置下，把优化线程由 1 调到 4、microbatch 由 16 调到 32。第三臂仍为 384/384 合格，6,056 次转移，三批优化由 8.56 降至 5.22 秒。训练墙钟 **56.47 秒，6.80 条/s**，比原始重测高约 64%。含评价、冷启动和导出共 **76.64 秒，5.01 条/s**。整程 CPU 43.62%、采样峰值 1,673 MiB，推理 P50/P95 为 26.55/43.65 ms，训练转移吞吐 107.25/s。单次 RSS 峰值有采样和工作进程生命周期方差，不能由此推断大 microbatch 更省内存。

与单线程 16 microbatch 的真实对照相比，384/384 条动作和终局、192/192 个原生根与逐步审计都匹配。三个冻结批次的可辨识参数最大差 1.26e−6，更新后价值与动作概率最大差均低于 6e−8。这个配置保留相同目标和采样。它是本次实测最高值，运行默认仍为保守的 16 microbatch 和单优化线程。

该配置采集 51.19 秒。若维持现有采集完全消除模型优化，训练吞吐上限约 7.50 条/s。维持已测优化成本时，10 和 20 条/s 分别要求采集低于约 33.2 和 14.0 秒。 [完整调参对照](../experiments/m1-nosl3c-ib/evidence/tune-summary.json) · [同批数值核验](../experiments/m1-nosl3c-ib/evidence/tuned-numeric.json)

## 数值资格与行为复核

容差和采样计划在运行参数对照前写入 [performance.json](../experiments/m1-nosl3c-ib/performance.json)。使用同一公开轨迹、起始模型和完整 Adam 状态，比对 Actor、Critic 和熵、裁剪前各参数梯度、单次更新后权重、固定公开历史的价值和合法动作概率。带计时的原始训练还与原始调用做哈希对照。跨 worker 和提前派发的比较要求更新后参数哈希、公开轨迹、终局、私有根摘要和逐步原生审计完全一致。跨训练后端的比较保留权重差和同一公开前缀上的分布差。

首轮原始逐参数检查发现 `actor.1.bias` 超过原容差。它给同一菜单中每个合法 logit 加上同一个标量，所以在精确算术下，Softmax 以及 Actor 和熵目标对它的梯度均为零。浮点归约留下的梯度残差会被 Adam 放大。验证保留原始失败、该偏置的原值差和两条训练路径的残余梯度，并对其余参数使用原容差。策略计算和 Adam 保留原实现。这个标量的变化不能单独解释策略分叉，判定采用其余梯度和参数、实际动作分布及连续真实采集轨迹。

### 离线对照

冻结更新 0、8、31 共复核 2,754 个公开状态。每臂独立反序列化模型和 Adam 动量的副本。三次带计时的标量更新哈希均匹配原函数与归档检查点。纯特征缓存和仅合并反向的模型哈希在三次在线更新逐批一致。下表为三个冻结批次上时间步批处理与原始更新的最大误差。

| Actor / Critic / 熵 | 1.35e−7 / 6.34e−8 / 4.10e−7 |
| 38 个梯度张量（相对 L2 最大 2.98e−7） | 4.48e−8 |
| 单次更新后 37 个可辨识参数张量 | 1.73e−6 |

| 更新后价值 / 动作概率 | 5.97e−8 / 1.20e−7 |
| 采样行为 logp 重放 | 4.77e−7 |

三批在线对照均重用每根独立采样种子。较大基准连续更新间的共同公开前缀上，记录的 logp 最大差 4.77e−7，价值最大差 8.95e−8。原始与批处理的模型哈希从第一批起不同，实际采样分叉 0/384。这个结果只覆盖已测更新窗口。6、8、10、12 worker 与 8 worker 提前派发相对 4 worker 批处理三次更新，模型哈希和两个原生审计摘要的匹配率均为 100%。批内调度和原生退役保持资格判定。

三个观察序列的静态特征构造中位数分别为 0.258→0.219、0.279→0.199、0.305→0.179 秒。静态缓存可覆盖重复卡牌规则，部分收益受冷根和并发方差淹没。固定 16 条 microbatch，PyTorch 1/2/4 个优化线程在三个归档批的中位数为 1.396/0.983/0.836 秒。固定一个线程，第 0 批 microbatch 4/8/16/32/64 的单次时间为 3.007/2.024/1.413/0.768/0.622 秒。扩大 microbatch 提高内核利用率并增加同时驻留的图内存。线程仅在优化窗口切换，采集维持单线程 PyTorch 设置。 [单批、线程与 microbatch 原始结果](../experiments/m1-nosl3c-ib/evidence/numeric.json)

### 强制中断与回归

优化版压力实验在第二批第 1 个根提交后强制终止进程。恢复前已提交的 15 个根封印与 2 个检查点封印逐一保持一致。最终模型、PyTorch RNG 和 Adam 状态逐张量匹配独立不中断对照。48 个训练和评价根批次的公开观察、动作概率和终局相同。新单测另覆盖不等长轨迹的归权、菜单 padding、隔离的历史与隐藏字段、过期行为哈希拒绝和 Adam 恢复副本。 全量回归 162 通过、1 跳过，跳过项为 S1 少于两条合法 A/B/A 续体。定向通过数为 Ib 4、NOSL3A 6、NOSL3B 4、NOSL3C 5、F4 6、LS2A 7（另 6 个子测试）、LS2B 5。 [恢复证据](../experiments/m1-nosl3c-ib/evidence/resume.json)

## 复现

从仓库根目录运行。游戏程序集、隔离研究宿主与 .NET 环境沿用 [NOSL3C-I 的启动说明](m1-nosl3c-training-infrastructure.md)。

```powershell
python experiments/m1-nosl3c-ib/benchmark.py logs/ib-matrix --suite matrix
python experiments/m1-nosl3c-ib/benchmark.py logs/ib-workers --suite workers --winner 8
python experiments/m1-nosl3c-ib/benchmark.py logs/ib-large --suite large --winner 10
python experiments/m1-nosl3c-ib/benchmark.py logs/ib-large --suite tune
python experiments/m1-nosl3c-ib/runner.py logs/ib-bounded --mode batched --workers 6 --through-update 3
python experiments/m1-nosl3c-ib/runner.py logs/ib-bounded-tuned --mode batched --workers 10 --threads 4 --microbatch 32 --roots-per-update 64 --through-update 3
python experiments/m1-nosl3c-ib/verify.py logs/nosl3c-formal-v2/training.sqlite logs/ib-numeric.json --step 0 8 31 --threads 1 2 4
python experiments/m1-nosl3c-ib/verify.py logs/nosl3c-formal-v2/training.sqlite logs/ib-tuned-numeric.json --step 0 8 31 --tuned
python experiments/m1-nosl3c-ib/resume.py logs/ib-resume
python -m pytest -q -rs experiments/m1-nosl3c-ib/test_performance.py
python -m pytest -q -rs tests
```

`runner.py` 将执行模式、训练线程、microbatch、并发调度以及源码指纹纳入运行身份。恢复时沿用相同配置与输出路径，可增加 `--through-update`。计时字段和私有审计均留在本机输出目录。基准汇总只保存指标、公开对照统计、版本与模型摘要。

若本地没有旧 SQLite 账本，可用原入口在新目录采集同一冻结协议的第 0 批，然后让数值验证读取该目录下的 `training.sqlite` 并传入 `--step 0`。复现第 8、31 批需有包含对应起始和更新后检查点的完整原始账本。
