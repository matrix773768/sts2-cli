# STS2 AI：总体研究方向与价值模型设计备忘录

> 讨论定稿：2026-11-17（Asia/Singapore）
>
> **性质：研究方向与建模原则，不是已验证的最优算法或产品能力声明。**
>
> 本文记录项目讨论形成的共识、待检验假设和近期工程优先级。现有代码能力与实测证据以 [PROJECT_STATUS.md](PROJECT_STATUS.md)、[M1-P0](m1-p0-performance-research.md) 和 [M1-P1](m1-p1-hot-worker-experiment.md) 为准。

## 1. 目标与评价标准

目标是在《杀戮尖塔 2》（STS2）**正常 Save/Load（SL）规则**下，使用忠实游戏机制的模拟、搜索和学习，争取达到乃至超过顶尖玩家的通关胜率；长期研究目标是 **99% 以上的跨种子通关胜率**。这不是当前实测成绩。

正式优化目标为

[
max_{pi}Pr_{pi}(	ext{最终通关}),
]

其中概率应以事先约定的游戏版本、难度、种子分布、SL 规则及计算预算为准。平均 HP、金币、战损、卡组分数只是辅助指标，不能取代通关胜率。尤其要防止平均资源收益掩盖低概率、灾难性的战败风险。

## 2. 信息边界：从一开始采用正常 SL，而非全知搜索

### 已确定的规则

1. **跨地图节点不能反悔。** 选择下一地图节点后，不允许返回上一个节点的地图选择界面，也不能先真实进入所有候选节点观察结果再选最优者。
2. **只允许当前节点内部的合法 SL。** 可以回到当前节点开始时，合法尝试该节点内的动作和选项；不允许任意回退更早的存档。
3. **游戏内部 RNG 与决策信息隔离。** 模拟引擎保留完整 RNG 保证转移忠实；正式 AI 不直接读取未合法揭示的隐藏 RNG、随机种子内部状态或未来结果。
4. **节点内部合法试探得到的知识可以并入当前信息状态。** 不必为它另建一个独立的全局规划层；但应保留影响后续决策的合法观察。

因此不再把“先训练能够看到完整 RNG 的全知求解器，再限制信息”作为正式路线。全知求解器可能专门操纵 RNG 消耗以获得未来收益，其决策标签与正常 SL 策略不一致。全知模拟只能作为离线实验、验证和理论对照工具，不能向在线 Agent 泄漏未揭示未来。

**在线与离线必须隔离：** 离线可以在许多种子上模拟反事实地图选择以研究条件转移分布；在线不能把当前存档其他未选节点的真实后果当作已知事实。离线训练也不能把某个样本隐藏 RNG 所决定的最优动作直接作为信息受限策略的无偏监督标签。

## 3. 分层决策：节点内部求解与节点间概率规划

以一次地图节点选择作为局外时间步：

- (S_t)：当前可用的局外信息状态（角色、HP、金币、卡组、升级/附魔、遗物、药水、进度、已揭示地图、仍有预测意义的合法历史等）。
- (A_t)：不可撤销的下一地图节点选择。
- (mu)：进入节点后的合法 SL 求解策略（含战斗、事件、奖励等）。
- (S_{t+1})：完成该节点后、下一次地图选择时的状态；死亡是单独的吸收终局。

把整个节点内部的行动、试探、奖励和结算抽象为宏观随机转移

[
P_mu(S_{t+1},Dmid S_t=s,A_t=a),
]

其中 (D=1) 表示节点内战败。转移分布依赖于节点内求解器 (mu) 的能力和预算。

**节点内部：** 以高速忠实模拟、强力 SL 搜索为核心。

**节点之间：** 以当前信息下的转移分布、长期价值与概率规划为核心，不能直接查询未选节点的实际未来。

需要留意：有限的可观测特征未必构成严格 Markov 状态。若某些公开历史影响后续分布，需纳入状态特征或承认当前模型是近似。

## 4. 长期价值函数和 Bellman 递推

给定后续局外策略 (pi)、节点内策略 (mu) 及约定的分布和预算，定义

[
V^{pi,mu}(s)=Pr(	ext{最终通关}mid S=s,pi,mu).
]

在足够完整的宏观状态模型下，最优性关系为

[
V^*(s)=max_{ain A(s)}mathbb E[V^*(S')mid s,a],
]

并约定胜利终局价值为 1、失败为 0。由此定义

[
Q(s,a)=mathbb E[V(S')mid s,a],qquad V(s)=max_a Q(s,a)
]

（第二式用于相应的最优价值定义）。

**期望与最大化的顺序不可交换：**

[
max_amathbb E[V(S'_a)mid s]
quad	ext{而不是}quad
mathbb E[max_a V(S'_a)mid s].
]

前者在未知具体结果时作地图决定；后者偷偷允许看完各候选节点实际结果再选，不符合正常 SL。

准确的通关概率目标本身已体现死亡风险；不能用期望 HP、金币或任意线性资源评分取代它，也不能把资源奖励与已包含资源价值的后继 (V) 重复计算。

## 5. 学习节点结果的分布，重视极端风险

仅预测平均战损不足以支持 99% 以上胜率目标。研究对象应为**节点内死亡与存活后状态的联合分布**，而不假定各类资源变化相互独立：

[
P_mu(D,S'mid s,a).
]

分解为

[
p_{mathrm{fail}}(s,a)=Pr_mu(D=1mid s,a),qquad
P_mu(S'mid s,a,D=0).
]

则

[
oxed{Q(s,a)=
(1-p_{mathrm{fail}}(s,a)),
mathbb E[V(S')mid s,a,D=0].}
]

这比“期望战损最小”更贴近最终目标。例如，1% 节点死亡概率即使换来很高的条件收益，仍可能显著损害整局胜率；但也不能武断拒绝任何风险，因为回避风险可能导致后续必败。

初步输出设计：

- 节点内死亡概率；
- 存活后 HP/金币、卡组、遗物、药水等结果的分布（从简单的边际/分位数和关键相关性逐渐扩展）；
- 后继状态的长期价值、进而得到动作价值；
- 与预测可信度相关的辅助信息。

CVaR、动态风险约束、价值下界等作为**待验证的辅助工具**，不默认替代最终通关概率目标。风险容忍度应考虑构筑强度和剩余流程，而非所有节点采用相同固定阈值。

## 6. 区分随机性与认知不确定性

- **Aleatoric（游戏随机性）：** 即使机制与概率分布已知，未揭示结果仍有随机性；靠建模条件分布处理。
- **Epistemic（模型不确定性）：** 数据稀少、陌生卡组组合、模型失配等造成概率估计不可靠；靠补充数据、独立校准、保守界和针对性测试处理。

预测 (p_{mathrm{fail}}=0.1%) 不代表已证明风险小于 0.1%。极低概率需要大量数据或额外可证明的机制约束；模型集成预测分歧不能直接当作有覆盖保证的置信区间。

后续研究低风险区间的概率校准、可靠区间、罕见失败案例的定向生成与必要时的重要性采样。定向样本的事件频率不能当作真实种子分布中的自然概率；采用独立种子/跑局分组训练与测试，避免同 RNG 轨迹的相关分支泄漏。

## 7. 价值模型与训练路线：先获得可靠信号

### 状态表示

输入应覆盖局外资源、可知地图与进度、卡组实例特征、升级/附魔、遗物及动态状态、药水、角色和候选动作。学习型嵌入配合非线性组合可表征卡牌—卡牌、卡牌—遗物协同，不能假设固定可加分数已足够。

初期优先比较结构化线性/树模型、卡牌集合编码加小 MLP 等轻量基线；不预设 Transformer 或 NNUE 就是最佳架构。网络推理开销应与原生模拟和搜索吞吐量一起评价。

### 学习目标与阶段

在高质量通关数据不足时，不宜仅以当前弱策略的大量失败终局训练 (V)。先使用密集且可验证的中间目标，例如

[
Pr(	ext{节点内死亡}mid s,a),quad
P(Delta HP,Delta Gold,ldotsmid s,a,D=0),
]

再逐步引入当前幕通过率、后续多节点生存和最终通关价值。阶段通过率是**辅助预测目标**，不能让策略只为短期生存牺牲长期构筑。

长期可比较直接学习 (Q_	heta(s,a))、学习 (V_	heta(s)) 配合转移采样、以及局部转移模型配合 Bellman 递推三条路线；倾向先建立可靠的短期风险与状态表示，再利用高质量终局数据/自举发展长期价值。Bellman 自举可能传播偏差，不能只用弱启发式自我蒸馏证明进步。

### 数据记录合同

每条样本至少保留：公开输入特征及合法信息边界、候选动作、所选节点类别、实际执行节点内策略版本、CombatSolver 版本及搜索预算、原生游戏版本、原始种子/跑局分组标识（仅用于离线实验分组，不输入正式策略）、终局/节点结果、资源与构筑变化、可靠性/unsupported 标记、耗时和必要的状态一致性证据。

同一可见状态可以汇集不同 RNG 种子下的分布样本，但具体隐藏 RNG 不能作为在线 (V,Q) 的输入。节点内求解器变化意味着标签所代表的 (P_mu) 也可能变化，需要版本化与重新校准。

## 8. 高性能 CombatSolver 是基础设施，而非事后附加模块

由

[
P_{mu_1}(S'mid s,a)
eq P_{mu_2}(S'mid s,a)
]

可知，弱求解器产生的战损/死亡数据不能直接代表强求解器下的转移分布。大规模价值学习首先需要**足够忠实、足够强且预算明确的局部求解器**。

必须区分两类性能：

1. **模拟效率：** 单次动作转移、Fork/Clone、有效节点吞吐、内存分配及峰值；
2. **求解质量：** 固定预算下的真实战损、成功找到合法完整胜利路线的能力、极端困难战斗表现、预算增加时的边际质量收益。

单纯每秒节点数提高不保证策略更好。未来探索高预算 CombatSolver 作为 Teacher，提取搜索路线、价值/排序监督，再训练轻量 Student 指导或加速搜索；需用实际结果验证，不能把搜索器内部启发式分数直接当成真实通关价值。

正式战斗搜索必须符合**当前已进入节点**的合法 SL 信息边界。模拟引擎内可以保留 RNG 以还原游戏，但不能将未合法获取的信息提供给策略。

## 9. 搜索引擎总体架构：暂不提前锁定算法

参考 Stockfish 的搜索组织理念：状态评价、着法排序、迭代加深、选择性展开、置换表和高速状态转移协同。STS2 不是国际象棋式双人零和 Minimax 问题，不照搬 Alpha-Beta 的适用前提。

暂定模块化架构：

- 节点内部：CombatSolver / 高速搜索，处理合法 SL、决策续体和战斗；
- 局外：学习型 (P_mu,V,Q) 与风险敏感概率规划；
- 搜索预算：根据估值、风险及模型不确定性分配；
- 缓存：**精确**状态键用于可证明等价的模拟结果；**抽象**可见特征用于共享价值统计，不能以相同 HP、金币、卡组等直接共享某个 RNG 下的实际转移。

Beam Search、Best-first Search、MCTS/PUCT 或混合搜索均保留为候选；最终用相同 SL 规则、相同预算、相同节点内求解器及未见种子的真实通关表现决定。

## 10. 当前已实现能力与性能证据

- M1-B1：以原生地图检查点为根的独立分支与动作前缀重放；
- M1-B2：有界并行与基准；并发 4 时约 1.935 个受测分支/秒（特定 26 步脚本，不能泛化）；
- M1-C：单步地图前瞻，当前按具体保存 RNG 模拟多个候选节点。**保留作为离线实验/差分工具，不得直接作为正常 SL 在线地图策略。**
- M1-C2：从事件位置独立重放比较选项，为**允许当前节点内 SL**的事件决策提供原型；
- [M1-P0](m1-p0-performance-research.md)：原生模拟与 CombatSolver 架构调查；
- [M1-P1](m1-p1-hot-worker-experiment.md)：**隔离实验**在两条固定 26 步战斗脚本上，热恢复 P50 约 21.6 ms、热批量推进 P50 约 108.4 ms、两段合计约 130.6 ms。两轮 A→B→A 与冷进程逐步、RNG 及存档差分通过，并发现修正过一次 profile 污染。这并非全游戏通用 worker 已验收，也没有证明完整节点 10 ms 可行。

CombatSolver 尚未集成到本项目。当前 M1-P1 仅在隔离探针里验证热恢复和批处理，尚未取代生产分支调度器。

## 11. 工程优先级与开放问题

**近期主要工作：提升 CombatSolver 的模拟效率、求解质量及可用作训练数据生成的接口。** 同时使用 M1-P1 的实验证据指导原生模拟器后续降本；暂缓 M1-C 的局外算法扩展，直到价值模型与信息边界得到更清楚的实现设计。

后续依次推进：

1. 建立版本化、可复现、同预算的 CombatSolver 性能与路线质量基准；
2. 研究快速固定脚本/战斗状态 API、战斗语义差分及训练数据采集；
3. 训练初版节点内死亡风险和存活后结果分布模型；
4. 利用长期跑局数据/阶段目标发展 (V,Q)，在正常 SL 信息约束下构建局外规划器；
5. 通过独立跨种子验证形成“战斗搜索—数据—价值学习—策略改进”闭环。

仍需研究：合法 SL 查询成本/次数的具体预算；抽象状态保留哪些历史；如何校准低于 1% 的风险；何时使用价值下界/CVaR；CombatSolver 精确覆盖及兼容性；不同版本求解器标签如何复用；哪类全局搜索在同计算预算下真正有效。

## 结语

> **在正常 SL 信息约束下，以高速而忠实的节点内战斗模拟与求解为基础，学习节点结果分布、罕见死亡风险和长期通关价值，再用风险敏感的局外概率规划最大化跨种子通关胜率。**

这是项目目前的研究主线，不是未经验证的性能、胜率或算法保证。
