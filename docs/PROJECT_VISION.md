>
> 适用于本项目的正常 Save/Load（SL）研究路线。具体实现、版本、当前进展、已验证的性能与剩余缺陷见 [PROJECT_STATUS.md](PROJECT_STATUS.md)；局外价值建模与合法信息边界的推导见 [research-direction-and-value-model.md](research-direction-and-value-model.md)。

## 1. 一句话主线

**以原生忠实模拟为基础，研发能以远低于强战斗求解器的成本达到或超过顶尖人类玩家战斗水平的“极速 Combat Solver”；用它批量生成真实、可复现的节点结果分布，再学习局外长期通关价值并规划整局行动。**

项目的最终优化目标是：**在约定的游戏版本、难度、正常 SL 规则及资源预算下，提高并争取超越顶尖人类玩家的跨种子通关胜率。** 99% 以上是长期研究愿景，不是本项目已验证的通关成绩或保证。

像国际象棋引擎的发展一样，阶段性追求“足够强且足够快”，不等于放弃以后追求最优；不同阶段不应使用同一精度门槛阻碍进展。

## 2. 已确认的研究取舍

1. **初期参考系是顶尖人类玩家，而非理论最优。** 一条在战损、存活、药水消耗及后续资源影响上达到或略优于顶尖人类实战水平的合法路线，可以是合格输出，即使强 Solver 还能找到更优路线。
2. **接受相对最优解的系统性战损偏差。** 极致速度通常需要放弃一部分最优性。初期不要求极速 Solver 对强 Solver 的最优战损近乎无偏，也不把两者战损一致作为上线的必要条件。
3. **极速 Solver 可以在初期全面承担局外评估。** 在满足独立的实战能力、可靠性及吞吐门槛后，可使用极速 Solver 批量生成战损、死亡和资源变化数据；不必把高预算强 Solver 作为每个样本的必经教师或校准器。强 Solver 可保留为研究对照或困难案例诊断，但不是初期生产流水线的强制依赖。
4. **不因此忽视模型偏差。** 测量并记录极速策略版本造成的偏差和失败模式，尤其要防止偏差集中于成长型卡组、特定敌人或极端风险场景。可接受偏差的标准应是**对目标玩法的绝对能力**，而不是无需检测偏差。
5. **战斗能力接近人类是整局超越人类的重要基础，但不是充分证明。** 局外决策、样本分布、罕见失败、SL 使用规则和算力约束也影响整局胜率；最终仍需独立的完整跑局验证。
6. **在证据不足时允许先落地可用的阶段性算法。** 不为追求最优解而无限推迟局外学习；生产用的完整预测胜路无需逐条取得 L3，但必须区分预测结果与原生严格验证结果，不得用合成样本上的高成功率或单一平均战损代替实战能力评测。
7. **初期默认信任固定版本的 CombatSolver 预测后端。** F3B/F4 复用原 CombatSolver 的战斗规则预测而非重新实现规则。考虑其既有玩家实战使用经验，初期大规模局外评估允许直接消费其支持机制内的预测结果，无须为每个样本重复固定帧冷重建及独立原生逐帧验收。此为主动的工程信任选择，不是对所有游戏版本、规则和终局状态的严格等价证明。

## 3. 极速 Combat Solver 的提出背景

[Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver) 已有高质量战斗搜索和大量工程优化，包括状态复用、Beam/Pareto/多样性保留及面向特定机制的路线搜索。继续从常规启发式或 Beam 微调中获取数量级加速，并非我们优先押注的方向。

**强 Solver 的优势是对单场战斗投入较多计算，寻找很高质量甚至近最优的路线；极速 Solver 的优势应是用显著更少的计算，稳定产生足以支持大规模局外学习的高水平路线。** 二者解决的资源配置问题不同。

提出过的**100 倍以上加速**是研发目标；毫秒至数十毫秒级的战斗求解是探索性的性能愿景，均不是已实证的跨场景结果。真正的倍率须在相同硬件、战斗根、SL 规则、原生验收边界和端到端计量范围下测量，明确区分热搜索、初始化、原生推进及验证费用。

顶尖人类玩家常凭少量有目的的 SL 尝试找到高水平路线，是我们采用战略驱动搜索的直觉来源；“一般少于 10 次、困难战斗不超过 1000 次”等是待系统核实的经验观察，**不能直接等同于机器 Replay 次数或复杂度证明**。一次人类尝试可能包含大量隐式推演。

> **2026-11-19 架构升级：** 已确认的长期主线是 [机制感知、端口驱动的 NOSL–SL 双层决策架构](research-port-aware-nosl-sl-architecture.md)。共享卡牌机制与条件组合关系提供知识，输出／防御／运转提供可解释归纳偏置；NOSL 直接策略基于合法公开历史对合法实例动作评分，不需要在线显式树搜索；正常 SL 使用该策略作为基础，增加当前节点合法试探、路线修复和战后资源优化。**旧四战略和 LS2B StrategySpec 都是可复用的基线/解释/数据生成工具，不是最终 NOSL 模型的必经输出空间。**
>
> 下述 F3B/F4 两阶段描述保留**既有战略搜索实现及其有效工程思想**，不应解读为每一次 NOSL 出牌都必须先生成完整战略计划。两阶段“先找到合格完整胜路，再改善资源”主要约束 SL 搜索，NOSL 单次轨迹直接由策略逐步产生。详细的信息边界、策略与价值函数、端口辅助、训练和消融均以新架构文档为准。



### 阶段一：先构造一条合格的完整胜路

核心不是单纯“在所有可达状态中挑当前评分最高者”，而是**根据卡组的获胜机制形成战略假设，再构造、检查和修复完整路线**。状态评分或局部搜索仍可作辅助，但不应压倒完整战略。

初期使用预设战略而非立即训练战略模型：

- **攻杀（AGGRO）：** 尽快形成足够的有效伤害、击杀关键敌人，同时避免无谓的致死风险。
- **防杀（DEFENSIVE）：** 优先覆盖真实来袭和生存约束，再在安全窗口推进击杀。
- **成长（ENGINE）：** 识别关键能力、力量/活力与多段攻击、抽牌/能量循环等获胜机制，允许短期收益较差但能改善后续战局的动作。
- **基线策略（如 Q1）：** 作为比较对象和可回退的候选路线来源，而非上述战略的替代物。

战略应表达**阶段目标、优先级、可接受的风险和切换条件**，而不是固定出牌脚本。例如依赖关键能力的构筑，应尽早寻找可存活地打出该能力的机会；依赖力量和多段攻击的构筑，可先建立增益，再为爆发窗口保留必要资源。

初始战略生成完整候选路线后，使用高速模拟判定是否取得合法胜利。若失败，诊断**可观察到的失败位置和可修改条件**：致死回合的防御缺口、关键牌不合适的抽取时机、伤害不足、资源分配、敌人阶段要求等。随后修改前缀动作、锚点、同回合局部序列或整个战略，再次完整重放；不能把诊断启发式当成严格死因证明。

**正常 SL 并不允许直接任意重排牌堆。** 如果想让关键防牌在攻击回合上手，或让增益牌先于多段攻击上手，只能通过游戏合法的选择及可验证的 RNG 演化改变后续结果。战略引导的是合法干预搜索，不是对隐藏未来的任意编辑。

### 阶段二：围绕已获得的合格预测胜路降低战损

一旦得到满足阶段一门槛的胜路，不必从头开始另一次全局搜索。保留现有路线，寻找成本低的局部改进，例如：

- 斩杀回合存在溢出伤害时，尝试将较早的部分攻击资源改为防御；
- 改变防御与输出时序、目标和过牌时机，而不破坏关键斩杀条件；
- 比较药水保留、使用与替代路线的后续资源价值；
- 复用可靠前缀，只对被修改的尾段或短窗口进行重算和严格核对。

阶段二的候选应在同一预测后端中重新执行并满足既定的合法性与资源质量门槛，不得牺牲已有合格胜路；原生严格验收可用于研发差分、已知异常与抽查，不是生产阶段逐条强制步骤。其停止条件受明确的预算和边际收益控制。**先有合格胜路，再改善战损**是算法结构，并不是“只要能赢，无论损失多少就合格”。

长期优先训练机制感知的 NOSL 直接策略及可选价值、端口辅助头，SL 再使用该策略引导修复和质量优化。结构化战略生成、风险约束和可解释编辑仍可作为辅助方法；已有 LS2B 在研究侧实现它们的初步组合与搜索反馈，但尚无整体胜率/成本优势，也未完成正常 SL 在线资格。

## 5. 为什么这条路线服务于局外学习

局外评估需要的是：给定卡组、角色、敌人、入场 HP、遗物、药水、可观测历史等条件，在真实游戏随机性和允许的 SL 预算下，**节点内死亡与战后资源状态的联合分布**，而不只是单场最优战损或平均 HP。

以节点内策略 \(\mu\) 表示极速 Solver，真正用于学习的分布是

\[
P_\mu(D,S' \mid S=s,A=a),
\]

其中 \(D\) 为节点死亡事件，\(S'\) 包括存活后的 HP、药水、金币、卡组等后继信息。不同求解器或预算会改变 \(\mu\)，进而改变数据分布；必须版本化求解器、预算和游戏规则。

样本量增加能降低抽样误差，却不能消除策略偏差。**我们接受对强 Solver 最优战损的偏差作为阶段性设计选择，绝不把偏差不存在当成事实。** 初期的质量门槛来自与人类基准、真实原生结果及跨构筑/遭遇表现的比较，而不是“同强 Solver 数值接近”。

局外学习的最终目标仍为通关概率，而不是无条件压低每场战损。药水、成长收益、资源分配和罕见死亡风险会影响长期价值；需要记录联合结果，不能只记录胜率或平均掉血。

## 6. 信息边界与验证红线

- **正式玩法采用正常 SL：** 跨地图节点选择不能反悔；只允许当前节点内部的合法 SL，不能提前读取未选择地图节点的真实结局。
- **隐藏 RNG 只用于忠实模拟与离线审计。** 正式在线策略不直接读取未合法揭示的种子、RNG 状态或未来。离线全知结果不得混作正常 SL 的在线能力。
- **原生规则是最终事实依据，可信预测可直接用于初期生产。** 固定 CombatSolver 版本、明确支持范围及完整合法预测胜路可直接生成局外评估数据，无需逐条独立原生验证；但只有实际经过独立原生逐帧核对的结果才可标为 L3。预测标签与 L3 不可混同。对于已知预测/原生差分、选择事务不支持或版本漂移，保留差分与不支持标记，针对性调查。
- **合成根的可重建性不等于真实跑局可达性。** 数据需标注来源及信息边界；真实跑局可达的独立根是长期泛化评测所必需。
- **不能以搜索超时证明无胜路。** 将未找到胜路、证明无法胜利、模拟器不支持、原生验证失败和资源限制分类记录。

### 预测可信度的生产合同（2026-11-19 决策）

1. **生产默认：** 使用同版本 CombatSolver 的预测根和 Replay 执行极速战略，直接输出预测胜负、战损与资源状态；不对每条结果运行独立原生冷重建。搜索是否有最优性保证与预测器规则是否正确是两个不同问题。
2. **证据分级：** 记录预测器版本、游戏版本、根来源、支持范围、搜索策略与预算、预测是否完整、结果是否曾严格原生审计；未原生逐条通过的标签不能追认成 L3。此前所有 L3 记录及严格门槛不追溯修改。
3. **针对性风险处理：** 已观察到的猎杀者（`PREDATOR`）击杀终局 `DRAW_CARDS_NEXT_TURN_POWER`/continuation `P` 差分，以及敌方侧回合终局 `Y`/`AttackStarts` 差分，先判断是无实质影响的终局快照生命周期差异，还是真正影响战损、RNG 或后续资源的预测错误。结果未明前不得简单宣称这些机制下的预测完全等价；受影响样本标记为 `known_mismatch`，对可能改变训练标签者暂缓生产使用或走专门复核。
4. **不建立逐样本强制审计门槛：** 版本变化、支持范围扩展、可疑结果、特殊机制或独立抽样研究可以触发原生差分。默认流水线仍以高速预测为主；原生检查的目的在于界定可信范围、定位异常，而不是要求每条数据重新证明一次。

## 7. 如何判断研究是否真正前进

应当区分四类指标：

1. **绝对战斗水平：** 与独立、可复现的顶尖人类基准相比，在同一正常 SL 规则及入场条件下的存活、战损、药水/其他资源代价；明确人类基准的样本与测量局限。
2. **高吞吐能力：** 每秒完整合格战斗、端到端耗时和内存，而非单纯每秒预测转移数；与强 Solver 比较相同质量门槛下的成本。100 倍只是目标。
3. **局外分布质量：** 分构筑、敌人、幕数、难度的死亡/战损分布与尾部风险；不能仅凭平均 HP 改善宣称总体更优。
4. **最终整局效果：** 未见种子、固定游戏版本与预算下的通关胜率，兼顾少数灾难性失败和统计不确定性。

保留开发/验证/测试隔离，尤其避免反复依据测试根调参。同一局史产生的根并非独立观测。测试集不能因为算法已经在开发集达到 100% L3 就提前打开。

## 8. 已有证据与仍需验证的假设

截至 2026-11-19 的已有工程证据：

- **M1-F3B：** 三种预设战略及路线修改已形成可运行原型；在少量共享局史的 BOWLBUGS 开发根上，允许用药的战略组以 24–39 次预测转移找到严格胜路，明显少于同批 Beam 对照。但这不证明普遍达到 100 倍端到端提速；诊断模块对胜场的独立增益尚不明确。
- **M1-F4：** 在首条严格胜路后执行局部路线改进，已在个别固定根与后续跨根实验中改善 HP，但额外耗时显著。
- **M1-S2B/S2C：** 256 个合成根具有两次独立冷重建证据；其中冻结的 32 个开发根和 16 个验证根上，F3B 与 F4 均为 48/48 L3。S2C 仅覆盖六类遭遇，不能推断复杂实战分布，也尚未形成可信的人类基准或通用 100 倍速度证明。

因而待研究的问题不是“能否再给 Beam 加一种优先级”，而是：战略如何表示为可执行的阶段目标；如何使 SL 干预有目的；何时需要改战略而非局部修复；怎样在不同真实构筑和遭遇上同时满足**人类级质量**与**大幅降本**；如何在局外学习中识别和缓解极端风险。

## 9. 研发优先级与文档职责

**优先顺序：** 固定预测后端及正常 SL 合法性 → 可用的极速战斗策略 → **学习指导的搜索—经验—再学习闭环，与独立战斗质量／成本评价并行推进** → 以可信预测结果开展大规模局外分布学习 → 长期价值与整局搜索 → 逐步提高战斗与全局决策的最优性。原生差分保留为规则风险调查工具，不是逐条生产门槛。

这不是严格的瀑布流程：质量测试、模拟性能、失败诊断和数据生成可以交替迭代。但**不得以逼近强 Solver 的最优战损作为启动局外学习的前置条件**。

**2026-11-19 学习路线更新（在 LS2B 之后）：** N2E 的共享机制语义保留。LS1 完成学习排序接入；LS2A 完成千根规模化采样；LS2B 完成可组合 StrategySpec、阶段切换、失败编辑及可执行路线验证，但在独立 40 根上总体胜路数与冻结基线持平，且墙钟更高。它们是工程基础，**不是必须永久采用战略四分类或 StrategySpec 的证据**。最新长期研究路径转为“机制/条件组合知识 → 可选时序端口辅助 → NOSL 直接合法动作策略（可配价值头）→ SL 合法搜索增强与训练反馈 → 局外长期价值”。允许在训练阶段使用模拟和研究侧搜索，但不得用隐藏 RNG 或全知搜索最佳动作冒充正常 NOSL 的监督真值；正式在线 SL 仍只允许当前节点实际合法试探已揭示的信息。详见 [新架构共识](research-port-aware-nosl-sl-architecture.md)；原 [M1-LS 工程主线](research-learning-guided-combat-search.md) 保留阶段交付与后续实现建议。
