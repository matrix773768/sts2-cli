# M1-E2 终局语义对齐与原生验证的预测分叉

**三个 E1 固定路线中，原始严格终局等价仍为 0/3，生命周期对齐和完整终局语义验收均为 2/3。** 两条死亡路线通过。Prisms 胜利的污染清理差异仍保留失败。Boss 的原生替代结束回合复现了预测的死亡，另一个合法替代动作通过了活动态原生严格差分。

## 版本、路径与证据

STS2 v0.113.1 / Build 26660232，CoreCLR 9.0.7，CombatSolver 0.51.5 / `78e4545e825e58c3d999354b1ffcd54241b1d2cf`。使用与 E1 相同 SHA-256 的基线 DLL、原生夹具、Q3 燃烧契约合同、可选节段显示绕过，及直接逐动作调用的内部 `Replay`。E2 构建仅向隔离宿主加入只读观察与比较适配。没有修改 Steam 文件、预测规则、求解器或正式宿主。每根 35 s 进程超时、64 动作与 256 MiB .NET GC 堆上限。峰值工作集为 171–178 MiB；该堆上限不约束原生内存。

两组独立进程矩阵各运行五条固定路线。原始三路线的根戳和 live 戳与 E1 的历史来源一致，动作、逐步原生前后戳、原生选择和终局均通过已有见证检查。D/E 从相同 Boss 根重新执行前 18 步。新观察包括末动作前、原生胜负入口、`CombatEnded` 事件和动作队列返回。预测边界由 `TerminalStamp` 标记。入口捕获记录胜负已决定而 `IsInProgress` 仍为真的状态；原生事件和队列结束时该值为假。没有通过额外游戏动作触发清理。

## 三个首差的原因

| E1 路线 | 活动态严格一致 | 原始终局严格 | 生命周期对齐 | 终局语义 |
| --- | ---: | --- | --- | --- |
| A · Defect Infested Prisms | 18/18 | 失败 | 失败 | 失败 |
| B · Ironclad Decimillipede | 19/19 | 失败 | 通过 | 通过 |
| C · Defect The Insatiable | 42/42 | 失败 | 通过 | 通过 |

- **A，最终击杀与污染。** 第 19 步打击将最后一敌 HP 从 2 降到 0，玩家保持 64/75 HP。预测侧 `SimulatedCombatState.NormalizePowerAfflictions` 在有效 `VitalSparkPower` 不存在时清除污染。原生在同一步进入 `VitalSparkPower.AfterRemoved`，但 `EndCombatInternal` 入口的 13 张受污染战斗实例仍带 `TAINTED:6`。观察器持有这些实例的引用，`CombatEnded` 与队列返回时 13 张仍带污染。原生活动牌区、能力、历史已经清理，永久牌组等资源无变化。差异来自预测的清理假设与原生实际生命周期不同；没有观测到原生可与预测带牌区快照等同的阶段。具体哪个原生回调分支使这些实例保持污染仍待定位。HP、敌人全灭和 RNG 一致只作为局部证据。
- **B，敌方回合死亡。** 第 4 回合结束回合后，节段重接使对应敌人 HP 从 0 到 25，玩家从 5 到 0。原生 `ProcessPendingLoss` 时本场历史仍从 143 增至 147 条，出牌开始和抽牌总数保持 16、26。玩家侧窗口的 `Y=0/3/6/6;…;AttackStarts=4` 在敌方侧窗口显示为零。预测保留最后玩家侧窗口。
- **C，敌方回合死亡。** 第 10 回合结束回合后，玩家 HP 6→0，Boss HP 191→185。历史 267→274 条，出牌开始和抽牌总数保持 33、56，原生玩家侧窗口原为 `Y=1/0/3/2;…;AttackStarts=1`。同 B，入口、事件和队列返回时历史都存在。源码 `AppendLiveTurnCardHistory` 通过 `HappenedThisTurn` 过滤原生记录，预测用玩家侧计数器；这里差异是窗口切换。

### 终局验收合同

活动态继续使用 E1 严格逐字段比较。死亡终局仅当实际进入 `ProcessPendingLoss`、同回合从玩家切为敌方、无新出牌开始或抽牌、窗口显示为零、跨窗的 `FlameHp` 不变时，才把原生死亡入口摘要里的窗口计数映射为该动作前实际观测到的玩家侧计数。映射后必须整份快照严格相等。原始终局字段和值单独保留。若实际死亡发生在别的阶段或发生了新抽牌、出牌，这项适配不会放行。

死亡路线另须满足：原生正常发出事件、动作队列返回且战斗已关闭，三个阶段的完整原生摘要相同；预测终局类型和回合与原生一致，HP、各敌 HP、RNG 一致，最大 HP、金币、永久牌组、遗物和药水与根观察一致。最终动作的个别触发器通过其结果和实际生命周期观测核对，没有采集通用的逐触发器事件流。胜利路径保留原始失败，尚未建立覆盖清理与原生奖励结算的通用胜利合同。

## 原生反事实

Boss 第 18 步后的父状态已通过严格原生逐字段差分。每项实验执行实际预测 A→B→A，A 是 `FRANTIC_ESCAPE`，两个 A 摘要相同，B 摘要与 A 不同，父状态摘要前后相同，三个子状态都无预测风险或边界标记。

| 原生替代 | 合法且跨进程复现 | 动作后比较 | 终局 |
| --- | --- | --- | --- |
| D · 结束回合 | 是 | 原始唯一首差为窗口中状态牌抽取计数 1 对 0。使用相同死亡窗口合同后全部字段和 RNG 一致 | 第 5 回合玩家 HP 65→0，Boss 260→254；语义通过 |
| E · `MOMENTUM_STRIKE`，手牌索引 3，目标 1 | 是 | 活动态严格一致，包括 RNG。玩家保持 65 HP，Boss 260→245 | 固定短路径在动作完成后停止，仍处于战斗中 |

D 的原生合法性和死亡均来自实际替代动作，不以预测 A→B→A 代替原生重放。E 用于独立覆盖“替代后仍处于活动态”的严格差分；未向后追加冻结策略。

## 下一步与复现

可在已对齐的稳定活动态，用 2–8 条短预测分支开展小规模定向搜索，入选路线仍由独立原生进程复验。Prisms 的胜利污染边界、其他选择合同、挂起的异步续体、药水和永久资源变更、奖励及切房仍应停在明确不支持的边界或交给原生引擎。所有隐藏 RNG、内部状态和已知脚本仅构成离线 Oracle 证据。计时测量执行给定动作的成本；未来在线策略必须使用公开状态和实际合法试探获取的信息。

从与仓库同级工作区运行，复用 CS1/Q3 构建输入，使用新输出路径。

```powershell
& sts2-cli/experiments/m1-e1/build.ps1 -Repair -TerminalParity
python sts2-cli/experiments/m1-e2/replay.py CombatSolver-m1-e2/repro-1
python sts2-cli/experiments/m1-e2/replay.py CombatSolver-m1-e2/repro-2
python sts2-cli/experiments/m1-e2/summarize.py CombatSolver-m1-e2/repro-1 CombatSolver-m1-e2/repro-2 CombatSolver-m1-e2/repro-results.json
```

隔离 Release 构建 0 警告、0 错误，两轮五路线均执行完毕，定向断言核对了胜负阶段、原始差异、生命周期映射、根身份及分叉确定性。全量 pytest 和五角色完整跑局未运行；正式模拟与默认策略无改动。原始逐阶段快照由脚本保存于隔离目录，提交的是 [派生数据](../experiments/m1-e2/results.json)。
