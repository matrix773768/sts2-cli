# M1-CORE-1 · 完整回合战术图与公平随机边界

2026-11-26，架构基线 v1.0，STS2 v0.113.1 / 26660232。研究起点为 `794d06b46e6a47d682d4a1bb3e956308eef21b97`。本地 Git 拉取遇到 TLS 证书链错误，通过 GitHub 的分支提交接口核对远端头，与干净的本地 HEAD 相同。

**工程验收为有限支持。** 在 24 个预先冻结的开发构筑族、18 种遭遇、13–24 张牌上，22 根实际执行到下一回合首个公开战斗菜单，其中 21 根在新菜单重新搜索并再次到达 B。46 次查询中 43 次完成执行。小夹具可精确枚举普通抽牌和洗牌；正常厚度使用独立条件世界上的有限策略图。两者都保存了联合后继、概率语义、选择规则及动作见证。

**研究证据支持在正常构筑上生成 B 后继，尚不足以认证教师。** 主面板的 43 个实际 B 都未逐字段命中所选策略的有限样本叶，188 个执行动作中有 37 个依赖未见菜单的冻结 G2 续策。真实抽牌的组合空间远大于三个世界。低命中率与能够执行到 B 可以同时出现；采样价值误差及能力收益仍待独立世界检验。

## 调查与实现选择

SV1 的 K0 保留完整动作来源，K1 仅在经对照的纯基础牌场景规约槽位。SV4A 已能输出公开合法前缀、A 提交边、随机停车和提前终局，其确定性树能最大限度利用现有宿主覆盖。原 N2A 的结构哈希适于找循环线索，完整见证能重放具体实例、目标、费用和逐事件输入。HotKernel 的固定世界 Step 很快，但单独推进一个已知世界会暴露未来。HotDraw 已能在真正读未知抽牌之前停住，复制父状态并用带地址的转录恢复；其资格表限定遭遇、牌、遗物、Power 和剩余随机源。因此保留两种互补实现并复用同一个策略编译入口。

* **精确图**使用常驻热根。节点为稳定决策、真实待选、C、结算、B、引擎终局或带原因的未解决叶。EndTurn 经真正敌方行动和下一轮 setup，只有回合号加一、玩家方、无在途出牌且 EndTurn 已合法才接受 B。击杀和死亡优先。抽牌前缀只从同一个动作前快照重试；每个完成转移另用 N2A 的实例动作和完整事件记录严格复放。选项使用合法已知顶底和未知多重集的不放回概率，仅合并 HotDraw 在已资格化范围内判断相等的抽牌副本。其他 RNG 探针、未支持牌、深度 12 或 3000 次试探上限都能产生未解决叶。[热图与差分](../experiments/m1-core1/TurnGraph.cs)
* **保守等价**限定在同一规则根和剩余深度。N2A 哈希只定位桶，桶键还含有序已知顶底、未知成员和洗牌代数。命中后比较完整未规范化 packed bytes 和 Cold sidecar 的结构相等性；每条入边和见证继续保留。没有基于血量、伤害、牌名集合或学习值剪枝。纯 Strike / Defend 换序的两个 A 保有不同弃牌顺序；结算洗牌后，两条路径以相同概率进入同一组 B 节点。菜单夹具从无合并的 344 节点减为 304。两图展开后逐边核对状态、选择、事件、概率及边界。
* **正常构筑**复用 N4 的条件世界启动器、SV4A 常驻进程、N4B 公开机制投影、G2 编码与续策。玩家实际观察仅用于条件化。生成器按公开牌组和开局手牌建立独立世界，独立生成引擎种子，从开局复放到当前完整公开历史，逐步核对动作前观察和最后的菜单。第二轮开始可利用已观察的手牌变化提示提议；均匀提议与提示提议各占一半，以先验密度除混合提议密度加权。提示错误仍保留全支撑；对无法构造的提示退回均匀。估计对应 N4 的受控开局先验；特殊开局排序及一般自然战斗任意中盘的后验尚未证明相同。[采样与复放](../experiments/m1-core1/sampled.py)
* **候选与执行**先扩展全部根合法动作和 SV1 在 24 次转移内给出的公开前缀，使用 G2 完成至 B/终局。再从已见的回合内菜单生成替代行动前缀，最多追加 12 条，按公开见证散列排序。每条候选都在同一批世界复评；偏离条件前缀时按真实观察执行 G2。每条 rollout 至多 16 个菜单动作。对每个完整公开历史，仅当该动作在到达这里的所有样本世界都有转移时才能选它；动态规划允许在不同新观察后选择不同续招。这个约束防止将各私有世界的最好动作加权拼成一条不可执行策略。同一 donor 上只有逐步核实每个处方和 G2 回退都一致时才重用整条见证。实战使用独立 lane，逐菜单用历史地址查询规则，未命中时调用 G2。

## 数据接口及下游资格

`compile_policy(graph, value, first=None)` 接受公开后继上的价值回调，可固定首动作返回一个候选，或编译条件策略。热图的 `first` 是根边槽，采样图是根菜单动作索引。结果都包含 `rules`、`unseen`、`measure`、`coverage`、`unresolved_probability` 及 `successors[]`。每个后继绑定 kind、联合状态、概率，以及热图节点或采样路径。精确图按节点规则和事件入边重建路径；采样策略用整段公开动作/观察历史作地址，实际执行不接触 donor 身份。B 和真终局可交给价值函数，其他叶的质量另计。[策略编译](../experiments/m1-core1/policy.py) · [执行器](../experiments/m1-core1/run.py)

`exact_conditional` 返回所选策略在受支持事件上的规则概率以及未解决质量。`self_normalized_conditional_samples` 返回自归一化样本质量，保留接受世界数、请求数、有效样本量和根历史；真实未解决概率为 null。样本覆盖 1 只描述已采样世界。对不曾匹配到的真实观察，抽牌前不会预选世界专属动作。原始采样图保留共同世界的分支顺序，CORE-3 可据此配对，并须另取独立复评世界。

CORE-2 可读取卡区、HP、能量、敌人与机制投影、B 时的合法菜单及历史。精确宿主保留已知顶底、未知牌实例和部分费用生命周期；正常宿主的敌种、当前分段意图、计数等沿用已有公开导出。两个宿主的原始字段随记录保留，可用字段存在性区分缺失。跨宿主通用层规范了 HP、敌方 HP 和终局种类；完整敌方后继机器、任意动态费用和公开历史充分性仍待 CORE-2 验收。此处用于选择路线的 B 分数为玩家 HP 减去 0.4 倍敌方总 HP，胜负另分档。它仅用于验证候选选择与实际执行，不能作为 G2 终局分布标签。

## 覆盖、成本及工程瓶颈

主面板最多提议 96 个世界，目标接受 3 个。46 次查询中 41 次得到 3 个，另有一次得到 1 个、一次得到 2 个；三次全部拒绝。两次失败位于 Exoskeletons 和 Phantasmal Gardeners 开局，一次位于 The Insatiable 第二轮。它们都用尽 96 次提议。失败可定位到公开历史匹配，没有证据能进一步把它们全部归因于某种敌方 RNG。

126 个接受的条件世界支撑 1,292 个候选、3,718 条 B 分支和 58 条死亡分支（含候选间共享的世界与复用结果）。已访问的公开历史有 8,950 个合法动作槽，见证实际覆盖 4,297 个。4,591 条产生的公开替代前缀中扩展了 514 条。该分母只覆盖已访问菜单，不能外推到整个回合空间。

主面板端到端 270.1 秒，含宿主启动、条件采样、前缀恢复、推理、独立执行和逐族证据写盘。单次搜索加编译中位 4.26 秒，最大 8.31 秒。3,940 次根恢复中包括 855 次条件提议，复放历史 7,956 步，实际执行候选 12,938 步，另有 1,032 次 SV1 搜索转移。2,946 次搜索内 G2 推理合计 8.00 秒。CPU 热点归因仍需细分，现有时间分解支持优先减少世界重建。

同批根的 G2 和 G2-search 从开局执行到第三回合首菜单或终局，各自花费 5.49 和 7.48 秒，执行 205 和 211 个动作，后者另用 1,924 次 SV1 转移。这两个数字是宿主建根后的执行循环时间；CORE 的 46 次查询纯搜索时间合计 204.9 秒，另计独立执行和导出。两边的停止语义和计时边界在此列明。单根隔离对照的缓存复用把宿主执行步从 350 降到 308，时间从 3.02 秒降到 2.60 秒。整批缓存命中 734 条完整 rollout；24 根无缓存运行的 16,521 步降到 12,938 步，但两次端到端墙钟分别为 262.3 与 270.1 秒，作业并发不同，不能据此声称整批加速。

最后一组的实际规模为前三个开发族，其中一次只接受到 7 个世界。查询延迟中位数 8.55 秒。该组 Python CPU 用时 9.98 秒，预测与执行宿主合计 65.91 CPU 秒；主面板 Python CPU 用时 29.81 秒，子进程 CPU 未计。所有前向都在 CPU 上，无训练呈现、参数更新或 GPU 作业。

归入本次账本的开发、重跑、构建、对照和回归作业合计约 **1,428 秒（23.8 分钟）**，并行作业按各自时长相加。包括初次热核构建因类型名遮蔽导致的启动失败、修复后重跑和一次 lane 二次 reset 的试跑失败；构建以 SDK 项目用时记账，部分早期无退出计时的作业用输出目录时间估算。技术调查、编辑文档、离线打包和部分短测试未逐项计时。HotDraw 既有 15 个夹具和 SV4A 的 3 项回归通过。

**对下游的决定。** CORE-1 足以向 CORE-2 提供带见证的真实结算后继，也能为 CORE-3 提供共同条件世界上的有限候选。稀疏经验分布、公开历史重建成本和未支持的精确机制仍是可量化阻碍。正式晋级需要独立世界的教师复评与固定能力基准；本次未运行确认集、神经网络训练、N4D 或部署替换。

## 复现

在仓库根目录运行，使用新的输出目录。正常宿主依赖历史 `logs/n4b-host-v2`、冻结 G2、游戏与 CoreCLR 9.0.7；会验证模型和预测宿主身份。热核构建另需 HK1A 固定 SHA 的源码压缩包和 Steam 根目录。提交的压缩图可用于离线概率与策略复核。

```powershell
$env:PYTHONUTF8="1"
python experiments/m1-core1/build_exact.py logs/core1-new-build ../hk0-isolated-131d10a/upstream.zip C:/Users/31830/Desktop/STEAM
python experiments/m1-core1/exact_cases.py logs/core1-new-build/build.json logs/core1-new-cases
python experiments/m1-core1/run.py logs/core1-new --roots 24 --turns 2 --worlds 3
python experiments/m1-core1/compare.py logs/core1-new-check logs/core1-new
python experiments/m1-core1/isolation.py logs/core1-new-isolation
python -m unittest discover -s experiments/m1-core1 -p test_turn.py -v
```
