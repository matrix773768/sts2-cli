# M1-F5A 极速 Solver 成本与常驻准入

冻结宿主在两轮跨根探针中均接受 A、拒绝 B，返回 `Synthetic combat requires a fresh process`。独立进程两轮均能执行 A→B→A。因此当前合成战斗宿主无法直接常驻接收第二个根。这个结果约束现有入口，尚未检验新建独立预测宿主或实现热重置后的行为。完整严格验收继续使用冷隔离。

## 基线与样本

基线 `d4d0a6e9f94950ba75b9dae625ac6cab28053d75`，分支 `port/v0.113.1`，开始时工作区干净。Windows build 26200、16 个逻辑处理器、Python 3.10.11。系统 dotnet 缺少 9.x，实测使用仓库本地的 CoreCLR 9.0.7。宿主、CombatSolver 和原生 DLL 哈希与 S2B 计划一致，版本为游戏 v0.113.1／Steam Build 26660232、CombatSolver 0.51.5。未重新构建。

从 S2C 冻结选择中按划分、遭遇及角色分组，各取 ID 字典序前两根。开发 16 根覆盖四种遭遇，验证 8 根覆盖两种独立遭遇。两组角色各半，总体覆盖四种资源档。首轮探针只使用两个来自不同开发遭遇的铁甲战士根。完整名单及来源摘要在 [selection.json](../experiments/m1-f5a/selection.json)。未打开测试根归档或标签。所有数据沿用 F3B C 和 F4 的 512 次总计费、禁止主动药水以及固定预测帧和独立原生逐帧验收。

## 成本

以下取 S2C 已落盘的匹配根作为冷路径参考。每格为每根墙钟秒的 P50 / P90。F4 包含共享的 F3B，固定预测和原生重放是各自包含冷建的阶段墙钟，热搜索含预测步进、状态摘要和菜单。各列存在包含关系，百分位应独立解读。

| 样本／算法 | 热搜索 | 固定帧重建 | 严格原生重放 | 搜索与验收墙钟 |
| --- | ---: | ---: | ---: | ---: |
| 开发 16／F3B | 0.28 / 0.44 | 2.30 / 3.37 | 1.89 / 2.97 | 6.53 / 9.94 |
| 开发 16／F4 | 0.73 / 1.00 | 4.90 / 8.96 | 4.10 / 7.60 | 15.94 / 22.60 |
| 验证 8／F3B | 0.33 / 0.38 | 2.78 / 2.94 | 2.28 / 2.55 | 7.74 / 8.23 |
| 验证 8／F4 | 1.11 / 1.38 | 8.99 / 10.49 | 6.98 / 8.52 | 22.49 / 24.08 |

S2B 对 24 根各两次冷建的 P50 为握手 155 ms、初始化 1,080 ms、快照和身份 79 ms、总计 1,311 ms。该组预建计时独立于标签批次。F5A 两轮串行准入探针记录了 6 次冷搜索的握手、初始化、身份比对、预测准备、首胜搜索、转移数和进程 CPU，以及完整批次墙钟。搜索 RPC 扣除同请求内预测准备及热搜索得到残差，包含日志、序列化、管道与边界开销。现有计时无法进一步分离这些成分。F4 保存热搜索和验收分项，未测全批 CPU 或独立日志成本。

本次六 worker 冷复跑完成 24 根及 48 个标签，471.71 秒，约 0.051 根/秒，采样峰值工作集 714.6 MiB。两算法均为 18/24 L3，18 个成功根的完整语义证据与 S2C 对应根一致，包括完整路线、摘要、胜负、资源、候选拒绝和计费。另有 6 根的首个 F3B RPC 达到原有 12 秒时限，同批保留原始失败和预算上界。随后用两个 worker 仅复跑这六根，65.91 秒，峰值 237.1 MiB。两算法均恢复为 6/6 L3，与历史逐字段一致。重跑与首次结果分别存档，不能用两批合并估算同并发吞吐。历史批次吞吐包含不同根数、并发时序和续跑，二者不能用于估算等价加速。逐根数据与差分在 [results.json](../experiments/m1-f5a/results.json)。

## 常驻准入与边界

冷 A→B→A 每个根使用独立进程，先核对完整原生根身份及 RNG，再以冻结 F3B 搜索，核对搜索前后的原生审计。语义差分只排除明确的性能观测字段。两轮冷 A 的预测结果逐字段一致，转移数分别为 A 19、B 7、A 19。两个常驻进程的首个 A 与对应冷结果一致，B 在原生初始化入口被拒绝，进程随即关闭。常驻序列的末尾 A 未执行。详见 [admission.json](../experiments/m1-f5a/admission.json)。常驻对照没有完整候选链或独立严格证据，因此无求解或端到端加速比。

F3B 的搜索和 F4 的优化都从独立恢复的 live combat 捕获预测根。F4 已在同根内沿已验证路线重建前缀并局部扩展。当前原生初始化依赖活跃的跑局设施，清理后还需要证明 RNG、卡牌实例、事件订阅及缓存独立。P1 的重置从已结算地图边界开始，且曾观察到外显决策一致时仍有 profile 污染。该前提在本实验的活动战斗根不成立。常驻探针保持原有保护，未尝试共享原生 continuation 或跨根预测缓存。

本样本完整生产主要耗在固定帧和独立原生重放，二者都重复进程初始化。单独优化热搜索的端到端收益受其墙钟占比限制，运行时复用潜力需要在等价批次实测。下一步优先把预测输入与 live 初始化之间的依赖做清点，并为独立的预测输入做冷／热差分。严格原生路径优先细分重建和富观察成本，按原生状态边界单独验证。战略生成适合继续提高更困难根的首胜覆盖，胜后局部优化可研究如何减少低价值候选的独立重建次数，比较时需同时报告质量和严格胜率。

## 复现与检查

使用保留 S2B 正式归档、S2C 正式标签和匹配宿主的仓库，从根目录执行。运行目录须新建。

```powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
python -X utf8 experiments/m1-f5a/probe.py logs/m1-f5a/admission-repro
python -X utf8 experiments/m1-s2c/benchmark.py run logs/m1-f5a/fresh-repro --selection experiments/m1-f5a/selection.json --workers 6
python -X utf8 experiments/m1-f5a/report.py logs/m1-s2c/formal-v2 logs/m1-f5a/fresh-repro logs/m1-f5a/repro.json
python -X utf8 -m pytest experiments/m1-f5a/test_profile.py experiments/m1-s2c/test_benchmark.py -q --basetemp logs/m1-f5a/pytest-repro
```

复跑时可复制冻结选择，把 `pilot` 改为首批结果中 F3B 未达 L3 的 ID，使用 `--subset pilot --workers 2` 输出到新目录，再给报告工具传入 `--retry`。

定向测试 8 项通过。生产入口与原生逻辑无变更，未执行全量 pytest 或五角色批量。P90 是小样本描述，尤其验证集仅 8 根。
