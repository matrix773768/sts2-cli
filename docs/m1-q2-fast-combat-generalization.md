# M1-Q2 冻结极速策略的独立困难战斗泛化

2026-11-18。**冻结的 Q1 战术策略只在已知的 A10 Defect Infested Prisms 根上获胜。** 新增五个独立困难根上，战术策略有两个原生战败、三个因选牌停止。当前数据不能证明跨根胜率，也不能把所有未完成战斗当作失败。Decimillipede 另做定向原生修复，越过节段重接崩溃后，战术策略在该既有根实际战败。

## 设计与信息边界

使用 STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7、CombatSolver 0.51.5 固定 DLL（源码 `78e4545e825e58c3d999354b1ffcd54241b1d2cf`）。Q2 从 Q1 源文件复制构建，只插入资源、动作菜单及根戳诊断。手序、战术评分、同分、结束回合和选择拒绝逻辑沿用 Q1。两组均零搜索、零预测转移、零每步 IPC、不主动用药。用新进程跑每个策略和根两次，交错顺序，同根先做 Q1 的 128 次只读预热。根戳和动作轨迹跨重复一致，两个 H1 根与 H1/Q1 的根戳相符。

- **手牌与预览。** 当前手牌、费用、预览伤害/格挡/抽牌、是否能力牌及可用目标进入观察。目标合法性由原生 `CanPlay` 与 `CanPlayTargeting` 检查。预览前后清理，目标使用当前可命中的敌人。策略收到玩家格挡、敌人 HP/格挡与来袭量，玩家 HP、永久资源和根戳只进入诊断。没有读取未来抽牌次序、隐藏 RNG 或模拟远期结果。
- **来袭信息。** 对当前版本的原生托管 IL 检查显示，`NCreature.UpdateIntent` 直接取 `Monster.NextMove.Intents` 并把元素传给 `NIntent.UpdateIntent`。后者保存 intent，`UpdateVisuals` 通过 `GetIntentLabel` 生成攻击数字。常规攻击标签取单击伤害和次数，动态攻击标签可取总伤害。Q1 用同一动作阶段的 `AttackIntent.GetTotalDamage` 合计，并且只在玩家 Play 阶段、前一步推进完成后评分。没有把 `NextMove.Id`、方法、后续 AI 状态或非攻击 intent 的玩法效果交给策略。
- 这支持把本批普通可见攻击意图当作公开信息。无头宿主没有渲染 UI，未覆盖刻意隐藏、特殊 UI 数字或多人可见性。若移植到更多根，应以可见意图标志或实际 UI 观察屏蔽无法确认公开的伤害值。不能将此审计推广为可任意读取 `NextMove`。
- 夹具均为上游既有 A10 生成场景，每根独立种子，包含四种角色以上和三类遭遇。无真实跑局根、人工改成必胜的牌组、普通战或额外求解器调用。Prisms Defect 与 Decimillipede Ironclad 是已知根，其余五根未用于 Q1。完整种子、夹具 SHA、根戳、观察轨迹和资源快照已保存。

## 兼容性与失败定位

- **选牌是最大的覆盖障碍。** `NativeTestCardSelectors.Push` 能捕捉原生合法选牌请求。当前拒绝属于策略的明确边界。H1 Ironclad 精英触发 `BURNING_PACT`，其他根分别触发 `PURITY`、`BEGONE`、`DREDGE`、`HEADBUTT` 或同一消耗选择。接入决策本身可以复用原生 selector，挑哪张牌则需要新增策略合同。任取首项会改变当前冻结策略覆盖及结果，本次保留 unsupported。
- **节段重接有窄修复。** 原生 `DecimillipedeSegment.ReattachMove` 的状态机先等待 `ReattachPower.DoReattach`，再执行 `ResourceLoader.Load<Texture2D>` 和 `ChangePhobiaModeTexture`。独立可选构建只替换最后两个显示调用，对 IL 命中数量做断言，保留原生重接与 await。以 H1 Ironclad 根另跑 A/B 各两次。A 保持原选牌停止与逐动作轨迹，B 两次各越过一次贴图加载，前节段第 4 回合缺席、第 5 回合以 25 HP 回归。策略随后真实死亡，第 5 回合、80 HP、25 次请求、敌人剩 50 HP。该结果单列。修复限于此路径，未验证其他 Godot 机制。
- **Regent 的持续致死条件。** B 第 2 回合选择能提供 50 格挡的孤注一掷，评分看到了当回合防御却没有表示此后未格挡攻击会致死。第 3 回合末仍有 65 HP 和 13 格挡，来袭 27，结束回合后直接归零。该场有 59 HP 无法按普通伤害账本归因，结合牌的公开效果，和致死条件触发相符。H1 原生见证不属于该根，尚未证明避开此牌即可获胜。
- **Defect Boss 的回合目标。** B 从第 2 回合开始多次有合法的狂乱逃离却没有使用，手序在第 2 回合使用一次。狂乱逃离能增加沙坑剩余时间，Q1 评分没有该收益。B 第 5 回合从 65 HP 直接为零，无普通伤害账本解释，A 到第 7 回合才死。与沙坑致死机制相符，实际沙坑计数未录入轨迹。两条路线首回合也均未打出公开可选的持续能力牌 `CONSUMING_SHADOW`，不能据此确定其反事实价值。此根没有原生胜利见证。
- **Ironclad 重接修复组。** 前两回合已损 42 HP，后续包含献祭和未能及时清除的分段敌人。记录支持检查短期防御、受伤换资源及多目标优先级，尚不足以锁定一种战略错误。

观察与原生执行仍远贵于策略打分。表中完整战斗峰值工作集约 162–169 MiB。未测跨战斗进程恢复，也没有用 IPC 采样替代这部分。单进程外限 28 秒，战斗 20 秒或 140 步、单动作 3 秒、256 MiB 托管堆，主批和修复批各有 260 秒总限。长期如果要大规模生成完整跑局，值得验证双执行路径。先用原生路径作为合法性与结算基准，再在有界夹具上做预测执行逐步差分，单独计入快速转移、开房恢复和必要原生抽检的成本。

**优先补原生选牌合同和高速执行验证环境。** 两个已观察到的致死风险可作为公开战略状态表示的下一批定向测试。先完善状态和动作覆盖，再用小规模定向 SL 研究相同根的可救性对照。当前缺少足量兼容且具有胜利见证的独立样本，直接训练长期策略难以区分执行缺失、牌组能力和实际决策错误。

从同时包含 `sts2-cli` 与 `CombatSolver-m1-cs1` 的工作区执行，输出目录使用新路径。

```powershell
& sts2-cli/experiments/m1-q2/build.ps1
python -B sts2-cli/experiments/m1-q2/benchmark.py CombatSolver-m1-q2/repro
& sts2-cli/experiments/m1-q2/build.ps1 -Repair
python -B sts2-cli/experiments/m1-q2/benchmark.py CombatSolver-m1-q2/repro-repair --repair
python -B sts2-cli/experiments/m1-q2/summarize.py CombatSolver-m1-q2/repro CombatSolver-m1-q2/repro-repair
```
