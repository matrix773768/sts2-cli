# M1-PRE1 Ironclad 机制感知基础网络

## 实验协议

起点 `fa0f884a6efe0bd54e995413544f6bbe9a617cf5`。运行使用 PRE0B 的隔离宿主、固定 STS2 v0.113.1 与 CombatSolver 0.51.5-iik.3b，经验及评价标为 `prediction_only`。工作负载只覆盖单人 Ironclad。训练公开观察由 PRE0B 合同导出，根种子及配方私有元数据只用于重建与划分审计。模型输入不包含任务 ID、行为身份、隐藏 RNG、未知抽牌顺序或未来结果。价值头另接实际后续行为身份作为条件。

首批生产冻结三臂。随机卡组分别用 P0 初始化权重与 v4 A2 更新 84，各在 26,000 个提交根后按固定前缀配额排空。33,000 为生产进程的应急上限。A2 历史模型 SHA-256 为 `180b1141d52fe836d5b7770c90c7be193c1c9a8b86bfd7e152274f2e8cd540a6`。结构化臂在原生起始牌组基础上加入力量、抽牌、格挡或自伤包，用 A2 执行，计划 3,600 根。构筑与战斗根均为合成，天然可达性未经验证。结构化构筑的起始牌组近似重复，统一放入训练，随机构筑继续按 PRE0B 的去升级卡组家族切分。P0、A2、结构化、开发根使用不同根及行为种子。历史 PRE0 提供额外的状态和辅助监督，不进入新增轨迹额度。PRE0B 已修复的生成牌、Knowledge Demon 交互和 Kaiser Crab 建根直接继承。

## 工程验证

四个定向回归覆盖绑定、屏蔽、哨兵血量与条件反转。CPU 接线验证从中间检查点恢复后参数逐张量相同。8 个顺序分支见证中，Inflame 在无修饰条件下先于 Strike 使局部预测伤害增加 2 或 3 HP。局部见证 SHA-256 为 `ed849891d853c78b2d96efa5a00f3138e4eea32f0355d90ac6ac103d24d6ae60`。真实预测 rollout 接线已执行一次可解冻范围的策略梯度更新，所选行为 logp 的最大重算差为 2.38e−7。这些工程验证使用临时权重，独立于正式权重和正式指标。开发清单 SHA-256 为 `5accc11215ec76fbcac4e45cceec42de12078422b28baa748c057a6ae72b96e9`。其中前 8 根在接线时用于验证接口可执行，完整 256 根没有参与训练、模型选择或超参数搜索。

## 模型与标签

共享基础模型宽度 96，为去重后的版本化 Card ID 词表分配独立 embedding。实例编码包含升级、费用存在位、公开修饰和区域。N2E 使用有序效果槽，分别记录已描述、部分、未知及表示溢出。模型对未知 Card ID 保留兼容路径。各区先独立聚合，再经两层四头注意力融合玩家、卡组、手牌、弃牌、耗尽区、选择候选、敌人及记忆。公开历史用上一决策、近期和长期平滑摘要，每场独立初始化。动作使用菜单绑定到卡牌实例、目标和选择，另加实际合法动态预览，归一化覆盖完整合法菜单。无额外未来搜索。

| 目标 | 标签与掩码 |
| --- | --- |
| A 条件状态变化 | 同回合、相邻公开战斗观察的资源差，回归条件均值。包括抽弃牌数量、当前可见费用和公开 Power 变化，省略未来卡 ID 标签。选择边界、跨回合和缺后继观测行屏蔽。Waterfall Giant 的巨大 HP 特殊值有单独存在位，并从普通敌方 HP 汇总移出。 |
| B 条件关系 | N2E 经描述且单效果、无修饰的力量与固定目标攻击，在两牌都合法、总费用可付、敌人无块与无 Power 的联合作用范围内比较顺序。两步未斩杀时按局部 HP 损失，单一普通敌人可立即斩杀时按更早终局。正反方向交替。对未知随机机制省略偏好标签。 |
| C 策略条件结局 | 胜负、终局 HP 比、累计战损、未来四个决策内预测死亡、终局金币及药水占用；用真实生成策略身份条件化。 |
| D 行为初始化 | 完整 A2 轨迹的采样动作负对数似然。P0 只贡献 A/B/C。原数据保存采样动作 logp，当前损失未使用完整教师分布。 |

标签缓存按每条轨迹均匀分层抽取最多六个公开决策，加入首个合格关系机会用于保留稀有监督。历史仍按全部实际执行动作更新。缓存独立保存哈希覆盖的数据、源码、N2E 和词表身份；SQLite 保留完整行动序列。每 epoch 顺序流式读取所有选定训练缓存，确定性地打乱分片及分片内批次。独立验证和报告分区只读。

## 训练与对照

主日程 20 epoch。前 10 epoch 学习 A/B/C，后 10 epoch 同时学习 A/B/C/D，保存初始权重、机制阶段权重、正式最终权重及单独共享编码器。AdamW、余弦学习率、梯度裁剪及检查点记录在 `schedule.json` 和训练日志。中断从上一已提交分片游标及优化器、学习率与 RNG 恢复。

等适配预算对照将基础随机模型与已训练编码器分别接入相同的种子 Actor，使用新 AdamW、相同 A2 行、顺序、学习率和 10 epoch 行为初始化。 初次对照沿用主日程学习率，行为分支第 10 epoch 的验证动作 NLL 升至 46,019.08，尽管 Top-1 仍约 52.69%。问题出在评分尺度，开发战斗前暂停移植分支，保留原始日志。稳定版给两条等预算分支共同使用 `adapt-schedule.json`，学习率 5e−5，合法 logits 均方正则 0.01。此修正基于训练和验证上的数值异常，主 20 epoch 权重与开发根清单维持冻结。另观察随机、机制阶段未适配 Actor、联合训练 Actor 和冻结 A2。固定开发根以同一逐根采样种子运行全部策略；额外一组用成组批推理重复联合训练策略。正式根集合在训练前写入 `logs/m1-pre1-dev-freeze/dev.json`。评价时按私有种子和卡组排查与训练经验的重叠。

`evaluate.py --rollout-model` 可加载任意版本匹配的 PRE1 策略并输出完整合法行动。新一轮 on-policy 实验可用 `--freeze --roots-config <单独种子配置>` 冻结新根集合。用 `rl.py` 对真实合法 rollout 执行单次策略梯度更新，有固定编码器、仅解冻交互层、全部解冻三种模式。RL 入口验证 rollout 策略哈希、合法动作绑定及 logp 重算。开发集结果仅用于评价。

## 256 根完整开发评价

各组跑同一份冻结清单、同一根配方与行为随机种子，使用 4 Worker 和公开菜单采样。逐场结果均标记 `prediction_only`，所有组有效终局覆盖 **256/256**，无截断、unsupported 或异常。本阶段按全尝试分母报告预测胜率。

| 策略 | 胜 | 败 | 胜率 | 胜局净战损 HP | 全正常终局累计战损 HP | 按 80 / 160 / 999 初始 HP 的胜场 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 新架构随机 | 176 | 80 | 68.75% | 88.30 | 129.96 | 40/85 / 60/85 / 76/86 |
| 仅机制，无行为适配 | 173 | 83 | 67.58% | 98.83 | 133.41 | 36/85 / 60/85 / 77/86 |
| 仅行为初始化 | 209 | 47 | 81.64% | 64.76 | 85.82 | 54/85 / 73/85 / 82/86 |
| 机制后同预算行为移植 | 203 | 53 | 79.30% | 58.94 | 89.12 | 51/85 / 72/85 / 80/86 |
| 机制 + 联合训练 | 206 | 50 | 80.47% | 61.68 | 83.81 | 52/85 / 72/85 / 82/86 |
| 冻结 v4 A2 | 210 | 46 | 82.03% | 64.29 | 86.29 | 56/85 / 72/85 / 82/86 |
| 联合模型双组批推理 | 206 | 50 | 80.47% | 61.68 | 83.81 | 52/85 / 72/85 / 82/86 |

完整终局的平均金币在 98.07 至 98.38 之间，药水均为零，符合当前无药水分布。各房型、初始 HP、终局回合与资源明细均存于开发摘要。按根配对，联合模型相对随机初始化有 33 场由败转胜和 3 场由胜转败，净增 30 场。相对 A2 有 2 场由败转胜和 6 场由胜转败。稳定版两条行为对照各执行 10 epoch、2,860 次更新、1,461,400 次 A2 决策呈现。仅行为分支胜 209 场，机制移植分支胜 203 场，配对是一场由败转胜、七场由胜转败。本组数据支持联合模型相对随机初始化的提升，未支持同等行为适配下机制预训练带来额外胜率。移植后的辅助头随无辅助训练的共享编码器而漂移，稳定版移植的独立状态变化 MSE 为 .6254，联合模型为 .00204。后续需要辅助能力时优先保留联合模型。

独立报告分区的 78 个关系样本均为力量先行，其中 44 个含 Twin Strike。机制阶段和最终模型分别得到 78/78、44/44，随机模型在这一分区为 0/78。最终报告分区无斩杀优先样本，不能据此判断网络是否会在斩杀条件下反转偏好。

## 复现

从仓库根运行。依赖 PRE0B 已验证的部署 `logs/m1-pre0b-host-final`。随机数据运行使用 `experiments/m1-pre0b/run.py`，结构化数据使用 PRE1 独立扩展。GPU 路径使用仓库内隔离的 PyTorch 2.12.0+cu126 环境。生产和 CPU 评价使用原 PyTorch 2.12.0+cpu。官方安装索引见 [PyTorch 版本说明](https://pytorch.org/get-started/previous-versions/)。如需要 CPU，可指定 `--device cpu --python <Python 可执行文件>`。

```powershell
python -X utf8 experiments/m1-pre1/evaluate.py logs/m1-pre1-dev-freeze --host logs/m1-pre0b-host-final --freeze --count 256
python -X utf8 experiments/m1-pre0b/run.py logs/m1-pre1-data-p0 --config experiments/m1-pre1/p0-roots.json --host logs/m1-pre0b-host-final --fast --workers 12 --batch 12 --batch-delay 0 --recycle 96 --count 33000 --seconds 7200 --disk-mib 8192 --buffered-logs
python -X utf8 experiments/m1-pre0b/run.py logs/m1-pre1-data-teacher --config experiments/m1-pre1/a2-roots.json --host logs/m1-pre0b-host-final --fast --workers 12 --batch 12 --batch-delay 0 --recycle 96 --count 33000 --seconds 7200 --disk-mib 8192 --buffered-logs --checkpoint logs/nosl3c-iii-a2-01/training/training.sqlite --update 84
python -X utf8 experiments/m1-pre1/structured.py logs/m1-pre1-data-structured --host logs/m1-pre0b-host-final --checkpoint logs/nosl3c-iii-a2-01/training/training.sqlite --count 3600
python -X utf8 experiments/m1-pre1/campaign.py logs/m1-pre1-campaign --python logs/m1-pre1-cuda/Scripts/python.exe --device auto --stop-at-prefix 26000
```

三个生产进程可在独立目录同时运行。正式执行器先核验生产库和新增完整轨迹数，再准备特征缓存、执行主日程和两个匹配对照，最后评价全部策略。训练可用同一命令、输入与输出目录恢复；主动暂停由权重目录下 `STOP` 文件触发，继续前移除此标记。
