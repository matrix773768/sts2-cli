# M1-INFRA v1.0

## 高速游戏环境与规模化经验生产

**版本 1.0 | 2026-11-28 | 新阶段工程研究合同**

项目：`matrix773768/sts2-cli`。历史高速引擎 H5 冻结发布 `7b0f21e4420d1ebf61e7103a874e77af3c8313c5`（`research/m1-infra`）；数据生产2A 冻结发布 `80ca8165fee768ba4e2b55bfd367ee00df650616`（`research/m1-infra2a`）。本版承接 M1-INFRA v0.1，不再把自行迁移全部游戏规则作为长期任务。总原则与性能目标见 [PROJECT-VISION v2.0](project-vision-v2.0.md)。

> 首要任务是选择能够长期支持 NOSL 完整跑局、分支搜索和自主学习的游戏环境。在选型阶段验证真实 AI 负载及规模化吞吐潜力，尽量复用外部成熟模拟器；不得仅因短期接入方便就锁定性能上限过低的架构。

## 2. 前置性能合同

### 2.1 绝对目标与现有差距

| 代表性负载 | 设计目标（待实测） | 实际测量要求 |
|---|---|---|
| L0 规则动作 | 单核10万–100万次/秒 | 真实攻防、抽牌、触发、待选及局外动作；同时报告含/不含菜单与导出，非仅空循环 |
| L0 快照 | 热复制/恢复微秒量级 | 完整战斗、长跑局状态，P50/P95、复制字节、内存、冷启动；测实际分叉后演化 |
| L1 搜索 | 批量同根分叉，避免每边完整复放 | 以公开条件搜索、回合结算和多回合续战测每根成本与覆盖；包括采样与状态销毁 |
| L2 自然战斗 | 四 worker 10万有效战斗/小时 | 固定低成本生产策略，真实模型、合法执行、准入和公开经验写出 |
| L3 完整跑局 | 四 worker 1万有效跑局/4小时 | 固定真实局内外策略，全部阶段、结束原因、章节深度和经验写出 |

目标机器为用户当前个人电脑；实际 CPU、内存、线程数、编译方式和竞争负载由任务运行时记录。四 worker 的自然生产目标折合约0.144累计 worker秒/场、跑局目标约5.76累计 worker秒/局（满负载理想预算）。这些是低成本生产策略的设计压力测试，不是高预算搜索教师的统一硬门槛。单核规则速度快也不保证达到端到端目标。

H5 实测两批自然生产1,041场，含全部公开导出约20.57 worker分钟/千场、四 worker活跃wall约5.77分钟/千场，即约1.04万有效场/小时。2A 新自然训练3,164/3,400准入，57.51 worker分钟，另59.65秒公开导出；全任务生产、筛选和导出74.11 worker分钟。它们提供真实基线，但并未测量 L3。10万场/小时约为 H5 活跃墙钟吞吐的9.6倍。不同负载、策略、准入与并发条件不得称作等语义加速。

### 2.2 性能前置的决策规则

1. 先冻结有代表性的 L0–L3 负载、环境版本、模型、搜索预算、平均战斗/动作数和实际记录级别；再测试外部候选。小夹具只排查正确性和热点，不代表整套系统吞吐。
2. 早期即完成贯穿环境、分支、模型和经验写出的纵向原型；至少验证批量策略执行、完整跑局的长状态复制，以及不使用逐动作高频 JSON 的可信实现路径。
3. 将预算分解为规则、复制、公开投影、搜索、推理、通信和写盘。以实测热点及可消除部分计算长期潜力；不能把未经实现的并行倍率直接算作已达标。测单核和1/2/4 worker，必要时更多并发，报告 P50/P95、峰值RSS、CPU、GPU、worker 与实际wall。
4. 若引擎达不到当前设计目标，先区分实现开销、研究策略昂贵和架构瓶颈。没有可信余量、必须全面重写或长期重复规则迁移的候选不宜冻结为主引擎。允许其暂作研究原型或原生参照；需要调整绝对目标时，以实测预算说明后交用户决定。

性能合同避免两个极端：不得等全机制适配后才检验速度；也不得以空负载跑分、短局频繁死亡或降低搜索质量达标。以代表性成功/失败/后期局分层，报告有效局、节点、真实动作、战斗数、通关及章节到达率。定义有效记录为规则正确、真实资源结算、公开信息合规且得到实际终局的记录，不要求获胜；失败与未完成另记。

## 3. 外部引擎选型：INFRA-3A（拟议首任务）

优先调查 `tfriedel/spire-mentor` 的规则模拟部分；保留现有 HotSearch、原生 sts2-cli/CombatSolver 参照，并在需要时调查其他可获得的 Rust/C++/.NET 模拟后端。此处仅列研究候选，不认证其许可证、版本兼容性、准确性或公开性能宣称。任务须核对具体冻结提交、真实源码、依赖、许可证及本地可运行性，不复用第三方 AI 权重/策略数据。

| 选型维度 | 必须取得的证据 |
|---|---|
| 游戏语义与版本 | 支持版本、角色、进阶、战斗、地图、奖励、事件、商店、篝火、先古遗物、药水；真实终局及资源接口；未支持项明确列出。 |
| NOSL 公平信息 | 原生状态与公开投影分离；合法观测、动作与条件世界；同一公开历史不同隐藏实现不能改变正式决策。 |
| 状态与分支 | 全局跑局状态与战斗快照，完整 RNG 和资源恢复、分支隔离、稳定合法动作绑定；公开采样不暴露真实未来。 |
| 性能潜力 | 依次测 L0–L3；同机、同负载/同策略对照，评估可消除热点和内存成本；证明向大规模生产的接口可行。 |
| 可维护性 | 代码组织、语言与依赖、上游活跃度/版本差异、适配成本；优先贡献可复用修复而不是另造全引擎。 |

若支持版本不同，不强行适配 v0.113.1 才开展研究。可在外部原生支持版本上先做独立完整跑局原型，但环境与数据身份必须分开；版本迁移与正式能力比较另行评测。若无法进行真正同版本/同语义比较，明确列出不可比因素，不虚报加速或胜率。

候选输出应包括一个明确的推荐方案、保留方案及淘汰理由：是否选择为长期后端、是否仅用于局外原型、是否采用混合后端，以及所需最少适配。只有有代表性的端到端实测及可信性能路径才能支持长期架构决定，不先承诺重写。RUN-0 可以同步使用现有原生环境准备基线，不能将其速度当成未来正式性能合同。

## 4. 环境与搜索实现要求

```text
环境实例（私有规则状态、RNG、静态资源）
  ├─ 公共投影/合法菜单 ── 研究策略与模型
  ├─ checkpoint / fork / restore ── 隔离搜索副本
  ├─ sample_public_world ── 合法条件采样
  └─ step / settle ── 实际转移、资源、终局
                        │
               批量公开特征与推理
                        │
               版本化数据分片与索引
```

接口名称是概念合同，不限定语言或 RPC 实现。每个环境句柄有明确生命周期、稳定公开决策身份和真实转移；快照恢复不得将原世界的未公开 RNG 给决策器。缓存分为规则冷数据、公开策略/分布缓存和私有模拟缓存，不能混淆。保留完整跑局和战斗分支的独立演化、清理和内存上界。

| 架构要求 | 推荐做法 |
|---|---|
| 紧凑状态 | 共享只读静态规则，热状态复制成本可测；避免频繁序列化整个对象图 |
| 同进程高频搜索 | 优先在引擎侧推进搜索、分支和结算；对需要 Python 学习的部分提供批量接口 |
| 批量推理 | 批量 C/B/局外特征、模型版本化缓存；CPU/GPU/进程内选择由实测决定 |
| 轻量跨语言接口 | FFI、批量二进制或其他可复用机制优先实测；避免每个动作发送完整 JSON 或历史 |
| 统一完整跑局 | 战斗结束资源自然交回局外；选牌/路线/商店分叉不要求重建另一套战斗状态 |
| 渐进替换 | 现有 HotSearch 和原生后端保持可用；接口适配器隔离版本，按真实需求增加机制 |

等语义实现加速与改变策略的近似加速分别验收。精确条件图、合法 Monte Carlo 与混合搜索都可使用；公开条件不明确时显式阻断或使用经证据验证的近似，绝不将真实隐藏未来当作条件采样。遇到不支持规则，优先考虑可靠原生执行或合法回退，不把全局低频适配变成主工程目标。回退若改变实际策略，保留版本与使用比例，不能宣称无损。

## 5. 经验生产、管理和共享

继承 H5/2A 已验证的原子分片、冻结计划、hash、收据、故障续跑、失败保留、完整公开观测和行为身份。扩展整局及其衍生战斗，而不是重建存储系统。

| 记录类型 | 关键字段 |
|---|---|
| 运行身份 | 游戏/引擎/模型/规则/编码/策略/预算/协议 hash，环境版本、运行时、采集来源、任务与分片 ID |
| 跑局根 | 角色、进阶、路线族、种子（仅环境侧）、初始资源、公开地图、split、可复建引用 |
| 局外转移 | 公开状态/合法菜单、实际动作、奖励及费用、战斗前后资源、终局或缺失原因 |
| 战斗与 C | 来源跑局及前缀、原始公开 C/B/R、实际动作、资源、终局、行为/续策、失败前缀 |
| 条件/教师 | 同根同世界 ID、候选条件程序、概率/采样、真实后缀、选案/复评身份、生成和续策 ID |
| 性能 | 实际wall与累计worker、CPU/GPU、内存、有效动作/转移/C/战斗/跑局、准入率及失败 |

整局、路线族和衍生战斗/条件世界必须共享 split；历史种子和构筑分区、失败、未激活备用一起隔离。完整轨迹中的同一终局标签不是多个独立跑局。不同后端及行为策略可共存，终局标签只能在目标续策一致或明确使用离策略方法时合并。原始公开事实优先于固定模型张量；私有快照仅环境端使用，不能进入策略特征或数据筛选依据。长期存储格式可按实际量级优化，不提前建设复杂分布式数据库。

经验生产分层：快速自然战斗、真实跑局、困难根、搜索教师、配对条件世界及独立复评。CORE/RUN 根据实际问题提出目标域、数量、策略和预算，INFRA 不自行无目的追加。积极复用真实前缀与快照、共享候选和批量后缀；选案与独立复评隔离。失败和原世界保留身份，不能为提高有效标签产率而事后删掉不利终局。

## 6. 新阶段任务与停止条件

INFRA-0 至 2 的前期工程、H5生产、2A规模数据已形成可用资产；不能据此标记全部原设计目标完成。以下编号仅为本版拟议后续任务，具体任务由跨线需求决定。

| 阶段 | 交付 | 验收/停止 |
|---|---|---|
| INFRA-3A 环境选型 | 候选冻结清单、本地构建、L0–L3原型与性能报告 | 给出可信主后端选择、性能潜力及阻碍；没有证据不启动整体重写 |
| INFRA-3B 统一环境接口 | 完整跑局/战斗、公开投影、快照及合法策略执行 | RUN-0 可以独立完成真实终局；规则差异有版本化记录 |
| INFRA-3C 高速生产与搜索 | 同进程或批量路径、推理、分片与完整跑局记录 | 代表性低成本策略吞吐达到校准合同或有明确缺口与批准方案；昂贵教师另计 |
| INFRA-4 需求驱动规模 | CORE/RUN 冻结需求的数据集、持续生产与能力成本 | 有可复验有效规模及可靠续跑；不只以峰值或目标总场数验收 |

首次选型可用约120 worker分钟作为实测预算参考，源码调查和开发耗时另记；不机械完成全机制回归。选型后先冻结实际长期架构，再安排正式大规模学习，不为理论上限反复做无代表性微基准。并行工作树严格隔离，CORE-5H 已冻结，后续 CORE 未提交改动不作为事实；避免高负载任务互相干扰性能测量。保持历史 H5/2A 只读发布，未经用户审查不合并或强推。
