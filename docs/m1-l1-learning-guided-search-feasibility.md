# M1-L1 学习引导 CombatSolver 搜索的可行性

2026-11-18。首步固定前缀补搜可以产生同父节点的胜利路线排序信号。两场普通战贡献全部严格排序样本，共 5 对，且共享种子组。当前暂缓训练和接入学习引导。困难夹具的主要问题仍是胜利标签覆盖率。

## 采集与标签

在 Windows x64、STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7 环境下复用 M1-CS2 的 OfflineSearchHarness、冻结 CombatSolver 0.51.5 源码与 DLL（`78e4545e825e58c3d999354b1ffcd54241b1d2cf`）。只在复制的 Harness 中安装诊断探针。每根先用 24 节点观察生成事件与外层保留池，再将每个观测到的唯一首步独立固定为前缀，用 Beam 24、1,000 节点、30 秒软期限、Smart 用药、DOP 1 搜索后续。整根另设 4 分钟协作取消。额外重放首步，比对生成时状态键。求解批次前后比对原生 live 戳，随后 Harness 正常跑一次无前缀 Evaluate。

固定前缀会改变调度与部分后继前缀的可达性。标签表示预算内找到的路线质量，因此仍受现有求解能力影响。只在同一父节点比较前缀一致、首步重放状态键一致、无预测风险和边界、具有结束回合的胜利见证。实验质量按复活消耗、未追回资源、战略 HP 赤字加药水价格、成长、实耗 HP、结束回合及用药量排序，排除末位启发式分数。平局不进入严格排序。死亡、截断、前缀未匹配和药水策略无可执行路线均保留原分类，均不提供劣质标签。完整胜利为模拟见证，本阶段验证首步，未对整条候选路线再做原生逐步差分。

生成候选经过求解器自身的分支上限及等价动作折叠，因此分母为观测到的唯一首步，覆盖率只描述这个集合。复杂战的路径可能在生成前或更深处被淘汰，本实验没有测量这个漏斗。按战斗根和种子组保留边界。普通战的两个根共用 `M1CS1`，跨根拆分仍会共享相同种子和初始卡组。

## 排序与反直觉动作

CombatSolver 的 `Expansion.Candidates` 先做候选评分和准入，留出防御、进攻、资源/过牌、持续布置、控制、击杀与 HP 投资的代表候选，并保留不同有效伤害目标。随后回合层和全局 Beam 会应用独立的排名、路线保护、路由配额与去重。`PathDiagnostics` 可观察生成、父状态、路线特征和保留决定。默认报告的终选路线、搜索计数和预算日志不足以恢复被淘汰分支的结局。探针记录保留池中的 `requiredIndex`、`routingIndex`、`selectedIndex`，缺少池事件时无法推断有无准入保护。

- 在 5 对严格样本上，生成时原始分数的排序为 5/5。实际 Beam 的 raw rank 只有 1 对共享同一保留边界，该对排序一致。跨边界名次不可直接比较。
- 手工基线用 `2 × 玩家 HP − 敌方 HP + 格挡 + 能量`，为 4/5。它在 Seapunk 上偏好先打击，实际先防御的胜路损 3 HP，先打击损 4 HP，原始评分与 Beam 排名均偏好防御。
- 小战先打击与先防御同为第 3 回合零损胜利，即时评分较低的打击能追平最佳，未发现低分分支严格反超。两条路线均跨 1 次洗牌，仍不能推断洗牌顺序相同或结论对隐藏 RNG 稳定。Seapunk 先结束回合也跨 1 次洗牌，却损 14 HP。计数不足以解释路线优劣。需要后续固定公开局面、干预隐藏 RNG，重复补搜同一候选，才可区分战术差异与 RNG 操作的收益。
- 5 对样本只来自同一有监督信号的种子组，其中多数是在比较立即结束回合。有效泛化样本不足，没有拟合线性模型或树模型，也没有比较引导搜索的固定节点、固定墙钟、内存或者推理成本。

## 信息与成本

| 数据 | 信息边界与使用 |
| --- | --- |
| 根的当前手牌、敌方已揭示信息、HP、能量、格挡、已提供的合法动作 | 当前公开观察，可作为未来在线特征来源 |
| 执行首步后的 HP、格挡、能量 | 可以是当前房间合法试探所得信息。本数据来自 Teacher 模拟，尤其结束回合时可能含新抽牌及敌方行动结果。在线使用要有真实合法观察来源与查询成本 |
| 根种子、精确状态键、未揭示牌堆、未来洗牌顺序、终局质量、后续展开数 | Teacher 专用。种子和状态键仅用于分组与验证，其余作为审计或标签 |
| 原始分数、保留排名、投影洗牌价值 | 求解器诊断。含离线投影时可能携带隐藏信息，只用于对照。深层排名也依赖其他候选及已执行的搜索 |

几个已物化数值的线性计算是低成本设计。为得到这些数字而重新 Fork/Replay、提取牌堆顺序或跑未来投影，可能吞掉节省的节点转移成本。候选补搜计时涵盖一次固定前缀 Solve，排除建根、24 节点诊断和额外首步重放，单次数据包含 JIT 与进程内顺序效应，不能当成在线推理开销。进入下一步前，先补有胜利的较难根、独立种子及低分候选的完整重放，统计共享保留边界覆盖。若后续采样支持模型实验，保留语义保护并计量特征提取、打分和排序合计成本，再检查同等质量路线的节点、转移与墙钟收益。

## 复现与验证

从同时包含 `sts2-cli` 和 `CombatSolver-m1-cs1` 的工作区执行。依赖沿用 M1-CS1 的本地源码、冻结 DLL 与夹具，Queen 请求指向其本地生成场景文件。

```powershell
& sts2-cli/experiments/m1-l1/run.ps1 -Results CombatSolver-m1-l1/repro
python -X utf8 sts2-cli/experiments/m1-l1/summarize.py CombatSolver-m1-l1/repro/small CombatSolver-m1-l1/repro/seapunk CombatSolver-m1-l1/repro/pressure-queen
```

探针输出保存在各根的 `candidates.json`，包含位于离线边界内的状态键、动作、排序记录和后续预算结果。版本库只保存派生汇总。验证采用隔离 Harness 编译、三根真实游戏运行时定向实验、首步状态键核对、原生 live 戳不变检查及 diff 检查。正式搜索和游戏流程没有改动，未执行全量 pytest 或五角色跑局。
