# M1-Q6 跨机制与同预算定向搜索

**两个根都通过了父状态严格核对，并有经原生验证的两回合延续。** Boss 在相同 16 次预测转移下，定向组找到两条到达共同终点的路线，普通组没有。提高上限后，两组找到同一条入选路线。Regent 各档两组均选出同一路线。两场均无原生胜利见证，这些结果支持继续做有界机制实验，尚不足以支持训练候选优先级。

## 对照与验收

固定 STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7、CombatSolver 0.51.5 / `78e4545e825e58c3d999354b1ffcd54241b1d2cf` 及 E2/Q5 基线 DLL 哈希。Boss 复用 Q4 C 的前 18 步，Regent 复用 Q4 A 的前 8 步，分别以第 7 和第 4 玩家回合起点为共同终点。两轮独立进程都严格核对了活动态、RNG、合法菜单和公开父状态。Prisms 正向哨兵为可选，本轮没有重新执行。

[预声明方案](../experiments/m1-q6/plan.md)中，A 单独运行冻结 Q1。B 的首步按合法动作 ID、手牌位置和目标排序，C 按公开机制和目标排序。B/C 的后续策略完全相同，均使用 Q1 评分，并在公开沙坑计数为 1 且逃离合法时优先逃离。A 使用原评分，无该保护，因此 B/C 可用于隔离首步排序效应，A 比较的是完整干预。Regent 的 Gambit 条件只核对当下显示格挡是否足够，无法保证下一回合。

B/C 各自最多四个首步、每路线 18 次转移、每组 250 ms 软墙钟限制、共同转移上限 16/32/64。计数单位是实际 Replay 调用。只对胜利或抵达共同终点的存活前缀选路，先按胜利，再看 HP、沙坑期限、敌方剩余 HP、延命能量。死亡、预算中断及中途不支持单列。无药水动作。预测挂起选择未进入本次验证，遇到该边界时停止。原生一致性检查复用 Q5 活动态严格快照和 E2 的狭义死亡窗口映射。使用隐藏 RNG 推进及比较未来结果，整体为离线 Oracle；候选生成用的公开信息不包含这些内部状态。

| 根 | 每组转移上限 | B 实用 / 到达共同点 | C 实用 / 到达共同点 | 终点质量 |
| --- | ---: | ---: | ---: | --- |
| Boss | 16 | 16 / 0 | 16 / 2 | C 两条均为第 7 回合 48 HP，Boss 209 HP；B 一条在第 6 回合被截断 |
| Boss | 32 | 28 / 2 | 32 / 2 | 入选为同一条先逃离路线；C 多用 4 次转移 |
| Boss | 64 | 28 / 2 | 35 / 2 | 入选为同一条先逃离路线；C 多用 7 次转移 |
| Regent | 16 | 16 / 1 | 16 / 1 | 均选结束回合，并以 17 HP 到第 4 回合，敌人总 HP 67 |
| Regent | 32 | 20 / 1 | 20 / 1 | 同上 |
| Regent | 64 | 20 / 1 | 20 / 1 | 同上 |

Boss 在第 5、6 回合各用一次 `FRANTIC_ESCAPE`，共用 2 能量。第 7 回合仍是沙坑 1、3 能量、零格挡，当前显示来袭 34，敌方相对父状态的净 HP 下降为 51。先打击再逃离也达到同一数值终点。冻结 Q1 第 5 回合死于沙坑，死亡前 65 HP，Boss 剩 211。先防御分支虽在第 5 回合找到一次合法逃离，下一回合仍触发沙坑，原生致死调用前 55 HP，Boss 剩 203。先过牌组在 32 上限尚未到达共同点，64 上限补全后预测第 6 回合死亡。首步优先级在低转移预算有效，较高档实际转移数也不完全配平，无法推出定向组普遍更有效。

Regent 父状态为第 2 回合 65 HP、零能量、5 格挡、显示来袭 32，`THE_GAMBIT` 可提供 50 格挡。该牌保护了当前回合，却留下攻击穿透时触发致死的公开能力。第 3 回合最后动作前，冻结路线有 65 HP、13 格挡、显示来袭 27、`THE_GAMBIT_POWER:1`，原生致死调用前仍有 59 HP。先结束回合避开该机制，原生到第 4 回合 17 HP、13 格挡、3 能量，显示来袭 36，仍有虚弱。牌面即时格挡足够的候选未生存，暂不能据此证明永久禁用更好。先打 `JACK_OF_ALL_TRADES` 的完整预测续推仍随后打出 Gambit 并死亡，未单独复验。

## 原生复验与兼容性

每轮 5 条不同字面后缀，累计 10 次独立原生复验。两条入选延续均完成共同时间边界的严格活动态差分。Boss 与 Regent 的冻结对照，以及 Boss 定向组的第一条死亡，均通过 E2 死亡合同，并由原生调用观测确认各自机制。两组 64 档的入选字面后缀完全相同，共用同一原生见证；Regent 定向组的第一条死亡也与冻结对照完全相同。无用药或永久资源变化。没有原生胜利，入选前缀也未被续推至整场终局。

试跑时 Regent 的第 14 步前公开敌方能力列表出现首差，原生还枚举已倒地节段 1 的 `REATTACH_POWER:25`，预测公开视图只枚举当前可命中敌人。正式实验限定两边公开投影都使用当前可命中且存活敌人，统一与 Q1 的公开敌方意图/目标菜单的范围。E1 完整状态、精确摘要及 RNG 的差分仍覆盖全部初始节段，包括倒地和重接。修正后两轮 Gambit 路线的 16/16 步核对通过。该适配限定于这一公开投影，并未改变求解器或游戏规则。

## 状态重合与性能

每个独立 B 或 C 组里，有 0 次重复后继摘要，所有转移结果在组内均不同。Boss 两条跨回合幸存路线的 HP、期限、能量、敌方 HP 相同，但完整状态含 RNG 的摘要不同，不能合并。跨 B/C 的证据如下。

| 根 | 16 上限交集 / 并集 | 32 上限交集 / 并集 | 64 上限交集 / 并集 |
| --- | ---: | ---: | ---: |
| Boss | 4 / 28 | 27 / 33 | 27 / 36 |
| Regent | 12 / 20 | 20 / 20 | 20 / 20 |

在 64 上限的两组合计执行中，Boss 有 27/63 次、Regent 有 20/40 次后继摘要重复。只按完整摘要测量潜在重合，没有在热搜索内按状态合并，因而这项没有已实现的转移节省。实际复用的是严格核对过的共同父快照，64 档每组相较逐候选重建父状态，Boss 少做 54 次历史推进，Regent 少做 16 次。单次热重建父状态中位数为 6.90/4.65 ms，作为对照独立计时并验证摘要。原生证据复用只发生在字面动作和实例序列相同的代表路线，已在复验次数中扣除。

热墙钟中位数，单位 ms，每组每档 10 个样本。计时含投影、候选排序、动态推进、评价和选路，详细差分与摘要记录在独立审计运行中执行。

| 根 | A 实用 8 转移 | B 16 / 32 / 64 上限 | C 16 / 32 / 64 上限 |
| --- | ---: | ---: | ---: |
| Boss | 5.30 | 8.83 / 13.69 / 19.56 | 9.37 / 17.78 / 15.88 |
| Regent | 6.85 | 14.27 / 15.71 / 18.43 | 12.87 / 17.04 / 17.66 |

所有热样本为 3.04–46.36 ms，未触发墙钟截断。Boss 的 B32 和 B64 路径相同，二者计时差异反映小样本波动，不视为算法收益。以 C64 为例，候选生成含初始投影中位数为 Boss 0.08 / Regent 0.19 ms，推进 13.85 / 14.53 ms，后续公开观察 1.70 / 2.45 ms，政策与实例映射 0.14 / 0.13 ms，终点评估 0.13 / 0.30 ms，最终选路约 0.01 ms。C64 线程分配中位数约 1240 / 859 KiB。整个原生或预测进程工作集峰值约 179 MiB。

Boss/Regent 冷根捕获中位数 16.48/29.54 ms，适配器初始化 199.41/153.18 ms，首次空 Replay 100.17/115.06 ms；原生前缀动作推进 207.54/165.93 ms。根恢复、原生及预测核对和全部热档位合计的搜索进程中位数约 7.51/7.50 s。两条入选原生后缀推进中位数为 57.84/51.60 ms；独立进程从冷启动复验的墙钟中位数为 6.92/6.14 s。分项与逐步证据见 [派生数据](../experiments/m1-q6/results.json)。

## 下一步与复现

可继续投入有界的定向搜索，优先验证能否用同样少的分支找到具有更好共同终点或原生胜路的延续。当前观察到的优势主要是低预算下先访问有效路线，扩大预算后会消失；保护规则只解决近期致死，尚缺能区分长期攻防质量的标签。开始系统收集学习优先级数据之前，需要独立战斗根、可比较的更长时间边界及更多原生验证的高质量路线。热步骤的主要计算支出为预测推进，端到端的首要耗时仍是原生冷恢复和核对。

从仓库同级工作区，复用 Q5/CS1 隔离构建输入。单原生进程上限 35 s、托管堆上限 256 MiB、矩阵启动窗口 180 s。

```powershell

python sts2-cli/experiments/m1-q6/replay.py CombatSolver-m1-q6/repro-1
python sts2-cli/experiments/m1-q6/replay.py CombatSolver-m1-q6/repro-2
python sts2-cli/experiments/m1-q6/summarize.py CombatSolver-m1-q6/repro-1 CombatSolver-m1-q6/repro-2 CombatSolver-m1-q6/repro-results.json
```
