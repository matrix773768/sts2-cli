# M1-LS2B 可组合战略生成与失败驱动修复

在 40 个独立合成报告根上，学习提议与冻结基线在 128／256 Replay 上限下各取得 **6／7 胜**。256 档两组共同胜 4 根，各有 3 个独有胜根。学习版在 32 根上执行了至少一条与四个旧策略均有实际动作分歧的路线。其中一根先预测死亡，编辑输出阶段后得到 5 HP 的完整胜路，F4 改进到 8 HP。该结果证明了战略的执行表达力。总发现率持平，学习版的总墙钟中位数更高。 [逐组统计](../experiments/m1-ls2b/evidence/summary.json) · [修复前后完整动作](../experiments/m1-ls2b/evidence/repair-witnesses.json)

## 根、版本和计量口径

起点为 `port/v0.113.1` 的 `41e86d57af71f5ab3e0f493c0716037387b4996c`。开始时工作区干净，本地 HEAD 与远端跟踪引用一致。拉取遇到 DNS 及证书链错误。运行时逐进程核对游戏 v0.113.1 / 26660232、CoreCLR 9.0.7 和 E3F Solver 0.51.5-e3f.1。每个根冷建一次，根内各臂重新捕获同一个原生状态。各次搜索前后比较原生审计，已执行动作由原有预测器推进。F4 按首胜动作、逐帧续体摘要重建，再用剩余预算优化 HP，保留药水。主表以固定重建成功、HP 至少 1、首胜及锁定路线均无 E3 敌方侧终局标记为合格。每档另有基线 2 条、各生成臂 1 条重建成功但带该风险的路线。 [分组清单和二进制摘要](../experiments/m1-ls2b/evidence/report-manifest.audit.json.gz)

策略生成只消费 LS2A 的公开入场投影。执行偏好只读取当前预测步已经展示的可行动菜单、HP、格挡、能量、敌方已揭示意图与目标、经过回合及已出现敌人的 HP。隐藏 RNG 与牌堆顺序由预测器内部保有。一次失败的反馈来自整条已执行预测轨迹，因此再次搜索具备研究侧预测资格。正式在线正常 SL 仍需隔离可合法获得的历史，约束反事实查询与重试权限，并验证原生行动及资源一致性。本次没有新增独立原生 L3 或完整跑局评测。

## 战略如何影响合法动作

`ls2b.spec.v1` 是封闭字段、整数范围有界的 JSON 对象。Python 将公开卡组的 N2E 成长、生成、抽牌与缺失标记，以及原生攻防牌型比例、HP、敌人数和入场压力组合成两套动作权重、切换门槛、HP 保留比例和目标偏好。对缺失机制保留 `UnsupportedEffect` 和静态身份，无法用现有伤害、格挡、抽牌或能力预览估值的动作有独立的尝试偏好。生成及修复无专用卡名配对。同一规格的规范化内容摘要为其身份，来源及父编辑另外记录。 [策略规格](../experiments/m1-ls2b/strategy.schema.json) · [生成与可验证编辑](../experiments/m1-ls2b/spec.py)

| 组成 | v1 的执行语义 |
| --- | --- |
| 目标与资源 | 存活击败所有敌人，保留药水。合法菜单沿用 F3B 的无主动用药口径 |
| 开局与输出 | 两套权重分别估值有效伤害、有效格挡、能力、抽牌和未估值动作。每步按经过回合或敌方剩余 HP 比例选择权重。召唤或治疗后可重新跨过 HP 门槛 |
| 生存约束 | 来袭扣除当前格挡后仍有缺口，而且预期剩余 HP 触及保留比例时，额外提高格挡及消除攻击者的得分。这是行动偏好，无法保证保住指定 HP |
| 选敌与动作 | 优先低有效 HP、高来袭或高有效 HP 目标。对击杀、能量成本加减分。稳定菜单顺序打破同分，所有牌得分均不高于结束回合时结束回合 |
| 编辑 | 提高风险储备与格挡权重、提前输出并提高伤害权重、改变目标。每个初始规格最多执行一层编辑。父规格与反馈保持可追溯 |

冻结 F3B C 从 Q1、AGGRO、DEFENSIVE、ENGINE 的 FIFO 队列启动，在预测死亡后可从原策略路径的具体节点派生动作替换、短窗口及战略切换。它复用同一搜索实例中的具体前缀节点。LS2B 在隔离宿主中增设 `strategy_spec` 命令分支，直接使用原 `Menu`、`Advance`、48 动作限制及预测终局判定；相同 Replay 总上限的一半供首胜搜索，实际剩余供 F4。无修复臂只试不同初始规格，修复臂可把一次编辑插入下一次执行位置，学习臂同时排序初始规格和可行编辑。冻结基线也保留其原生失败修复。 [原路线搜索](../experiments/m1-f3b/RouteSearch.cs) · [执行适配器](../experiments/m1-ls2b/Strategy.cs) · [同预算调度](../experiments/m1-ls2b/execute.py)

每个原始响应区分死亡、动作上限、Replay 上限、墙钟／内存限制、预测不支持和重建失败。终局敌方 HP 仍高、可见来袭可能致死、末步能量耗尽只形成输出或资源压力假设。修复允许与第一条启发式建议不同，排序模型可以选择先提高输出。同根的新规格从根重放，已付费的重复前缀照实统计。规格规范化消去永不执行的开局字段；发现相同规格时去重。整根结果缓存按版本、目录、完整建根输入、分组、预算、模型、执行次序绑定。跨规格的续体缓存尚待实现，需要同一精确根、同一动作前缀、同版本、可分叉状态和完整续体核对。

## 划分、预算与学习

LS2A 按原生角色卡池、幕和房型生成新配方。两个正式分区从同一预登记候选池按遭遇留出、每角色等额取样，检查卡组配方、家族、种子、配对块、局史和精确根跨组冲突，并排除 LS1 已公开报告配方。试跑另用命名空间。10 个试跑、50 个开放开发、40 个独立报告根各有不同配方。本次三组均为合成，标记自然可达性未知。报告覆盖五角色各 8 根、22 个遭遇、235 个卡牌 ID，三幕分别 12／18／10 根，入场 HP 23–69，16 根携带药水。报告 40 根均有部分 N2E 缺失。真实跑局、多轮用药和更复杂的阶段约束仍待独立评测。

修正试跑中的旧基线空动作字段读取后，10 根、3 worker、60 个单元耗时 14.8 s，3,764 Replay。每组生成平均 0.84 ms，单规格预测调用平均 47.28 ms，11 次修复后的调用平均 32.12 ms，均不含后续 F4。然后冻结 4 worker、每阶段 480 s、每根 75 s、总引擎工作集 1,400 MiB、目录 600 MiB、每根只预约一次。开发组最多 38,400 Replay，实用 12,571、31.8 s。报告组最多 69,120 Replay，实用 30,024、52.4 s，其中 2,055 次用于单独执行四个旧策略的轨迹对照。报告过程根建成时间 P50 1.46 s，单根全部单元 P50 4.60 s。搜索单元在根内预先打乱顺序，包含冷首调用。开发和报告期间同机还运行回归测试，因此墙钟属于此环境下的观测。 [试跑配置](../experiments/m1-ls2b/pilot.json) · [正式预算与口径](../experiments/m1-ls2b/formal.json)

开发组每根独立执行四个提议探针，产生 274 条执行记录，其中 74 次为编辑后重放。去掉不支持、已知终局风险和不可比预算，按根、规格及预算去重后，31 根的 184 条记录进入拟合，39 条为合格胜路。岭回归使用 128 个公开状态与可组合参数的交互项，每根总权重相同，固定正则 0.5；有界终局效用偏好胜利和更高 HP。有限预算截断和提议选择会影响标签的分布，未发现胜路无法证明战斗不可胜。模型在开启报告组前冻结，内容摘要为 `1233d37e66378586a9f5b5c941601cae0f8260086f4d4802a5b070275c7e1e98`。报告组仅作一次独立评价，后续冷复核运行同一参数。 [冻结模型](../experiments/m1-ls2b/evidence/model.json) · [拟合与排序](../experiments/m1-ls2b/learning.py)

## 独立质量与成本

每行分母都是同一批 40 根。首胜 Replay 包含发现与固定重建，首胜 ms 为截至发起 F4 的实际计时加 F4 内部到验证结束的计时，未完整计入 F4 调用传输和建根开销。总墙钟为单元实测，中位数包含公开编码分摊、生成、排序、RPC、审计及质量优化；共享冷建根成本上节单列。首胜和资源中位数仅取合格胜局，各行的胜根组成不同。

| 上限 | 搜索臂 | 胜根 | 首胜 Replay P50 | 首胜 ms P50 | 全组 Replay | 单元总 ms P50 | 锁定 HP P50 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 128 | 冻结 F3B C/F4 | 6 | 44 | 260 | 2,364 | 149 | 25.5 |
| 128 | 生成 | 5 | 38 | 75 | 2,518 | 211 | 31 |
| 128 | 生成与修复 | 5 | 38 | 64 | 2,528 | 210 | 31 |
| 128 | 学习提议与修复 | 6 | 47 | 85 | 2,592 | 208 | 29 |
| 256 | 冻结 F3B C/F4 | 7 | 46 | 157 | 4,523 | 223 | 25 |
| 256 | 生成 | 6 | 44 | 103 | 4,332 | 292 | 35.5 |
| 256 | 生成与修复 | 6 | 44 | 96 | 4,492 | 293 | 35.5 |
| 256 | 学习提议与修复 | 7 | 50 | 115 | 4,620 | 421 | 30 |

所有臂合格胜局的锁定金币和剩余药水数 P50 分别为 99 与 1。128 档学习臂与基线各有 2 个独有胜根，256 档各有 3 个。两档各 4 个共同胜根的首胜动作路线全部不同，因同一首胜重排而提早发现的配对数为 0。共同胜根的锁定 HP 配对差中位数分别为 −0.5 与 +1.5。四个臂各有 1 个根在从 128 提到 256 后才胜。当前样本上的速度和胜率没有形成整体优势。

- **超出旧策略的执行路径。** 每个报告根额外执行四种冻结单轨迹，各 48 Replay，只作动作对照。128／256 档学习臂分别有 126/235、181/302 次执行在与四条控制轨迹的共同长度内均出现动作分歧；各有 32/40 根至少出现一次。只有可比较位置上确实不同的动作才计数，长度较短的共同前缀不作为分歧。根 `f31b74dd32fe667860ec` 的四条控制均预测死亡，冻结 C 两档均耗尽首胜预算；生成臂花 64 Replay 发现并验证胜路，保住 20 HP。
- **参数改变与实际改变。** 报告共执行 386 种不同规格。两档学习臂相对固定修复臂首选规格各改变 38/40 根，首条实际动作序列可确认分歧各 17/40。学习臂的 235／302 次尝试中有 127／173 次实际跨越阶段或进入生存优先级。单元实测推理 P50 为 0.47／0.62 ms。
- **编辑的增量。** 固定修复臂分别执行 29／55 次编辑，有 7／19 次与父路径出现实际动作分歧，两档均没有编辑后新增首胜。学习臂分别执行 28／54 次编辑，11／27 次有实际分歧，256 档有一次编辑成功。根 `a79696e673c3c0af20b4` 上，父规格在 32 Replay 后预测死亡、敌方余 23 HP。学习臂选择提前输出，开局最多 3 回合减为 2，切换阈值 56% 提到 76%，输出伤害权重 7 提到 10。子路线执行和固定验证各 31 Replay；计入前序尝试后，首胜成本为 142 Replay，随后 F4 使用 114 次改善到 8 HP，保留原药水。该根在冻结基线两档、固定修复两档及学习版低档均未获胜。 [父子规格、诊断及逐步动作](../experiments/m1-ls2b/evidence/repair-witnesses.json)
- **重复与失败。** 256 档纯生成无语法重复，固定修复去重 29/563，学习修复去重 42/560。该档学习臂 109 条已胜／死亡轨迹中有 50 条与同单元已执行终局轨迹动作完全相同；2,838 个已完成动作中有 1,588 个与同根同预算下早先路径共享前缀。19/40 根至少有一个新规格触及预测不支持。两档三种新臂合计 1,013 次不支持，其中 516 次目标类型不支持，428 次为待选择边界，69 次报告预测风险且无显式边界名称。失败与截断保留原状，没有根据报告标签调整规格、模型或预算。

## 存储、复现与验证

SQLite 沿用 LS2A WAL 事务、冷进程隔离、预约结算、校验和和恢复机制。本次正式预算将最大尝试次数设为 1。开发、报告 manifest 记录精确输入、版本、配对顺序及成本上限；同名 manifest 变动会拒绝，已完成任务再次运行不增加 Replay。公开分片每根一行，内含公开状态、缺失资格、逐规格预算、标签和父编辑引用。学习读取器分开返回分组、输入和目标，修复视图可显式读取同一预测实验里父尝试的反馈。完整执行 trace、实际路径和精确根保存在隔离的审计分片及 SQLite。Git 留存三个分区的公开 Gzip 分片、冻结 manifest、模型和实例；完整账本位于本机 `logs/ls2b-qualified/search.sqlite`。早期 LS2A 账本仍绑定其既有 producer 摘要，需要用留档版本重开。 [经验合同](../experiments/m1-ls2b/experience.schema.json) · [分析、学习读取器及导出](../experiments/m1-ls2b/report_analysis.py)

从仓库根目录执行，环境依赖同 LS2A，先准备合法游戏 DLL、冻结 Solver 和已资格的 E3F 构建。指定新输出目录可复跑整套，原实验目录可恢复已冻结的阶段。

```powershell
$env:STS2_DOTNET = (Resolve-Path logs/m0-v5/dotnet9/dotnet.exe).Path
$env:STS2_DOTNET_VERSION = '9.0.7'
$env:OPENBLAS_NUM_THREADS = '1'
$env:PYTHONUTF8 = '1'
python -X utf8 experiments/m1-ls2b/build.py
$here = 'experiments/m1-ls2b'
$out = 'logs/ls2b-repro'
python -X utf8 "$here/campaign.py" pilot $out --config "$here/pilot.json"
foreach ($step in 'development','fit','report') {
    python -X utf8 "$here/campaign.py" $step $out --config "$here/formal.json"
    if ($LASTEXITCODE -ne 0) { throw "Failed $step" }
}
python -X utf8 "$here/report_analysis.py" $out logs/ls2b-repro-export
$env:STS2_LS2B_NATIVE = 'logs/ls2b-repro-check'
python -X utf8 -m unittest discover -s $here -v
```

LS2B 定向 5 项通过，包括冷进程 A/B/A、同一真实引擎预测根的冻结宿主与关闭规格宿主差分、非法字段拒绝、修复路径与成本、两分区隔离和从公开分片复算冻结模型。LS2A 定向 7 项通过，含崩溃恢复、精确缓存及串并行一致性。100 条分组导出（含 2,129 条规格执行）通过两份 JSON Schema。里程碑全量 `python -m pytest -q tests` 为 162 通过，1 个既有 S1 出边不足跳过。隔离宿主没有改动全局规则，未重跑五角色各五场完整跑局。

后续值得优先验证的是在精确根内复用重复前缀，扩大多目标及选择边界的可信覆盖，并在新收集的真实局史上复验修复增益。这些数据目前支持学习提议及编辑，无法外推为人类战斗水平或整局通关率。
