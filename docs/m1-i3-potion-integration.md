# M1-I3 CombatSolver 药水动作接入与连续跑局验证

Ironclad A0 的 `run_1` 完成 9 场经原生逐动作验证的普通战，共 158 步。第 5 层的甲虫汁通过差分，该场正常领奖。跑局越过 M1-I2 的第 6 层终点，在第 17 层 Boss 战由回退策略正常战败。另一固定种子 `run_2` 完成 2 场逐动作验证，最终在第 7 层正常战败。两局均收到原生 `game_over(victory=false)`，进程退出码为 0。

## 支持形状与失败处理

M1-I2 的第 5 层（NIBBITS_NORMAL）和第 6 层（OVERGROWTH_CRAWLERS）计划均在第一回合使用槽位 0 的甲虫汁（`BEETLE_JUICE`），目标 Combat ID 分别为 2 和 1，均无选择字段。旧第 6 层计划触及节点上限且没有完整胜路。新路线在前一场就消耗了甲虫汁，所以新第 6 层验证的是改变后的真实跑局状态。

接管仅放行甲虫汁、原生 `AnyEnemy`、显式存活且可命中目标、无主选择或嵌套及回合开始选择的药水动作。按计划槽位读原生 `PotionSlots` 并校验 ID，将该实例和按 Combat ID 解析出的敌人传给原生 `UsePotionAction`。仅在玩家出牌阶段且无待决选择时入队。其他药水或附带选择的计划在预检阶段标为 `unsupported`，仍沿用既有安全回退。

原 Headless `DoUsePotion` 可能在动作失败或药水仍在时手动丢弃。隔离构建复用它的原生动作队列、等待和决策读取逻辑，由严格方法单独调用。严格方法要求原生动作成功完成、未取消、槽位确实清空，并且目标的缩小层数增加。开发中试过以 `PotionUsedEntry` 作附加证据，但该路径上没有取得可用匹配记录，最终用目标的原生效果验证。动作失败或出现待决续体立即停止，首个预测差异保存期望与实际帧并停止。生产入口没有改动。

## 差分证据

`run_1` 第 5 层第 3 步使用甲虫汁。槽位 0 从 `BEETLE_JUICE` 变为空，Combat ID 2 获得 4 层缩小。玩家 HP 保持 81，敌方 HP、手牌和牌堆顺序保持一致。用药当步没有 RNG 消耗，Shuffle 计数保持 8，其他受测流及续用戳与预测一致。下一步成功打出打击，整场 28/28 步一致，并完成卡牌奖励及地图返回。用药前分别注入槽位 -1 和不存在的 Combat ID，均由映射层拒绝且前后完整原生帧一致。

## 对照结果

Windows x64，STS2 v0.113.1 / Build 26660232，CoreCLR 9.0.7，固定 CombatSolver 0.51.5 / `78e4545e825e58c3d999354b1ffcd54241b1d2cf` 基线。沿用 M1-I2 的策略和预算。每场 1,000 节点、6 秒软期限、8 秒取消令牌、DOP 1。整局 480 动作、120 秒、256 MiB 托管堆硬上限及 512 MiB 工作集检测阈值。

| 指标 | M1-I2 run_1 | M1-I3 run_1 |
| --- | ---: | ---: |
| 完整接管胜利 / 匹配步骤 | 3 / 38 | 9 / 158 |
| 药水相关回退 | 2 | 0 |
| 首次无法接管 | 第 5 层，计划含药水 | 第 17 层，Boss 超出接管范围 |
| 原生终局 | 第 6 层战败 | 第 17 层战败 |
| 捕获与求解合计 | 10.87 s | 28.50 s |
| 战斗执行请求合计 | 0.78 s | 2.50 s |
| 整局墙钟 / 峰值工作集 | 14.72 s / 164.4 MiB | 37.25 s / 176.7 MiB |

执行耗时含回退和差分 IPC，排除结算与故意拒绝的探测。两条路线处理的房间数不同，累计耗时不能估算单步性能变化。

`run_2` 的前两场通过 25/25 步差分，随后三场回退。首个未接管计划含需要选择的 `COLORLESS_POTION`，后续计划还涉及其他药水或卡牌选择。该局共 88 个动作请求，约 27.34 s，峰值工作集 186.3 MiB。两局是定向样本，未估算通关胜率。

## 复现与学习实验范围

沿用 [M1-I1](m1-i1-combat-integration.md) 的本地构建依赖。定向验证包括以下命令，原始报告保存在各自输出目录。未执行全量 pytest 与五角色批次，运行时改动限于隔离实验。

```powershell
python experiments/m1-i1/build.py
python -X utf8 experiments/m1-i2/run.py --seed run_1 --verify --verify-potion --out logs/m1-i3/run_1-verified
python -X utf8 experiments/m1-i2/run.py --seed run_2 --verify --out logs/m1-i3/run_2-verified
python -X utf8 experiments/m1-i1/run.py
```

现有接口可以开始范围受控的离线学习型战斗搜索实验，以已通过原生差分的路线为 Teacher 样本，并保留不支持、预算截断和回退标签。其他药水、选择、复杂续体、中途重根、精英和 Boss 仍需覆盖。正式在线 SL 策略还需要只依赖公开状态与当前房间合法试探的观测和搜索控制。当前数据明确标记 `offline-teacher`，使用隐藏 RNG。
