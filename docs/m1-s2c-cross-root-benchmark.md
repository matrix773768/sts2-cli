# M1-S2C 跨根基准与严格失配审计

基线 `81b4c98b92beee2b1ed1894d8d57b597fbefb8fb`。固定 48 根、512 次计费预测转移、禁用主动药水。F3B C 和 F4 均通过 **开发 32/32、验证 16/16**。F4 改善了 13 条开发根和 12 条验证根的原生战后 HP。9 次候选验收仍被严格拒绝，分别涉及两类终局字段差分。

## 冻结协议

用 S2B 版本化索引、正式计划和选中根归档的身份、Spec 摘要及原生 continuation 摘要交叉核验。开发集 4 种遭遇各取 8 根，验证集 2 种遭遇各取 8 根。每个集合内的遭遇与模板组合取一根，先平衡资源档，再以固定哈希排序选根。每个集合各半铁甲战士和静默猎手，开发及验证各有 8 个第二幕根。排除 S2B 已抽评的两个开发根。四根试批固定为每个开发遭遇一根。

S2C 未打开 64 个测试根的原生归档或既有测试标签，只用 S2B 冻结索引核验划分。S2B 曾报告的既有两条测试根不进入本阶段。选择、根 ID、源计划摘要在运行前固定。搜索复用原 S2B 同预算 F3B/F4 路径，F4 从 F3B 的首条严格原生胜路继续。固定帧重建、失败候选和分支续搜均计费。标记 `offline_oracle=true` 和隐藏 RNG 使用，沿用完整原生验证。同根的 L0 为独立恢复，L1 为冻结策略的原生胜负，L2 为完整预测胜路，L3 为该路线经过独立原生差分且确认为胜利。本阶段未运行 L1 策略。

## 成对结果

首次预测、首次严格通过和总计费均以预测转移数计。时间为单根墙钟，包含冷恢复和验收。F4 时间含其共享的 F3B 阶段。表中分布为中位数和四分位区间。

| 集合／算法 | L0／L1／L2／L3 | 首次预测 | 首次严格 | 总计费 | 墙钟秒 | 原生战损 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 开发 F3B | 0／0／0／32 | 11 [9, 16.75] | 22 [18, 38.5] | 22 [18, 38.5] | 6.56 [6.30, 7.28] | 3 [0, 11.25] |
| 开发 F4 | 0／0／0／32 | 11 [9, 16.75] | 22 [18, 38.5] | 257.5 [205.25, 464] | 12.55 [8.88, 20.40] | 0 [0, 10.25] |
| 验证 F3B | 0／0／0／16 | 16.5 [10, 23.5] | 33 [20, 46.75] | 33 [20, 46.75] | 7.97 [7.43, 8.12] | 3.5 [2.25, 19.5] |
| 验证 F4 | 0／0／0／16 | 16.5 [10, 23.5] | 33 [20, 46.75] | 492.5 [240.25, 507.75] | 21.23 [12.91, 22.95] | 1.5 [0, 11.25] |

- 两个集合均为所有配对同时通过，观察到的 L3 差均为 0 个百分点。两算法的根级 Wilson 95% 描述区间分别为开发 **89.3–100%**、验证 **80.6–100%**。F4 共用 F3B 的严格保底，首胜与成功率相同是本协议的结构属性。
- 战后 HP 改善为开发 **13/32**（Wilson 95% 为 25.5–57.7%）、验证 **12/16**（50.5–89.8%）。HP 配对变化的中位数为开发 **+0**、验证 **+3**，范围均为 0 至 +28。平均为 +3.09 和 +6.44，无下降，主动药水消耗均为 0。
- 以上区间按根计算。根共享遭遇和模板，同遭遇内可能相关。开发只覆盖 4 种遭遇，验证只有 2 种，因此区间用于描述这批根，不能据此推断测试集、其他遭遇或真实跑局的成功率，也无法可靠断定验证集收益高于开发集。

## 候选拒绝与复现

F3B 共送审 52 次，4 次拒绝。F4 在共享阶段之后另外送审 64 次，5 次拒绝。9 次中包含一次对同一候选的再次独立核验，按验收次数统计。4 个受影响根都找到严格替代路线，F4 中被拒绝的改进候选未替换保底。

| 首个差分 | 次数 | 原生证据 |
| --- | ---: | --- |
| 猎杀者（`PREDATOR`）致死时的抽牌状态 | 4 | 首次分别发生在第 7、12、15、16 步。预测仍含 `DRAW_CARDS_NEXT_TURN_POWER`，玩家侧原生终局帧没有该效果，continuation 的 `P` 也不一致。开发根 `660d09b29ecc…` 独立重放再次在第 7 步复现 |
| 敌方侧胜利回调的当前回合计数 | 5 | 结束回合后原生切到 Enemy，`Y` 与 `AttackStarts` 归零，预测保留玩家侧计数。验证根 `e4c214f621ff…` 独立重放再次在第 28 步复现 |

每次拒绝的 Spec、最短可定位动作前缀、预测摘要、原始首差分和对应完整标签均保存在审计归档。本批没有固定帧失败、L2 或最终未解根。评测器分开记录搜索覆盖、转移或运行资源耗尽、执行正确性故障、预测兼容性、固定帧工作流失配和原生逐帧失配。固定帧不能完成时，可另跑原生动作前缀以定位可能的首差异，该探针无权授予 L3。本批两类终局问题由完整独立重放直接观测，尚未修改或证明猎杀者差分的内部回调原因。F4 有 30 根耗尽局部候选，18 根达到其转移上限，最终标签仍基于已通过的路线。

## 成本、续跑与回归

四根试批用四个 worker，26.23 秒，合计峰值工作集约 462 MiB。正式批次六个 worker，计划内时限中断及恢复共 **198.78 秒**，峰值约 **691 MiB**。中断前已落盘的 31 个标签恢复后全部保持字节一致，正式批次与试批的 8 个重复单元也逐一匹配状态、路线、资源和转移费用。正式输出目录约 3.05 MiB，另执行两个冷重放复查。本阶段使用已固定哈希的宿主，无需重新构建。

第一次并行试跑的全目录文件检查遇到其他 worker 正在清理临时目录，导致发布中止。修复只让扫描容忍已消失的目录，其他文件访问错误仍会报出。该次结果排除在正式测量外。21 项定向测试通过，包含划分封存、预算、失配字段提取、续跑、重复结论、并行文件扫描及 S2B/F4/F3D-B 回归。未执行全量 pytest 或五角色批次。

## 复现

从仓库根运行。需要本地 S2B 冻结的 `logs/m1-s2b/formal` 归档和与其 `headless_sha256` 相符的宿主。可用 `--bank` 指定归档。版本或身份漂移会拒绝运行。已存在的输出目录用同一根集合、预算和算法重跑即可续接，worker 数可调整。

```powershell
python -X utf8 experiments/m1-s2c/benchmark.py run logs/m1-s2c/pilot-repro --subset pilot --workers 4
python -X utf8 experiments/m1-s2c/benchmark.py report logs/m1-s2c/pilot-repro --subset pilot
python -X utf8 experiments/m1-s2c/benchmark.py run logs/m1-s2c/repro --workers 6
python -X utf8 experiments/m1-s2c/benchmark.py report logs/m1-s2c/repro
python -X utf8 experiments/m1-s2c/benchmark.py audit logs/m1-s2c/repro --workers 6
python -X utf8 experiments/m1-s2c/benchmark.py recheck logs/m1-s2c/repro --route 44f38b01ca978742d6274394a2cc5ff50312805a7cdfc3699bb1faafa56e942e --route c886bea660a8d823961eccb51e45765ad5453fe7a38f43cb259cf1e461761755
$env:STS2_S2C_PILOT = (Resolve-Path logs/m1-s2c/pilot-repro).Path
$env:STS2_S2C_FORMAL = (Resolve-Path logs/m1-s2c/repro).Path
python -X utf8 -m pytest experiments/m1-s2c/test_benchmark.py -q --basetemp logs/m1-s2c/pytest-repro
```

本次实测正式目录为 `logs/m1-s2c/formal-v2`。如需复现续跑，在首次运行追加 `--batch-seconds 55`，再去掉该限制以同目录重跑。可用 `--selection`、`--algorithm` 和 `--budget` 固定独立对照配置。续跑字节断言需要第一段输出的标签哈希清单，普通复现会跳过该项。[冻结根清单](../experiments/m1-s2c/selection.json)与[逐根计费、资源和审计结果](../experiments/m1-s2c/results.json)随提交保留。
