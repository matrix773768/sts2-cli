# M1-B2 独立进程分支基准

在 Windows build 26200、Intel Core i5-13500H（16 个逻辑 CPU）、Python 3.10.11、CoreCLR 9.0.7 上测量。游戏为 v0.113.1 / Steam Build 26660232。游戏 DLL、Headless 构建、协议版本与检查点 SHA-256 见机器可读摘要。

## 复现

按项目状态文档配置游戏 DLL 和 .NET 9，指定一个尚不存在的输出目录。

```powershell
python python/search_benchmark.py --game-build 26660232 --output logs/m1-b2-benchmark --samples 12 --budget 360
```

CLI 使用 M0 夹具种子 `m0-a-save-load-1`，以 Ironclad A0 取得 Neow 后地图检查点。从两条 Monster 出边分别记录串行参考，每条脚本执行 26 步直至战斗奖励。正式测量对 A、B 各重复 6 次，每次都启动新进程。输出目录的 `samples.jsonl` 保留逐任务状态、阶段时间、内存与回收结果，`summary.json` 保留完整脚本、指纹和汇总。

| 1 | 12 / 12 | 37.45 | 0.320 | 1.00× | 3.133 / 3.313 | 118.7 |
| 2 | 12 / 12 | 12.17 | 0.986 | 3.08× | 2.000 / 2.187 | 234.3 |
| 4 | 12 / 12 | 6.20 | 1.935 | 6.04× | 2.047 / 2.125 | 467.9 |

| 阶段 P50（秒/分支） | 并发 1 | 并发 2 | 并发 4 |
| --- | ---: | ---: | ---: |
| 启动与握手 | 0.219 | 0.172 | 0.141 |
| `load_save` 请求 | 2.257 | 1.391 | 1.422 |
| 全部动作请求 | 0.562 | 0.352 | 0.360 |
| 逐步地图请求 | 0.039 | 0.032 | 0.039 |
| 脚本执行总时间 | 0.633 | 0.399 | 0.421 |
| 关闭与回收 | 0.047 | 0.031 | 0.031 |

初始化单次 `start_run` 请求约 2.109 秒，位于正式批次之外。完整摘要另分列指纹、恢复校验、恢复地图、轨迹记录及各段 P95。脚本总时间包含动作、地图和轨迹等子阶段。请求计时包含协议往返，`load_save` 还包含新进程的延迟初始化。细粒度阶段的零值受当前 Windows/Python 计时分辨率限制，应理解为未分辨出耗时。

36 个分支均进入预期的战斗奖励，逐步决策与地图和串行参考完全相同。源检查点字节及 SHA-256 不变。36 个进程全部正常退出。单引擎峰值工作集 P50 约 118 MiB；批次总峰值来自同时活跃引擎工作集的采样之和。采样等待设为 20 ms，实际间隔受系统调度与读取开销影响，可能漏掉短暂尖峰；统计不含 Python 父进程。

`load_save` 请求是这组负载的最大耗时段。并发 4 约 1.93 个有效分支/秒，足以支持小预算的首版局外策略比较。串行批次先运行且单支较慢，缓存和主机状态未控制，观察加速比不能外推成并行效率。每批 12 个样本，P95 使用最近秩且不稳定；同一存档的重复样本只衡量性能。

M1-C 可先在单个地图检查点展开合法出边，用固定战斗策略推进至第一个评价边界。可以先用并发 4 和小预算比较路径，评价函数与更深搜索范围留待共同确定。
