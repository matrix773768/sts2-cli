# M1-INFRA-1H3-R · 独立 HotKernel 公平搜索与整战经验生产

从 `699f8988f88ab8ba0c2148f8284b108f3dd4f6dd` 出发，在 `research/m1-infra` 新增独立生产入口。自然面板共 96 个根、44 种遭遇。严格模式完成 84 战，其中 80 战通过整条决策轨迹的独立原生重放，产出 **379 个抽牌前 C**。修正遥测的 1A 继续承担默认生产。

## 执行路径

同一个 .NET 9 进程依次接收多场战斗。每次原生初始化开局后，真实牌序、随机流、资源、敌方结算和所有实际动作都由 HotKernel 持有和推进。每次回合搜索从公开牌区、牌袋、顶底约束、可见状态和已宣告的历史构造新根。C# 在内存中分叉并累计条件概率，在下一轮初始抽牌前或终局停止。Python 使用冻结 G2 选择动作，在一个候选批次的 C 上调用冻结 V2。策略树、真实战斗和配对后缀均可在生产路径中独立运行。旧模拟器只提供冻结输入和外部对照。原生重放使用独立可执行文件。共享的 Python 子进程传输器增加了可选的命令与子进程环境参数，1A 使用原有默认值。

候选包括 G2 首两名及合法的结束回合。默认候选的后续动作按当下伤害、格挡和目标生命排序，遇到可见待选时选第一项。参考策略在每个新公开观察上调用 G2。自然生产每个回合最多比较一次，每个首动作的分支展开预算为 32 次规则调用；只有两个回合结果均闭合且候选价值严格更高时才采用候选。参考分布不完整时继续执行公开 G2 动作。所有预算、未知概率和被拒绝的候选均有记录。训练、开发和诊断结果分别保存，本轮只做推理。

## A · 规则与公平信息

- 原生对照按真实轨迹重放 96 根。对每个出牌边界比较生命、最大生命、格挡、能量、手牌顺序及升级、敌方生命及格挡；重放待选，终局比较胜负、生命、最大生命及领奖前金币。89 根通过、3 根 Hot 自身未完成、4 根原生进程未返回所需决策。其中 3 根是 Phantasmal Gardeners 敌方回合超时，1 根是 Soul Nexus 中原生宿主打出 Rampage 出错。这 4 根保留为未裁决。该投影的通过数不能代替全部隐藏状态或所有 C 字段的逐字段认证。
- 在另一套试验中，按冻结 CORE-5D V2 的历史动作推进 Hot。96 根中有 89 根匹配旧终局、6 根中断、1 根终局不同。500 个可对齐的抽牌前 C 中，371 个公开记录匹配冻结字段，467 个冻结模型输入张量完全一致。差异涉及敌方字段 97 次、实例状态 18 次、事件 14 次及少量资源等。原生确认过的 OUTRAGE 生成副本随实际结算保留，生命上限从当前战斗读取。其余差异保留到具体根与回合。
- 搜索不复制实际 RNG。待抽未知牌按公开类型、可见实例描述重建并重新编号，已知顶底位置单独处理。受支持的抽牌和敌方加权分支使用规则概率，未解析的概率质量分类留存，分布未闭合时不给出战略期望。条件试验在第一个重采样世界另行扰动牌序和十个 RNG 流，比较公开观察和整个搜索输出，再恢复实验世界。这是所测根上的非干涉证据。尚未核对的寄存器、能力辅助状态或复杂实例历史仍可能引起后继差异。

### 中盘反事实与 CORE-5E 条件世界

每个根选择两个具有不同完整后继分布的合法回合策略。先在原世界配对续战，再按预定种子重排可交换的未知牌尾，两个策略共享同一实际未来 RNG。每侧记录终局效用、干预首次到达的完整公开 C 或终局键、冻结输入张量键以及两种预测支持。严格模式在干预后续战中继续核对所有已闭合的回合预测，失配即停这一侧。整根要求原世界和全部预定世界的两侧均通过。世界样本存在共同根与配对随机性，不能将各侧当作独立自然战斗累加。

终局侧数包含未满足整根准入的已完成侧。严格通过根中，先在同一世界对两个方案的终局效用作差，再对世界、根依次等权平均，训练为 +2.385，开发为 −1.965。根 123 的原世界效用差为 +4，12 个审计世界的配对均差为 +2.25，配对 Monte Carlo 标准误为 2.89。

独立前缀面板采用 Hot 自己的自然动作进入第 2 回合。5E 桥接面板保留旧源开局与公开前缀动作，在 Hot 内实际执行。根选择固定在第 2 回合，选择程序与冻结 5E 有差异。诊断口径仅检验干预首次边界，训练为 102/128 根、408 个整根准入世界对，开发为 37/48 根、296 对，自有前缀为 26/32 根。诊断训练实际发起的 444 对中有 416 对匹配，开发发起的 344 对中有 306 对匹配。严格口径以表中数字为准。

根 123 是 5E 训练索引 123、自然源索引 87 的三只尸蛞蝓。历史公开手牌、敌方生命、玩家资源及抽牌约束通过专项核对。通用候选生成得到两个不同分布，分别包含 9 和 1 个战略输入键。正式估计与另行审计的种子不重叠。严格审计在原世界及 12 个重采样世界完成全部 26 条策略后缀。专项只用于核对身份和结果，搜索与其他根调用相同入口。

## C · 冻结搜索的等语义性能

本轮没有覆盖全负载的同语义速度比。候选集合、遍历预算、G2 输入与数值、实际通过率及部分战斗转移均有变化。相同冻结权重可以核验，实际输给模型的特征仍有上文列出的差异。旧版修正 1A 的同一自然面板完成 96/96 战、52 胜，产出 513 个 C，在 4,852 个策略中闭合 3,225 个。旧版 wall 为 307.35 秒，Python / 宿主 CPU 为 177.22 / 132.91 秒，两进程峰值 RSS 为 356.35 / 293.18 MiB。既有 Ritsu 依赖与旧证据的运行身份也需单独考虑。这些历史记录保留作基准，3–5 倍与 10 倍目标均尚待验证。

## D · 新搜索的能力和成本

## 覆盖缺口与复现

当前目标是单角色合成战斗。带活动遗物、非空药水、宠物、部分特殊区域和复杂实例变化的根会显式停止。公开根仍缺部分能力来源、辅助计数、超容量费用和敌方历史细节；随机目标、部分卡池、敌方生成生命等随机路径会留下未解析质量。主要工程缺口是提高公开后继准确率、复核 33 个不等张量对应的特征，以及在保持规则和有效产出的前提下改进战术候选和 G2 回调成本。配对世界的后缀有 Hot 自身的终局与概率检查，尚缺整套独立原生逐步重放。以上观察限于所列面板。

构建、资源与各入口的命令见[运行说明](../engine/HotSearch/README.md)。[逐阶段账本与身份](../experiments/m1-infra1h3r/evidence/summary.json)记录 DLL、冻结模型与输入身份、失配原因、测量分母和计量字段。[校验清单](../experiments/m1-infra1h3r/evidence/sha256.json)覆盖所有交付证据。运行 `python -B engine/HotSearch/verify.py` 可核对文件哈希、面板分母、概率质量、数据分离、准入集和根 123 的独立抽样。
