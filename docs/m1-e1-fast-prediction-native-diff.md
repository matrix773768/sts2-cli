# M1-E1 无搜索战斗预测执行与原生差分

**结论：固定动作可直接通过 CombatSolver 的内部 Replay 推进，无须搜索。三个根在终局前逐步一致，终局均有可复现的首差，因此完整路线严格通过数是 0/3。** 在已核对前缀上，热预测中位数为 17–39 ms，比同段原生动作推进快约 6–12 倍。Boss 的稳定动作边界可重复分叉。下一步先对齐终局语义，再用小规模定向 SL 接入这一预测路径。

## 环境与方法

- STS2 v0.113.1 / Build 26660232，CoreCLR 9.0.7，CombatSolver 0.51.5，源码基线 `78e4545e825e58c3d999354b1ffcd54241b1d2cf`。构建与驱动校验既有基线 DLL 的 SHA-256，复用 Q3 的原生选择和可选节段显示绕过。Steam 文件及正式求解器保持原样。
- 原生第一玩家回合通过 `CombatRootSnapshot.Capture` 捕获同一根。用真实合法菜单确定手牌实例位置和敌人 ID，映射到 `PlanAction` 的卡牌状态键、同键出现序号与目标。每次反射调用 `CombatBeamSolver.Replay` 仅传入当前指定动作及上一步预测快照。根用空 Replay；有父节点时 Replay 复用现有 Fork 和模拟推进，生成内部评分快照。没有调用 Solve、候选枚举、Beam 或 Coordinator。宿主命令中的搜索配置字段用于兼容参数解析。
- 差分复用 I1 的 `CaptureActual` 与 `CaptureSimulated`，对初始敌方实例和玩家序列化后逐字段严格相等检查。包含 HP、格挡、能量、敌人存活及状态、手牌与各区、费用、升级、动态变量和能力、回合/阶段、精确续体摘要、RNG 种子与计数。胜利使用原生结束回调捕获的现场，死亡使用原生动作返回后的快照。不同点完整输出到本地 `audit.json`，派生数据保留字段级差异。
- B 第 4 步燃烧契约从原生合法选项中选 `THUNDERCLAP+1` 实例，映射为 Hand/Exhaust 单选及实例 token。此处预测请求的 SourceId 为空，来源信息保留在原生记录。两次原生重放与历史路线的逐步前后戳、动作、选牌合同和结局一致。当前适配器范围为固定路线出牌、结束回合和这一单选。没有覆盖药水、奖励、永久资源结算、其他选择合同或挂起中的选择续体。
- 每个矩阵依次执行 A、B、C，每根独立进程，35 s 超时、64 个输入动作上限、256 MiB .NET GC 堆硬上限。堆上限本身不限制原生内存；观测到的整进程峰值工作集为 170.3–174.7 MiB。两次矩阵合计 6 次正式原生验证。

## 首个差异

| 路线与见证 | 一致动作 | 首差 | 原生结局 |
| --- | ---: | --- | --- |
| A，A10 Defect Infested Prisms，Q3 战术获胜路线，与 Q1 同根 | 18/19 | 第 19 步 `STRIKE_DEFECT` 击杀末敌。原生结束回调的技能牌仍带 `TAINTED:6`，预测已清除；差异见 `playerCardStates` 与 `exactContinuationState` | 第 5 回合胜利，64/75 HP |
| B，A10 Ironclad Decimillipede，Q3 手序选牌路线 | 19/20 | 第 20 步结束回合。精确续体中预测为 `Y=0/3/6/6;…;AttackStarts=4`，原生为 `Y=0/0/0/0;…;AttackStarts=0`；三个敌人视角均记录同一玩家字段差异 | 第 4 回合死亡，敌方剩余总 HP 72 |
| C，Defect The Insatiable，Q4 持续保护路线 C | 42/43 | 第 43 步结束回合。精确续体中预测为 `Y=1/0/3/2;…;AttackStarts=1`，原生为 `Y=0/0/0/0;…;AttackStarts=0`。此前 6 次 `FRANTIC_ESCAPE` 均通过逐步核对 | 第 10 回合死亡，敌方剩余 HP 185 |

三根的终局类别、HP 与独立 RNG 字段都对齐。A 可能采样在污染清理前后不同的阶段；B/C 的差异集中在原生死亡后已清零的攻击相关历史字段。当前结果尚无法归因到单一回调或清理点。保留这些差异作为完整等价验收失败，不据此推断活动回合中存在沙坑或选牌的模拟错误。三个根的续体戳与 live 戳、两组首差及预测分叉摘要见 [派生结果](../experiments/m1-e1/results.json)。

热前缀三组均低于 100 ms；最快一次仍距 10 ms 约 1.9 ms。原生 / 热前缀中位数比分别为 6.6×、12.4×、6.1×。同段原生动作推进计时排除了根准备、公开观察和审核；冷进程墙钟包含宿主启动、环境恢复、两种执行和计时循环，不能用于计算纯执行加速比。冷态各段仅两次样本，启动与原生恢复未进一步拆开。逐动作预测耗时在数据的 `audit.steps`，热循环线程分配中位数分别为 706、778、1333 KiB。

C 从第 18 步后的稳定状态分叉：出 `FRANTIC_ESCAPE` → 结束回合 → 再出 `FRANTIC_ESCAPE`。两进程均得到相同的 A/B/A 摘要；父摘要前后一致，两个 A 连同 RNG 状态一致，B 与 A 不同。各子分支都无风险标记或预测边界，单分支耗时约 0.39–0.83 ms，含复制、首次修改和子快照；无法从本测量分离首次写入的独立成本。A 属于原生已核对路径，B 只验证了预测器内部隔离与可重复性。挂起的选择请求及异步续体未作为分叉父状态测试。

## 使用边界与后续工作

这是离线固定路线执行。完整脚本、原生内部状态与 RNG 用于差分；策略在线只能用公开观察和当前房间合法 SL 所得信息。预测时延既未包含发现路线的成本，也不能证明预测器可直接用于在线决策或局外训练结算。当前原生路径继续负责活体合法性、终局验证、未映射选择及任何会影响永久资源的结算。

建议下一项先用 A 的胜利和 B/C 的死亡建立配对终局采样，明确战斗规则结束、动作返回和清理后各字段何时有效。终局严格通过后，再在已经核对的稳定前缀上试行少量预测分支，由原生重放选中的分支。热启动优化可在相同的终局验收通过后测量，目前已有足够的前缀吞吐数据支撑这一顺序。

## 复现与验证

从与 `sts2-cli`、`CombatSolver-m1-cs1` 同级的工作区运行。复用 CS1/Q3 既有本机构建输入。输出目录须为新目录。

```powershell
& sts2-cli/experiments/m1-e1/build.ps1 -Repair
python sts2-cli/experiments/m1-e1/run.py CombatSolver-m1-e1/repro-1
python sts2-cli/experiments/m1-e1/run.py CombatSolver-m1-e1/repro-2
python sts2-cli/experiments/m1-e1/summarize.py CombatSolver-m1-e1/repro-1 CombatSolver-m1-e1/repro-2 CombatSolver-m1-e1/repro-results.json
```

Release 隔离构建 0 警告、0 错误。两轮 A→B→C 和摘要复现断言通过，断言覆盖历史根身份、逐步原生动作及状态、选择、首差和分叉确定性。验证范围为新增的实验宿主及固定路线，跳过全量 pytest 和五角色完整跑局。
