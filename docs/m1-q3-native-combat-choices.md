# M1-Q3 原生战斗选牌与困难战斗覆盖

2026-11-18。**五类原先阻塞的卡牌选择均已由原生流程执行，七根中六根的两组策略都跑到原生终局**，Q2 只有两根。Q2 七个选牌停止单元中，五个本次到达终局，另两个在通过原选择后遇到新的弃牌请求。新增覆盖主要把未知结果变成了可观察的战败。战术组仍只在已有的 Defect Infested Prisms 根上获胜。

## 隔离环境与策略

复用 Q2 七个独立 A10 现有生成夹具，没有新增种子。Windows x64、STS2 v0.113.1 / Build 26660232、CoreCLR 9.0.7，冻结 CombatSolver 0.51.5 DLL（源码 `78e4545e825e58c3d999354b1ffcd54241b1d2cf`）。原 Q2 为历史 A，两组新策略均称 **Q1+Choice**。B 复用手序出牌并在原生候选中取最少合法数量的最前项。C 复用 Q1 战术出牌打分，只在选择回调中增加公开价值排序。排序依据候选类型、费用、升级、基础伤害与格挡，低价值优先消耗或变形，高价值优先回收，纯洁只在有状态或诅咒时考虑选择可选项，同分按原候选次序。未改出牌规则或参照测试结果调权。没有搜索、预测转移、用药策略或逐步 IPC。

每根每组两次，独立进程、交错顺序和 Q1 的 128 次只读预热。单进程 28 秒、战斗 20 秒或 140 步、单动作 3 秒、每批 260 秒、托管堆 256 MiB。主矩阵启用了 Q2 的隔离贴图绕过，只有节段重接进入该补丁。原生 `DoReattach` 及其 await 保持原样。构建开关可去掉该绕过；禁用时仍预计遇到 Q2 已复现的宿主崩溃。

## 原生选择合同

从游戏 DLL 的原生出牌状态机检查接口，并用回调实测数量验证。只在预先登记了当前原生动作、组件没有处理过该动作的其它显式选择时接受回调。候选必须来自相应原生牌区且是不同的真实对象。观察记录来源、作用、动作步、回合、能量、候选序号、卡 ID、升级、当前费用、公开数值及用于核对的实例状态键。选择结果直接返回候选对象；同 ID 卡牌凭候选序号和引用区分。实例状态键用于诊断，未输入评分。策略没有取得牌堆顺序，`HEADBUTT` 的牌堆顶只在动作完成后核对。

| 来源动作 | 原生接口与牌区 | 实测范围和动作恢复检查 | 主矩阵显式请求数 |
| --- | --- | --- | ---: |
| BURNING_PACT | `FromHand`，手牌 | 1–1，所选实例进入消耗堆，原生流程继续抽牌 | 3 |
| PURITY | `FromHand`，手牌 | 0–3，可返回空集，本批两组均选择空集 | 2 |
| BEGONE | `FromHand`，手牌 | 1–1，原生恢复后手牌的 `MINION_STRIKE` 数量增加 | 1 |
| DREDGE | `FromCombatPile`，弃牌堆 | 本批 3–3，原生范围由牌值和手牌空间决定。三个所选实例进入手牌 | 1 |
| HEADBUTT | `FromCombatPile`，弃牌堆 | 1–1，所选实例成为抽牌堆顶 | 3 |

上表按去重的根/策略轨迹计数，每项另有一次完全重复。原生自动处理的单候选等情况可以没有回调，统计只含显式请求。返回 `Task` 后由已有原生 ActionExecutor 等待和消息泵完成动作，随后关闭事务、核对效果再继续发下一步。意外来源、重复回调、超时、局外卡牌奖励以及无法验证的后效均有独立诊断或停止原因。对非空纯洁、更多嵌套或连续选牌分支、重复物件跨事务没有泛化验证。变形后核对新牌数量，未验证旧牌对象生命周期的所有字段。

## Q2 与 Q1+Choice 结果

每格的数值依次为回合 / 实际累计战损 / 动作请求。两次重复结果一致。死亡以玩家原生 HP 归零为准，胜利要求原生结束回调、玩家存活且敌人全灭。失败的选择请求计入动作数，执行中止不计作战败。

| Decimillipede / Ironclad | 选牌停止 / 宿主崩溃 | 死，4 / 80 / 20 | 死，5 / 80 / 25 |
| Infested Prisms / Silent | 选牌停止 / 选牌停止 | 通过纯洁，止于 `SURVIVOR`，3 / 39 / 13 | 通过纯洁，止于 `PREPARED`，2 / 10 / 13 |

共 14 个去重单元，**1 胜、11 死、2 个选择未支持**。所有可比较的根戳与 Q2 匹配，全部记录无药水使用，观测到的永久牌组实例键、金币、最大生命、遗物和药水槽无变化。战斗内原生结算已核对，领奖和存档落盘仍在范围外。Ironclad 精英 C 的宿主问题通过 Q2 贴图绕过解决，C 路线无新增选择，结局与 Q2 修复组一致。

## 正确性与计时

定向再跑 Ironclad Decimillipede 的含燃烧契约路径。在两个独立进程中，根戳、候选实例顺序、选中序号、消费堆效果、20 步请求及终态一致。附加核对了每个非终局动作后的 **19 个原生状态与 RNG 摘要**，逐步一致。摘要来自 `ContinuationStamp.CaptureLive`，其中包含牌区和游戏 RNG 流；摘要在决策和推进计时之外采集，只用于复现核对。这是同一原生执行跨进程对账，未做预测器或游戏 UI 间的差分。

主矩阵的同根两次范围与中位数均保存在数据中。完整终局单元的整场纯决策含出牌与选择约 **0.006–6.67 ms**，公开出牌观察约 **28.7–97.8 ms**，原生推进约 **145–515 ms**，战斗循环约 **174–596 ms**，进程墙钟约 **4.42–7.81 秒**。原生推进的区间包含原生回调中的选择观察和打分，这两小段另列，不能相加当成额外原生时间。出牌评分已预热，首次选择仍可能含 JIT。未测跨战斗热恢复。

## 定向 SL 准备度

执行覆盖的缺口从 Q2 的八个未完成单元缩到两个。现有主矩阵暴露更多策略战败，尤其缺少可靠的多回合目标和持续风险价值。Silent 的下一项兼容工作是原生弃牌合同，当前拒绝发生在指定的两张牌，已明确分离出其它失败。

Regent C 仍在第 2 回合打出孤注一掷，并在第 3 回合以 65 HP、13 格挡面对 27 来袭后归零。Defect Boss C 仍重复遇到可合法打出的狂乱逃离并跳过，第 5 回合死亡，B 活到第 7 回合。两根的动作顺序、公开 HP、格挡、伤害意图与关键候选菜单已保存，未加入沙坑计数实时字段。**具备下一步做定向原生 SL 对照的执行和复现基础**。先验证避开孤注一掷与推迟沙坑是否能救活同根。两根没有已证实的替代胜路，当前不将它们定性为可解。
