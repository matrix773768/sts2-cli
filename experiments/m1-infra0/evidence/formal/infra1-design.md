# INFRA-1 实现研究建议

**首项建议是冻结搜索顺序的参考转移批处理原型。** 自然与多世界生产共用该路径。5D 高预算自然首遍 Aggregate 的整任务 wall 为 444.35 秒，Planner 内累积 417.42 秒，图搜索与条件补全分别为 196.02 和 220.09 秒。在该负载，迁移整套搜索所需工作量大于先测一个等价接口的工作量。实际可取得的加速要由原接口和新接口同面板逐行对照决定。

## 公开参考查询与分支句柄

- 自然 96 根发送 141,103 条参考 RPC，其中 140,496 条带路由，其余含清理。参考 RPC 的 216.02 秒中，155.54 秒为宿主 handle，Python 两端 JSON 调用合计 16.03 秒，宿主 parse/serialize 合计 9.56 秒，剩余 34.88 秒包含管道、调度、探针和其他未覆盖工作。即使消除该命令 handle 之外的全部时间，节省上限也只有 60.47 秒，占整任务 13.6%，对应至多约 1.16 倍。这是这个狭义边界的上限；真正必要的 JSON、传输与调度占比仍未知。
- 客户端为该命令发送 30.1 MB，收到 369.9 MB。请求带 536,719 条累计路由边；现有 48 快照缓存已命中 339,354 条边长，真正进入 197,012 次回放动作或选择，61,787 次逐出。早停会缩短回放。“传输了前缀”与“重算了前缀”需要分别归因。句柄能缩短请求，回包投影和分支结果批量返回所作用的字节量更大。尚无同等语义下扩大缓存后能够消除多少剩余回放的实测比例。
- 从 `complete.Turn.read` 与 `search5.reference` 的已就绪前沿开始。宿主接收已授权的公开动作、抽牌转录与父句柄，按原顺序返回 decision/R/C/终局/未解决、权重、合法菜单和原公开绑定。句柄须验证进程、episode、根和代次；clear、reset、异常与逐出均使相应句柄失效。先以空批/单元素批和原单请求差分，再允许一次提交多个已确定的兄弟节点。提前生成未来节点可能改变 cap、遍历顺序及已完成方案，须在严格对照中排除。

## 中盘根与条件世界快照

三个 5E 负载首遍 Aggregate 共 339.85 秒，分母含三次独立进程启动、父轨迹读取与文件关闭。259 个已尝试方案侧各建一次环境，累计复放 3,040 个实际前缀动作。侧内 restore 为 8.95 秒，全部重排为 0.339 秒，其中同世界第二侧的重排为 0.155 秒。对“消除全部侧内 restore、消除第二侧重排，其余保持不变”的理想化改动，上限为 9.11 秒、2.68%、约 1.028 倍；实际分叉、持有状态、重绑菜单、释放及验证均有成本。固定选案阶段还需恢复候选回合，上述数字不含那部分。三个负载固定成本共 43.44 秒，内含 menu 的 28.34 秒；初始候选已经在同根多个世界间共享。

V2 续战消耗 250.31 秒，占三组总 wall 的 73.7%。训练、开发与 12 世界审计分别为 49.5%、80.6%、80.9%。训练错误/无对根和启动费用会抬高固定占比。四个审计根中，编号 123 单根约 119.8 秒，对审计均值影响很大。这些分层值仅适用于冻结面板。中盘快照有明确功能价值，目前可移除的重复恢复占比不足以把它列为吞吐首项。

若未来负载前缀更长，建议分两层实现：

1. 在稳定公开决策处保存一个完整环境根。已生成的 Solver 源码中 `CombatBeamSolver.Expansion.Replay.cs::TacticalFork` 调用空动作 Replay，父快照分支实际调用 simulator.Fork。它可提供战斗模拟副本。宿主 `InteractiveEpisode.cs` 还拥有动作位置、合法/待选菜单、已选索引、终止/风险状态、pile events、战略 C、稳定 root stamp，以及对原生 episode 的所有权。Solver 的 InteractiveCombat 另有回放起点、待选 checkpoint、pile origin、自动动作和当前计划。首版仅接受已证实稳定的非待选决策；不满足条件的根执行原 restore。PileLaw、资源、实体实例及 RNG 流、Python 公开历史和开局效用参数都需隔离。寿命管理覆盖同一根多次分叉、子分支异常、父根回收和跨 lane 使用。
2. 在根副本上沿原 5E sampler 对未知且可交换的尾牌重排一次，检查实例键、牌数、公开 state 和 law；由这个私有世界分叉 A/B。保留牌组实例和各随机流的独立推进，保留同一个 seed 及原动作计数。验收顺序包括原 A→B、交换执行先后、A→B→A、分支释放后重复恢复，以及待选、随机抽牌/生成、终局与失败。逐步对照动作绑定、选择、C、HP/上限/资源、终局效用与整组准入。私有顺序、seed 和私有状态哈希只停留在环境/验收侧。

## 候选、推理与部署

- 5E 的初采只在选根时运行完整 menu/pair。独立审计确实再次 choose_root 并核对原 public 和方案 law。四个审计根首遍 Aggregate 中 menu 约 9.3 秒，约占该 treatment 的 5.7%；这是把整段审计 menu 全部省去的理想上限。复用需同时保存可执行见证和完整合法条件程序，继续验证原方案 law。静态存储 law 本身不能执行。
- 跨节点策略缓存需包含公开投影、完整公开 PileLaw 及机制/实例绑定、合法菜单、G2 从开局观察与历史动作重建的 encoder.history、开局 HP/上限、动作位置及剩余预算、模型/规则/门控/搜索版本。已有 V2 缓存按输入张量字节复用概率，再依开局效用换算；相同张量不构成相同搜索根。原自然高档的 G2 前向 53.29 秒、19,987 个 batch 1，V2 前向 1.51 秒。可在同优先级已就绪的公开节点批量跑 G2/价值网络，按原顺序分发；逐条核对完整概率、门控和动作。batch 形状可能改变浮点结果。发生不同排序、截断、精度或行为时，另列近似优化。
- 多世界续战若用分支调度，模型只接收各自合法的公开表示。环境调度可管理不透明句柄，策略排序和预算不能根据私有牌序、seed 或哈希切换。固定工作量的 worker 扩展先用实际资源曲线决定；持有更多世界会增加内存及尾部不均，须同时报告每 worker 峰值和完整吞吐。
- 压缩/写盘的独立时间很小。配对 Aggregate 扫描四个父分片共 256 行，read/decode 约 0.15 秒。把扫描次数直接换算为整任务加速会明显高估收益。HotKernel 1.0.2 的单转移吞吐不能替代当前公开投影、选择绑定、信念恢复、RNG 与原生生命周期的同范围对照。已有证据支持先做现行宿主的等语义接口实验，尚不足以给出 HotKernel 整体迁移的收益区间。

## 原型的投资边界与验收

| 改动 | 用本轮记录估算的收益边界 | 实施工作与依赖 |
|---|---|---|
| 现行宿主参考查询分批 | 若原型实测能移除参考 RPC 非 handle 时间的四分之一至一半，5D 高预算自然对应约 1.035–1.073 倍。节省比例是待测假设，13.6% 为该范围内最高可移除的整批时间。 | 中等。先给现行命令加一条保持顺序的批量入口，用原始单命令验收，再从已确定的兄弟节点开始。记录批次大小、首回包及宿主处理以外的实际等待。 |
| 前缀分支句柄 | 高预算自然共 35.88 秒落在已插桩的参考 Play 内；整个 treatment 的 fork/缓存 fork/信念 fork 调用共 20.90 秒，作用域更广。这些调用包含必要模拟，实际可省比例仍未知。 | 中至高。引入代次、释放、超时、缓存逐出处理；先核对正常、待选和异常时得到的完整公开状态。与上一行共用宿主处理边界。 |
| 中盘根及条件世界快照 | 在首遍三个 5E workload 上，即使分叉免费也至多约 1.028 倍；若只净省去测得重复项的一半，约 1.014 倍。 | 高。双层持有环境、克隆实例及随机流，验证 reset 后的分支隔离和释放。先用独立正确性夹具测每次建根、克隆与持有内存。 |
| 相同公开状态的候选或推理复用 | 审计一次候选菜单只占约 5.7%。高预算自然即使将 G2 forward 耗时减半，也只相当于该面板约 1.064 倍；仅优化 V2 forward 的整批上限约 0.34%。 | 单进程推理批次中等，跨根可执行候选复用较高。缓存须有完整公开身份。分别核对权重、浮点概率、排序、合法菜单、截断及实际执行轨迹。 |
| 存储 | 96 个自然根的记录 JSON、gzip write 与 flush 合计约 0.112 秒，占 444.35 秒的约 0.025%。 | 小。面板规模下收益很低。宿主回包的 JSON 归在 RPC，磁盘重写不能消除它。 |
| HotKernel 迁移 | 缺少同等公开转移、恢复和终局投影的端到端证据，无法给出可验证的预期倍率。 | 高。需先证明随机、待选、额外抽牌、部分可观察状态、资源及生命周期一致，再比较同请求范围。 |

这些单项换算均固定其余工作，实际加速以整个 workload 的 Baseline 复测为准。批量接口及持有分支也可能增加开销。验收须同时检查工程成本、有效经验/秒及工作集；多个单项收益不能相乘。

### 12 世界审计的定向函数检查

四个冻结审计根在 cProfile 下完整执行。全 treatment 中 `complete.Turn.search` 共 220 次，累计 103.88 秒；`follow` 41,828 次、99.61 秒，`read` 62,196 次、78.77 秒。后两者的 Python 函数自身时间分别只有 0.51 和 0.48 秒。另一路 `improve.graph_plan` 220 次、60.58 秒，内含 `search5.reference` 的 39.10 秒。最热调用贯穿多个 Python 入口和同步宿主请求，直接把最外层递归函数改写成 C# 时，可省下的时间取决于能否同时减少 RPC 及重复转移。上述累计时间互有嵌套，均含诊断插桩。[按函数的调用数、self 与 cumulative 时间](diagnostic-functions.json)

### 固定工作量部署选择

高预算自然 1、2、4 worker 各两遍，平均 447.58、178.43、122.17 秒。4 worker 比 2 worker 的整批 wall 再短 31.5%，生产 worker 成本由 354.33 升至 397.53 秒。着重交付时间时采用已验证的 4 worker；受 worker 配额约束时采用 2 worker。该比较仅覆盖原 96 场自然战斗，5E 的审计根 123 会构成不同的分片尾部。动态分派需再核对 lane 缓存、面板顺序、异常恢复及逐行策略身份。[完整扩展数据](tables.md)
