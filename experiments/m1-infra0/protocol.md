# INFRA-0B 冻结测量协议

0A 只执行单 worker、单任务语义检查和定向机制夹具。正式启动条件为用户确认 CORE 计算资源已释放。工作目录为独立的 INFRA worktree。全部命令在其仓库根执行。

## 面板和策略

输入固定于 `panel.json`，源文件哈希随表保存。`freeze.py` 仅使用 5D 的开放训练自然轨迹及其配对文件、训练根和既有三章原生重载索引。采样在计时前完成。按历史机制分层，以族哈希稳定抽取并补足自然总数。分层描述历史路径，正式低档仍使用同一批世界。自然面板含长战 28、条件采用 21、多抽约简 22、其余正常 25。四个层互斥，长战优先。无胜负或速度准入门槛。正式汇总给出各层分母，同时报告长战及复杂机制层，汇总率仅代表本面板。

反事实面板共 44 个原训练编号。两侧各自续战 16 个、存在自然终局复用 16 个、实际未匹配或未解决 7 个、无有效对 5 个。分层以历史行动转录和准入字段识别。保持原索引，使 5D 的目标回合与奇偶选择规则不变。每个 worker 按生产代码扫描四份父轨迹，跳过未分配的根。计时包含扫描、重建、失败和复用，另报实际续战、复放及扫描量。生成、待选、头槌、无序抽牌和前缀缓存另有定向夹具。三章合法根按原生重载专栏报告。

| 部署臂 | 图转移、批量结算、参考、扩展预算 | 首动作和补全配额 |
|---|---|---|
| V2 | 512 / 80 / 256 / 20 | 前 4 个，每个首动作 32 / 80 / 80 / 80 |
| V2low | 192 / 40 / 160 / 10 | 2 个不同牌优先，24 / 56 / 56 / 56 |

权重、开局 HP、未知牌序条件、策略门控和 128 实际动作上限取自冻结生产入口。两侧返回完整匹配终局且效用可计算才计有效对。有效自然 C 只取有合格终局的真实轨迹。面板含同源开发过的机制，对后续能力确认无独立性。

## 执行与停止

```powershell
python -B experiments/m1-infra0/infra_assets.py ../sts2-cli
python -B experiments/m1-infra0/build_meter.py ../sts2-cli
# 在已准备好的本机 worktree，从下一行开始。批次标签须为新名称。
python -B experiments/m1-infra0/formal.py infra0b-01
```

前两行用于新 checkout。构建目标目录必须为空缺，避免覆盖实验。Python 3.10、CPU 版 Torch 和本地 .NET SDK 使用本阶段环境清单。正式工作固定 OMP/MKL 与 PyTorch intra-op 为 1，记录实际 inter-op。使用独立标准流，进程启动至每根自然刷新、完整 gzip 可读、宿主退出分别有时戳。每个 worker 持有本地推理缓存。相同总工作量按索引轮转分给 1/2/4 个 worker，分片输出路径各自独占。

协调器优先测高档自然和反事实，其次低档自然。每类执行 Baseline、Aggregate、Aggregate、Baseline。扩展实验用无插桩高档自然同一面板。逐根去除顶层 `seconds` 后做完整记录校验，有差异立即停止。异常和截断仍留在生产分母。0A 定向比较采用 JSON 精确一致（允许误差 0），历史无序质量夹具另用原定绝对误差 1e-8。正式开销按配对同面板平均耗时比报告，超过 5% 时主吞吐采用 Baseline，并根据热点缩小诊断范围。高档运行按实测 worker 时间递减约 7200 秒预算，预估下一档超过保留量即停止；当前任务的预计成本可受竞争影响。出现持续异常、语义差异、隔离失效或外部资源竞争则中止本批次并保留已写文件。无后台调度、无自动重试或训练调用。

## 原始量与分母

`logs/infra0-runs/<标签>/` 下的 task、process、worker、gzip 和 result 分别保存分配、启动/退出、分阶段计量、原始经验和整任务收据。计时从启动 worker 前至最后一份经验文件关闭并成功打开；校验器随后遍历到 EOF，检查 CRC 和全体编号。面板验签、文件分发、事后审计另计。累计 worker wall 与整任务 wall 单列。首根包含进程、导入、模型和开局预热。相邻完整根刷新之间的区间用于常驻观察。短面板只出现一个根时，稳态指标为空。

阶段计时使用 Python perf_counter_ns 和 .NET Stopwatch；host ticks 依本进程频率换算。Python self_ns 扣除同步栈内已包裹的子调用，未解释时间保留在上层或 worker 未覆盖项中。宿主 handle、内层 step、C 导出以及旧探针的毫秒值与外层 RPC 嵌套；不同表禁止相加。请求等待剩余量减去两端 JSON、宿主 handle 后仍含排队、缓冲、锁、写回、探针和系统调度。保留有符号 residual。逻辑候选、尝试/完整策略、截断质量来自 queries；实际 step、fork、缓存查找深度及执行工作来自宿主账本。返回对象按 UTF-8 行长的 log2 桶统计。host 和 Python 的进程 CPU、峰值工作集、GC 以及 Windows 进程 I/O 分开记录。Windows I/O 含管道和缓存，输出流 write 另有字节与耗时，物理介质落盘延迟不可由这些值推出。

诊断用单根 cProfile，包含生成器和递归调用，分析 Turn.read/outcomes/follow、graph_plan.back、模型编码/打包等。其总耗时带有剖析成本。0B 在有真实数据后选高成本层的定向根，比较同一世界/预算。每个 worker 的样本量、失败率、首根和稳态、尾延迟、内部线程与并发、负载不均和异常回收单列。正式分层分析须从每根编号关联面板；累计吞吐为有效工作总量除整批 wall。对热点建议用可消除工作占比计算上限，避免把嵌套层或串并行倍率相乘。
